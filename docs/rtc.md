# RTC / CMOS (DS12887) в ядре Sprinter: материал к обсуждению

Статус: исследование от 2026-11-21. RTL и прошивку не трогали. Идея пользователя: набор регистров DS12887 держать на RP2040, а не в RTL.

Главный вывод: **набор регистров MC146818A на RP2040 уже есть** (`karabas-go-firmware/lib/rtc/rtc.c`, `rtc_mode 0`). Ядру нужна только зеркальная RAM `kg_l2_rtc` и тонкая логика порта. Но у Sprinter есть три особенности, которые нынешняя схема не покрывает (раздел 3).

## 1. Как Sprinter обращается к DS12887

### Порты

Источники: `Shared_Includes/constants/SP2000.inc` (подмодуль tt-sprinter-bios, пустой в `upstream/`, взят с zxgit.org/Tolik-Trek/Shared_Includes) и https://doc.sprinter.ru/blocks/cmos.

| Порт | Код DCP | `DCP.MIF` | Действие |
|---|---|---|---|
| `#DFBD` | `1D` | `70D4` `CMOS_ADR_WR` | `OUT`: номер регистра |
| `#BFBD` | `1E` | `71D4` `CMOS_DAT_WR` | `OUT`: запись данных |
| `#FFBD` | `1C` | `71D8` `CMOS_DAT_RD` | `IN`: чтение данных |

- Чтения адреса нет.
- BIOS не даёт номер регистра ≥ `#80` (`_mCMOS_MAX_TEST`, `CMOS.MAX_ADDRESS = #7F`). У DS12887 128 байт: A7 игнорируется.
- doc.sprinter.ru пишет: «Записывать какие либо данные в CMOS без ведома BIOS-а не рекомендуется. Исключение – установка регистров времени/будильника».
- Страница https://doc.sprinter.ru/blocks/cmos/registers содержит только ссылку на PDF Dallas 12887A.
- Страница функций BIOS (`.../funktsii-upravleniya-zhelezom-i-opredelenie-versii`) отдаётся пустой. Описание функций `#F5`/`#F6`/`#F7` взято из `Shared_Includes/Docs/BIOS functions.asm`.

### Цикл шины

Все три кода имеют `TYPE = 7` (системные порты).

1. В фазах 5-6 DCP выставляет управляющее слово на `MA`: `HDD_C = MA[8..5]`, `FDD_C = MA[4..2]`. MAX защёлкивает стробы на `10K_CLK` (`SP2_MAX.TDF:430-432`, наш `sp_max.v:144-146,176-178`):
   - `CMOS_AS` (активный 1) = `HDD_C 0110 & FDD_C x01`;
   - `CMOS_DWR` (активный 0) = `HDD_C 1110 & FDD_C x01`;
   - `CMOS_DRD` (активный 0) = `HDD_C 1110 & FDD_C x10`.
   Это Intel-режим DS12887: AS, /WR, /RD, мультиплексированная шина `MD[15..8]`.
2. Ожидание: `W_TAB` для `TYPE 7` равен 10 тактам `CLK21` и в турбо, и без (`sp_dcp.v:229-237`, `docs/ahdl.md` п. 3.4). Получается ≈ 476 нс `/WAIT` плюс сам цикл, всего ≈ 0,6-0,7 мкс на `IN`/`OUT`.
3. Стробы `/IOMY` и `/IOMZ` снимаются при `WT_CT ≤ 1` (`sp_dcp.v:381-385`), то есть до конца ожидания.
4. Чтение: ЦПУ получает `PDD = MD[15..8]` (тип 7, `sp_acex.v:320-327`). В нашем `sp_machine` это `PER_D` / `PER_OE` (сейчас `16'hFFFF` / `0`), плюс удержание `md_keep`.
5. `/WAIT` собирается как «И» открытых стоков (`WAIT_N_OE`). Дополнительный источник ожидания технически добавляется: ЦПУ будет стоять, пока линия в 0.

IRQ и SQW DS12887 нигде не используются:
- в MAME `ds12885` без `irq()` (`sprinter.cpp:1966`);
- у ACEX нет входа от CMOS;
- doc.sprinter.ru про прерывания (`/blocks/z84c15/isa-interrupts`) называет только IRQ1/IRQ2 ISA;
- BIOS и `CMOS.EXE` пишут в B `#02`: PIE, AIE, UIE и SQWE выключены.

## 2. Что использует ПО

### Функции BIOS

Функции BIOS `#F5 CMOS_TEST`, `#F6 CMOS_RD` (D = регистр → A), `#F7 CMOS_WR` (D, A).

**Каждый вызов `#F6`/`#F7` сначала выполняет `CMOS_TEST`.**
- 3.04 (дизассемблер, ROM `0x232ca`): прочитать ячейку `#3F`, записать её дополнение, прочитать, сравнить, записать исходное. `#3F` — это ячейка контрольной суммы.
- 3.06 (`bios/exp/FUNC_CMOS.ASM`): то же на ячейке `#7F` (`CMOS.TEST_CELL`).

Отсюда два следствия:
- на одну полезную операцию приходятся 2 записи в тестовую ячейку и 2-3 чтения, причём чтение идёт сразу после записи, через микросекунды;
- **«CMOS: None»** выводится, когда тест не прошёл (прочитанное ≠ записанному). Сейчас шина читает `FF`, поэтому и None. Тогда BIOS эмулирует CMOS в ОЗУ (`SYS_PAGE` `#FF00+reg`), и настройки не переживают выключение.

### Раскладка CMOS

Источники: `SP2000.inc` `CMOS_CELL`, `sprinter-bios/SETUP/DSETUP.ASM:28-80`, `SETUP.ASM:811-864`.

| Адрес | Содержимое |
|---|---|
| `00-09` | время / будильник: сек, сек-буд, мин, мин-буд, час, час-буд, день недели, число, месяц, год. **BCD, 24 ч** (B = `#02`) |
| `0A` | `#26` (32 кГц, 1024 Гц); `0B` `#02`; `0C` RO; `0D` RO (`#80`) — по `CMOS.EXE` |
| `0E` | BootUpParams: тест памяти, сохранять RAM-диски, обновлять BIOS, задержка, язык, звук, быстрый старт |
| `0F` | автоповтор клавиатуры |
| `10` | системный / альтернативный диск |
| `11` | FDD1/FDD2 720/1.44/нет, IDE master/slave Auto/Setup/Off |
| `12-19` | геометрия IDE primary master / slave |
| `1A` | ScreenSET (цвет, синхро 312/320, INT) |
| `1B` | конфигурация |
| `1C` | режим сброса / ZX |
| `1D` | опции (сообщение перезагрузки, ZX ROM) |
| `1E` | монтирование TR-DOS A-D |
| `1F` | позиция экрана X/Y |
| `20` | IDE secondary |
| `32` | **век, BCD** (`#19` / `#20`) |
| `3B-3E` | геометрия IDE secondary (3.06) |
| `3F` | **контрольная сумма** |
| `40-7E` | свободно (старые программы туда пишут) |
| `7F` | тестовая ячейка 3.06 |

Контрольная сумма (`CHEKSUM`) берётся по байтам `#0E` и дальше, в количестве `DEFVAL.Size`/`USEVAL`: `H = #DE`, затем для каждого байта L: `H = rlc(H − L) − L`. Результат лежит в `#3F`. При несовпадении выводится «CMOS CHECKSUM ERROR, INSTALL DEFAULT VALUES» и пишутся значения по умолчанию.

### Время

- BIOS 3.06 `GETTIME` (`SETUP/MAIN.asm:100-185`) читает часы, минуты, секунды, число, месяц, век `#32`, год как BCD с проверкой диапазонов. Век должен быть в `[#1A, #9A)`. При ошибке вызывается `CMSERR`.
- **BIOS 3.06 `CMOSINIT` на каждом старте** (`MAIN.asm:212-243`, вызов из `:749` после удачного `CMOS_TEST`):
  - если `A ≠ #26` или `C ≠ #50`, то выполняется `CMSERR`;
  - `CMSERR`: B = `#82` (SET), A = `#26`, C = `0`, **дата по умолчанию** (00:00:00 и дата сборки BIOS), B = `#02`.
  - На настоящем чипе `C = #50` (PF и UF) — нормальное состояние, если C не читали больше секунды.
  - В 3.04 SETUP упакован (`DEPACK`), его логику не проверяли. В распакованной части BIOS 3.04 похожей проверки нет. Для 3.04 это **не доказано**.
- DSS (`sprinter-dos/DOS5.ASM:1165-1340`, `SYSTIME` / `SETTIME`):
  - через `#F5` проверяет наличие часов, потом читает регистры 7, 8, 4, 2, 0, 6, 9 и `#32` как BCD;
  - день недели берёт как есть;
  - если век не сходится с годом (≥ 80 → `#19`, иначе `#20`), переписывает `#32`;
  - `SETTIME` пишет те же регистры и `#32`.
- UIP никто не ждёт: ни BIOS, ни DSS, ни `CMOS.EXE` не читают бит 7 регистра A.
- `sprinter-apps/.../timerv2` (замер частоты ЦПУ) в цикле `DI` читает **секунды напрямую** (`OUT (#DFBD),0` / `IN (#FFBD)`) и считает такты между сменами секунды. Ему нужен точный фронт секунды.

## 3. Что уже есть в общей инфраструктуре

### Прошивка

`lib/rtc/rtc.c` (только чтение):
- DS3231 на плате;
- `rtc_mode 0` = MC146818A: BCD/двоичный по DM регистра B, всегда 24 ч;
- старт (`rtc_send_all`):
  - 00-09 — время и будильник;
  - A — из EEPROM, при `FF` → `#26`, UIP всегда 0;
  - B — из EEPROM, при `FF` → `#02`, SET снят;
  - **C = `#00`**, D = `#80`;
  - остальное из EEPROM банка ядра;
- каждые 500 мс время приходит пакетом `RTC SET`;
- запись ЦПУ (`RTC GET`): 00-09 → поля и `adjust()`, то есть **DS3231 переставляется**; A, B и остальные байты → EEPROM.

EEPROM задаётся в `core.json` полем `eeprom_bank`:
- 0..3 — 24C08 на плате;
- 4..254 — файл `/config/<id>.eep` (kgo2), запись на SD не чаще раза в 30 с (`core_loader.c:215-290`), начальное содержимое из секции `EEPROM_INIT`;
- 255 — нет EEPROM.

**У sprinter сейчас `eeprom_bank 255`, `rtc_mode 0`**: все ячейки придут `FF`, записи пропадут.

### Модули

`kg_l2_rtc.v` (цель 06 link v2, `ENABLE_RTC` в `kg_mcu2`; у нас сейчас `ENABLE_RTC(0)`):
- RAM 256×8: ядро читает за 1 такт и пишет сразу, MCU пишет пакетами `SET`;
- записи ядра (кроме C и, при `SKIP_0D`, D) уходят в **fifo на 8**, IRQ бит 6;
- «девятая запись до чтения теряется» молча.

MCU обслуживает это из главного цикла по выводу INT (`docs/link_v2.md` §3). Задержка не задокументирована; по оценке от сотен мкс до единиц мс (SD, USB, OSD) плюс десятки мкс SPI.

### Другие ядра

Все работают через зеркало, ЦПУ никто не останавливает:
- **profi**: Gluk `EFF7`/`DFF7`/`BFF7` → `RTC_A`/`RTC_DI`/`RTC_WR_N` → `kg_mcu2` `ENABLE_RTC=>1`, `RTC_CS='1'`, `eeprom_bank 1`, `rtc_mode 0`; плюс I2C Next для esxDOS.
- **tsconf**: `rtc_mode 2` (ZX Evo), `eeprom_bank 0`. Оригинальный механизм ZX Evo — `zwait`: ЦПУ ждёт по `/WAIT`, пока AVR не ответит по SPI (`wait_start_gluclock` → `wait_end`). В нашем порте он закомментирован (`tsconf.v:1132` `wait_n(1'b1/*wait_n*/)`, блок `zwait` в `/* */`), чтение идёт из зеркала.
- **zxuno**: `zxuno_cmos.v` переводит MC146818 в раскладку DS1307 (`rtc_mode 1`). A, B, C, D там константы (C = `00`), `eeprom_bank 255`.
- Прецедент синхронного ответа MCU есть: nanomig DSKCHG (`IMG EVENT` kind 5, ядро держит выбор, пока не придёт `IMG 07`).

## 4. Проблемы, общие для любых вариантов

1. **Потеря записей в fifo.** Сохранение SETUP (`WRITING`: `0E..3F`, 50 вызовов `#F7`) даёт ≈150 записей за доли миллисекунды: тест 2 + данные 1 на ячейку, по ≈20 мкс на вызов при 21 МГц. Fifo на 8 переполняется, и пропадают в том числе настоящие байты и восстановление `#3F` (в 3.04). Зеркало в ПЛИС верное, а копия в MCU / `.eep` испорчена. После выключения будет «CHECKSUM ERROR». Нужен один из вариантов:
   - **слияние**: битовая маска «грязных» регистров, `GET` отдаёт текущие значения, последняя запись побеждает;
   - **`/WAIT` при полном fifo**.

   Это правка `kg_l2_rtc` под параметром, по умолчанию выключенная.
2. **C = `#50` и век.** С нынешней прошивкой (C = `00`, `#32` = `FF` при пустой EEPROM) BIOS 3.06 на каждом старте уходит в `CMSERR`. Тогда **DS3231 платы переставляется на дату сборки BIOS** через `adjust()`. Нужно:
   - чтение C отдаёт `#50` (константа или эмуляция PF/UF со сбросом по чтению);
   - `#32` в EEPROM_INIT = `#20`;
   - A = `#26`, B = `#02`.
3. **Сохранение настроек.** Нужен `eeprom_bank` 4..254 (`.eep`) и `EEPROM_INIT`: значения BIOS по умолчанию с верной суммой, либо только `0A`/`0B`/`32`, тогда BIOS один раз сам поставит значения по умолчанию.
4. Мелочи:
   - **День недели.** Прошивка шлёт 0..6 (0 = воскресенье, `kg_datetime_weekday`), а DS12887 ждёт 1..7 (1 = воскресенье). DSS читает его как есть. Ошибка общая для всех ядер `rtc_mode 0`.
   - **SET в B прошивка игнорирует.** Пакет времени раз в 500 мс может на миг вернуть старое значение между записями ЦПУ.
   - **Точность секунды.** Зеркало обновляется раз в 500 мс, фронт секунды запаздывает до 0,5 с, и `timerv2` будет врать.

## 5. Варианты

| | (a) RTL MC146818 | (b1) регистры на RP2040 + зеркало (как сейчас у profi) | (b2) регистры на RP2040, синхронно под `/WAIT` | (c) гибрид: b1 + тонкий RTL |
|---|---|---|---|---|
| Суть | Счёт времени, флаги и UIP в ПЛИС; при старте время из `kg_l2_rtc`; изменения и CMOS-байты уходят в MCU | Прошивка `rtc_mode 0` держит семантику и сохранение, ядро читает RAM `kg_l2_rtc` | Каждый `IN`/`OUT` — запрос по link, ЦПУ стоит до ответа | b1 плюс в ядре: защёлка адреса (7 бит), C = `#50` / PF-UF, D = `#80`, слияние или `/WAIT` для fifo |
| Чтение после записи (тест) | да | да (RAM пишется сразу) | только если ждать каждую запись или держать теневую копию | да |

| Ожидание ЦПУ | нет | нет | 0,1-несколько мс на доступ; 3.04 SETUP ≈150 синхронных чтений; теряются кадровый INT, SIO, звук CBL; `timerv2` бессмыслен | нет (кроме короткого `/WAIT` при полном fifo, если выбрать его) |

| Модули | двойной счёт времени, расхождение с DS3231, конфликт с пакетами `SET` | fifo-проблема (п. 4.1) | новый протокол | параметр слияния / full в `kg_l2_rtc` |

| Риски | дублирование логики, которая уже отлажена в прошивке | 3.06 `CMSERR` без правки C | задержки, нестабильный цикл, нет прецедента для частых обращений | минимальные |

Свободного места на Mini G достаточно: 45 % LUT, 63 % слайсов.

## 6. Рекомендация

**Вариант (c)**, по сути идея пользователя в уже существующей форме: регистры, время и сохранение на RP2040 через `rtc_mode 0`, в ядре только зеркало и тонкая логика.

Минимальный набор:
- **Ядро.**
  - Защёлка адреса по `CMOS_AS` (`MD[14:8]`, A7 игнорировать).
  - `CMOS_DWR` → `RTC_WR_N` на 1 такт.
  - `CMOS_DRD` → `PER_D[15:8] = RTC_DO`.
  - Подмены на чтении:
    - `0C` → `#50` (или эмуляция PF по 1024 Гц и UF по смене регистра `00`, со сбросом по чтению);
    - `0D` → `#80`;
    - `0A` бит 7 → 0.
- **Модули.** `kg_l2_rtc`: параметр слияния записей (маска 128/256 бит, `GET` с текущими значениями) или `/WAIT` при полном fifo.
- **core.json.**
  - `eeprom_bank` из 4..254 (файл `/config/sprinter.eep`), `rtc_mode 0`.
  - `EEPROM_INIT`: `0A = #26`, `0B = #02`, `32 = #20`. Значения по умолчанию из BIOS с суммой — по желанию.
- **Прошивка.** Ничего обязательного. Желательно исправить день недели (1..7) и, если нужен `timerv2`, отправлять время по смене секунды DS3231.

## 7. Вопросы пользователю

1. «Регистры на RP2040» — это (b1), то есть как сейчас: прошивка держит семантику, ядро читает зеркало? Или (b2), синхронный запрос на каждый доступ под `/WAIT`? (b2) не рекомендую (раздел 5).
2. Какие BIOS целевые: только 3.04 или сразу 3.05/3.06? Подмена C = `#50` нужна для 3.06. Для 3.04 проверить на плате или распаковать SETUP.
3. Fifo: слияние записей в `kg_l2_rtc` (PR в modules, параметр) или `/WAIT` при полном fifo?
4. Где хранить: файл `.eep` (банк 4..254) или 24C08 платы (банк 0..3, общий с другими ядрами)?
5. `EEPROM_INIT`: полный набор значений BIOS с суммой или только `0A`/`0B`/`32`? Во втором случае при первом старте один раз будет «CHECKSUM ERROR, INSTALL DEFAULT VALUES».
6. Нужна ли точная секунда (`timerv2`)? Если да: доработка прошивки (отправка по фронту секунды) или счётчик секунд в RTL?
7. Исправлять ли день недели (0..6 → 1..7) в прошивке для всех ядер `rtc_mode 0` (profi и т. д.)? Сначала проверить, чего ждёт BIOS profi.
