# Z84C15 в Sprinter: что реально использует софт

Цель — реализовать в ядре (T80) только те части Z84C15, которые трогает софт Sprinter. Опись на 2026-11-20.

## Источники и как искали

- MAME: `upstream/mame/sprinter.cpp` (подключение :1944-2005, список внутренних портов :1449-1454, CSBR :1160), `z84c015.{cpp,h}` (SCRP / SCDP). Файла `tmpz84c015.cpp` в `upstream/mame` нет (`tools/fetch_mame.sh` его не берёт) — сброс WDT / INTPR оттуда не взят; они и не нужны (п. 1.6).
- Порты: `sprinter.cpp:1449` + `estex_h.asm:149-167` (Sayman) + `KEYINTER.ASM:757`, `INTMOUSE.ASM:7`, `VIDEO.ASM:589` (DSS) + FUZIX `platform-micro80/z84c15.h`: CTC 10-13; SIO A data 18, ctrl 19, B data 1A, ctrl 1B; PIO A data 1C, ctrl 1D, B data 1E, ctrl 1F; SCRP EE, SCDP EF; WDTMR F0, WDTCR F1, INTPR F4. Регистры SCDP по индексу SCRP: 0 WCR, 1 MWBR, 2 CSBR, 3 MCR (`z84c015.cpp`).
- Исходники: BIOS 3.06 / 3.07 Tolik-Trek (`upstream/tt-sprinter-bios/bios`, имена `Z84.SIO.Ch_A.Ctrl` и т. п.; подмодуль `Shared_Includes` с их определениями пуст, номера портов восстановлены по комментариям и дизассемблеру), SETUP 2.17 (`upstream/sprinter-bios/SETUP`), DSS (`upstream/sprinter-dos`, утилиты), `upstream/sprinter-apps`.
- Двоичные: BIOS 3.04 (`~/Downloads/karabas-sd-sprinter/roms/mame-named/sp2k-3.04.rom`) — дизассемблер `z80dasm` в точках: POST-инициализация 0x20151, `PORTS_INIT` 0x2037E, загрузчик ACEX 0x30000; плюс BIOS 2.13 … 3.03, образы DSS 1.60 / 1.62, TITD (`titd0.exe`, `TITD.PAK`). Поиск — эвристический сканер `OUT/IN (n)` и `LD BC / LD C,n` + `ED`; он не видит упакованный код (SETUP внутри ROM, игры), а найденные в данных совпадения отброшены после дизассемблирования (CTC1 0xD19 / 0x2035F, CTC3 0x198A / 0x1CC7, WDTCR 0x183C в 2.13, `IN (10)` 0x228B2, `OUT (19)` 0x2701 / 0x22B94 / 0x3B34F в 3.04, `LD BC,#D8F0` в образе DSS 1.62 (это −10000 в выводе числа) — перекрытие операндов и данные). **Сторонний софт (игры, демо) не проверен полностью — открытый риск, не «нет».**

## 1. Таблица по блокам

Обозначения: «3.04» — BIOS 3.04 (двоичный), «TT» — BIOS 3.06 / 3.07, «DSS» — Estex DSS 1.6x исходники.

### 1.1 CTC

| Канал | Используется | Кем | Настройка |
|---|---|---|---|
| CTC0 | да | 3.04 `PORTS_INIT` (0x203C6), TT `EXP.asm:998-1003`, DSS `INTMOUSE.ASM:160-164` (`MS_INIT`) | управляющее слово **55** = счётчик (D6), фронт ↑ (D4), константа следует (D2), без прерывания (D7 = 0); константа **2D** (45). CLK/TRG0 = `AUD` = `CT3` MAX = 42 / 48 = 875 кГц → ZC/TO0 = 19,44 кГц = такт x16 SIO B ≈ 1215 бод (мышь 1200). Чтений CTC нет. |
| CTC1, CTC2, CTC3 | нет (найдено только в данных) | — | В MAME: CLK/TRG0-2 = 875 кГц, ZC/TO2 → TRG3 (каскад), ZC/TO0 → RxCB / TxCB. Это проводка, читателя не найдено. |
| Вектор CTC | не пишется | — | — |

### 1.2 SIO

| Канал | Используется | Кем | Настройка |
|---|---|---|---|
| SIO A, Rx | да: **скан-коды AT-клавиатуры, опросом** | 3.04 `PORTS_INIT` (0x2037E); TT `EXP.asm:961-997`; SETUP 2.17 `KEY.ASM:215`, 3.06 `SETUP/KEY.asm:166-185`; DSS `KEYINTER.ASM:255-258` (`KINIT` :760-781, вызов `DOS-MAIN.ASM:187`), утилита `KEYBOARD.ASM:1078` | WR1 = 00 (прерываний нет), WR3 = **C1** (Rx 8 бит, Rx вкл), WR4 = **05** в 3.04 (x1, 1 стоп, нечёт), **07** в DSS (x1, 1 стоп, чёт), **04** в TT (x1, 1 стоп, без чётности; `INC A` закомментирован). Такт x1 = внешний RxCA = линия CLK клавиатуры, RxDA = DATA. Опрос: RR0 бит 0 → чтение 18. TT дополнительно: RR1 бит 5 (overrun), WR0 = **30** (error reset), `KEY.asm:768-785`. При чётности, не совпадающей с AT (нечётная), байт всё равно должен приниматься — ошибки чётности / кадра ПО не смотрит. |
| SIO A, Tx | нет | — | WR5 = **62** (3.04, TT, DSS; **60** при `SPRINTER=97`): Tx 8 бит, **Tx выключен**, RTS = 1, DTR = 0. Сами биты WR5 DTR (7) / RTS (1) — см. п. 6. |
| SIO A, RR0 биты 5 / 3 (CTSA / DCDA) | только комментарий | `VIDEO.ASM:605-606` | PE (бумага) и SELECT принтера по комментарию DSS; `PRINT` порт 19 не читает. |
| SIO B, Rx | да: **мышь MS serial, опросом** | 3.04 (0x203A2), TT `EXP.asm:1004-1031`, DSS `INTMOUSE.ASM:165-182` (`MS_INIT`), чтение `READ_M` :626-645 (вызов из INT: `RST 30` с `C = 80`, `DOS-MAIN.ASM:92-94`) | WR1 = 00, WR3 = **41** (Rx **7 бит**, Rx вкл), WR4 = **44** в 3.04 (x16, 1 стоп, без чётности), **47** в DSS (x16, 1 стоп, чёт), **40** в TT (стоп-биты 00 — формально синхронный режим; в TT помечено `!TODO вспомнить`, DSS при старте мыши перезаписывает на 47). WR5 = **E0** (DTR = 1, Tx 8 бит, Tx выкл). Такт x16 = ZC/TO0. `READ_M`: RR0 бит 0, затем **внутри обработчика INT ждёт байты 2 и 3 в цикле** (`TST_01`, `TST_02`) — пакет из 3 байт должен приходить целиком; бит 6 = синхро-байт, бит 7 не смотрится. |
| SIO B, RR0 биты 5 / 3 (CTSB / DCDB) | DSS печать | `VIDEO.ASM:595-621` | WR0 = **00**, **10** (reset ext / status), **00**, затем RR0 канала B: бит 5 = BUSY (`BIT 5 / JR NZ,LPTBUSY` — 1 = занят), бит 3 = ACK. |
| SIO B, Tx | нет | — | Tx выключен. В MAME TxDB → RS-232 мыши (не нужно). |
| WR2 (вектор), прерывания SIO | нет | — | WR2 не пишется ни одной программой; WR1 = 00 у обоих каналов. |

### 1.3 PIO

| Порт | Используется | Кем | Настройка |
|---|---|---|---|
| PIO A | да, **только вывод** | 3.04 и TT POST (0x2015C; `EXP.asm:326-331`): CF, 00 (режим 3, все биты — выход) и данные 00 / коды 7-сегментного POST-индикатора; загрузчик 3.04 (0x30026): CF, 00, данные EA / 62; `PORTS_INIT` (3.04 0x203CE, TT `EXP.asm:1041-1042`): **0F, 0F** (режим 0, вывод); DSS `PRINT_INIT` 0F | Данные: принтер (DSS `PRINT`), POST-коды (`EXP.asm:453-741`), PC-Link полубайтами (TT `FUNC_SYS.ASM:397-510`, функция BIOS). ARDY → STROBE принтера, ASTB ← BUSY (схема 2016s). Чтений порта A нет. |
| PIO B | да, **только настройка и вывод** | 3.04 (0x203D4), TT `EXP.asm:1044-1050`, DSS `VIDEO.ASM:642-651` | CF + маска **3F** (BIOS: биты 0-5 вход, 6-7 выход) или **63** (DSS); байт после CF — маска направлений, не команда. Данные **C0** (бит 7 SELECT IN, бит 6 AUTO LF). Биты 0-5 по схеме — ISA IRQ1 / IRQ2 / DRQ2 / DACK2 / DRQ1 / DACK1. Чтений порта B не найдено. Порт 1F — только через `OUT (C),A` с `BC = 001F`: ACEX подменяет операнд 1F → 07 у `OUT (n),A` / `IN A,(n)` (`docs/ahdl.md`, ACCELER). |
| Прерывания / векторы PIO | нет | — | — |

### 1.4 SCRP / SCDP (EE / EF)

| Регистр | Кто пишет | Значения |
|---|---|---|
| WCR (0) | загрузчик (3.04 0x30001, TT `loader.asm:6-12`); EXP POST (3.04 0x20165, TT `EXP.asm:333-337`) | сброс **00** (MAME; по комментарию — FF до 16-го M1); **04** в загрузчике, **00** после него |
| MWBR (1) | никто | сброс **F0** |
| CSBR (2) | загрузчик: **FE** (0000-EFFF CS0, F000-FFFF CS1); если в `FEF0` найдена подпись конфигурации в fastram — **F0** (0000-0FFF CS0, 1000-FFFF CS1, загрузка битстрима из fastram с 1000, `loader.asm:45-50`) | сброс **FF** (MAME; комментарий там: на деле `|= 0x0f`); FE / F0 |
| MCR (3) | загрузчик **03** (CS0 + CS1); EXP POST **01** (только CS0, границы не меняет); TT `FUNC_SERVICE.asm:535-538` (`HardReset`) **03** | сброс **01**; 03 / 01 / 03 |

SCRP после сброса 00. Сброс MCR = 01 при CSBR = FF — вся память CS0. Загрузчик игры TITD (`TITD.PAK`, в начале — копия загрузчика ACEX: `DI`, `LD BC,#FFEE`, WCR = 04, …) пишет SCRP / SCDP так же, как загрузчик BIOS. Никто не читает SCDP. Бит деления такта и прочие старшие биты MCR всегда 0 (как после сброса). CSBR читает только MAME: `m_conf = !(csbr & 0x0f)` в конце битстрима (`sprinter.cpp:1160`) — признак «конфигурация из fastram». В MAME (`z84c015.cpp`, `translate_memory_address`) CS0 → обычная карта Sprinter, CS1 и «ни один» → `bootstrap_r` (fastram, пока идёт загрузка конфигурации).

### 1.5 CLKOUT / делитель

CLKOUT по схеме 2016s → цепь `CLK_Z80` (на ACEX). Делитель (MCR) не меняется программами. Для ядра не нужен: T80 тактуется нашим `ce`.

### 1.6 WDT, INTPR

Порты F0, F1, F4 не пишутся и не читаются ни в одном источнике (BIOS 2.13-3.04 двоичные, 3.06 / 3.07 и SETUP 2.17 исходники, DSS 1.52-1.70; в образах DSS 1.60 / 1.62 и TITD сканер нашёл только данные). Сброс WDT / INTPR не взят: `tmpz84c015.cpp` в `upstream/mame` нет. Раз WDT никто не выключает, WDTOUT не может быть заведён на сброс — **не реализуем**. INTPR (приоритет цепочки) не нужен — внутренних прерываний нет.

## 2. Прерывания

- **Ни один источник Z84C15 не включён**: WR1 = 00 у обоих каналов SIO, у CTC0 бит 7 = 0, нет слов разрешения прерываний PIO, векторы (WR2, вектор CTC, вектор PIO, INTPR) не пишутся. Цепочки приоритетов (daisy chain) в работе нет — **все INT идут от ACEX** (`INT_X`: кадр из таблицы режимов, клавиатура, CBL).
- Режимы: SETUP (2.17 `DSETUP.ASM:139-151`, 3.06 `SETUP/MAIN.asm:378-391`) — **IM 2**, `I` = старший байт ячейки на адресе `xxFF` (`IM2_INT.asm`: `INT_POINTER` выровнен на `#FF`), то есть рассчитан на **вектор FF**. Выход из SETUP — IM 1, `I = 3F`. DSS и EXP (BIOS) — **IM 1** (`RST 38`). ZX-софт — IM 1 или IM 2 с таблицей 257 байт.
- При INTA на шине должно быть **FF** (MAME: `set_irq_acknowledge_callback` → 0xFF, ACK снимает все три источника). В ядре: при INTA от T80 отдавать FF, внутренние блоки вектор не выставляют.
- RETI важен только ACEX (`ACC_BLK` в ACCELER: INTA ставит блокировку, RETI снимает), не Z84C15.

## 3. Клавиатура

Одна AT-линия (`KBD_CLK` / `KBD_DATA`) идёт **в оба места**:
- **SIO A** (RxCA = CLK, RxDA = DATA, x1) — скан-коды для SETUP, BIOS EXP и DSS: опрос в обработчике INT (`KEYSCAN`), своя таблица XLAT. Это путь «родного» режима Sprinter во всех версиях 2.17-3.07 и DSS.
- **ACEX KBD** (`KBD_CC` / `KBD_DD` через мультиплексор `XA`) — матрица ZX для портов `xxFE` в ZX-режиме, Ctrl+Alt+Del (`KB_RESET`), F12 (турбо), NMI; INT на каждый принятый байт — бит разрешения зависит от версии конфигурации: 3.03a `KEYS.int_ena = ALL_MODE0`, матрица ZX `KEYS.ena = ALL_MODE1` (`BASE_303.TDF:323-325`); MAME — `all_mode & 9 == 9` (биты 0 и 3), счёт 11 тактов линии (`sprinter.cpp:1709-1716`); k30 / BIOS 3.05+ — `ALL_MODE3` (`docs/PLAN.md`).
- Значит — **оба**: скан-коды через SIO, ZX-матрица и INT через ACEX.

## 4. Мышь

Одна линия `MOUSE_D` (MS serial, 1200 бод) идёт **в оба места**:
- **SIO B** (RxDB, x16 от CTC0) — драйвер DSS (`INTMOUSE.ASM`, протокол Microsoft: 3 байта, бит 6 = начало пакета).
- **ACEX MOUSE** (свой приёмник на `DFF(CTH5)` 15,6 кГц) → **Kempston-мышь** для ZX-режима (`BASE_303.TDF:1226-1232`: `KEMPS` = кнопки / X / Y по `DECODE.TYPE0`). Курсор VIDEO2 выключен (`MOUSE = "NO"`).

## 5. Минимальный набор для ядра

1. **Дешифрация**: внутренние порты по `A[7:0]` (10-13, 18-1B, 1C-1F, EE, EF; F0 / F1 / F4 — принять и игнорировать). Чтение внутреннего порта имеет приоритет над ACEX; запись **также уходит в DCP ACEX** (как в MAME `cpu_io_w`, `sprinter.cpp:1445-1458`).
2. **INTA → FF**; внутренних источников прерываний, векторов, daisy chain, RETI-логики в Z84C15 нет.
3. **SIO A Rx**: WR0 (указатель регистра, команды 10 / 30), WR3 бит 0, WR4 (только чтобы не мешать), WR1 / WR5 как регистры; FIFO 3 байта + RR0 бит 0, RR1 бит 5 (overrun) и сброс по команде 30. Байт принимать при любой ошибке чётности / кадра.
4. **SIO B Rx**: то же, плюс 7 бит (WR3 = 41), бит 7 — любой. Если принимать с линии — x16 от ZC/TO0 и асинхронный приём при WR4 = 40 (стоп-биты 00 трактовать как 1 стоп).
5. **RR0 CTS / DCD**: A — PE / SELECT, B — BUSY / ACK. Принтера нет → отдавать «занят» (бит 5 = 1, как у `rc2014_sio`): `PRINT` DSS выходит с CF = 1 без зависания. WR0 = 10 принять.
6. **CTC0**: счётчик с константой (нужен, только если SIO B принимает с линии); CTC1-3 — принимать запись, чтение — текущий счётчик (дёшево) или FF.
7. **PIO**: регистры режима / маски и данные A / B; выход данных никуда не нужен (принтера нет); чтение данных — регистр (входы = 1). Без handshake и прерываний.
8. **SCRP / SCDP**: указатель SCRP + 4 регистра (WCR, MWBR, CSBR, MCR) на чтение / запись, сброс SCRP 00, WCR 00, MWBR F0, CSBR FF, MCR 01 (MAME `z84c015.cpp`, `device_start`); CS0 / CS1 по CSBR + MCR — для выбора «обычная карта ACEX» / «fastram загрузчика» во время загрузки конфигурации и признака «конфигурация из fastram» (выбор личности по хэшу). Ожидания WCR не моделировать.
9. **Не реализуем**: WDT, INTPR, Tx обоих каналов SIO, синхронные режимы, CRC, векторы, CLKOUT / делитель.

**Подача данных (рекомендация).** Прошивка МК даёт скан-коды PS/2 и движения мыши. ACEX KBD / MOUSE в переводе AHDL ждут **линии** (`KBD_CC` / `KBD_DD`, `MOUSE_D`), поэтому генераторы линий нужны в любом случае: AT-кадр 11 бит (~10-15 кГц такт), пакет MS из 3 байт 1200 бод с **двумя стоп-битами** (подходит и под 7N1 BIOS, и под 7E1 DSS). SIO проще кормить **байтом в FIFO по концу кадра** генератора (в тот же момент, когда ACEX KBD ставит INT), а не вторым приёмником с линии: тогда CTC0 и внешние такты SIO функционально не нужны. Темп — не чаще одного байта на кадр AT (~1 мс), пакет мыши — целиком; при полном FIFO держать байт в генераторе (как `rxb_ready` у `rc2014_sio`), иначе overrun (TT его ловит, 3.04 / DSS — нет).

## 7. Неожиданное

- **Принтер DSS через SIO**: статус LPT читается с CTS / DCD обоих каналов SIO (`VIDEO.ASM:605-606`), строб — ARDY PIO A. Комментарий DSS к WR5 канала A: бит 7 = направление буфера LPT, бит 1 = разрешение буфера (`VIDEO.ASM:659`). Функция BIOS `#EA` «послать байт в клавиатуру» (`FN_KBD_OUT`: есть уже в 3.04, 0x23E4E; в TT `EXP.asm:1487-1541` с пометкой «скомпоновать и допаять») дёргает **те же** биты DTRA / RTSA как CLK / DATA клавиатуры (11 бит, задержка из `B`). Как это сочетается с LPT — неясно: либо нужна доработка платы, либо линии разделены на схеме; вызовов `#EA` в DSS / apps / BIOS не найдено. Для ядра: биты WR5 — просто регистр.
- **WR4 SIO B = 40 в TT 3.06** — стоп-биты 00 (синхронный режим на настоящем SIO); мышь в BIOS 3.06 до инициализации DSS, вероятно, не принимается. Ядро должно быть терпимым (асинхронный приём).
- **Чётность клавиатуры разная по версиям** (нечёт / чёт / нет) — ПО ошибки не проверяет, приём не должен зависеть от WR4.
- **Ранние BIOS** (`_bin_0001` … `_bin_0007`, `BIOS_20010724` … `BIOS_20020124`; страница 1, 0x78B5 / 0x78BE) переключают DTRB (WR5 B = E0 / 60) в коде вокруг дисковых функций (назначение неясно). В 2.13 / 2.17 / 3.0x этого нет. В MAME DTRB = управление джойстиком 1, PIO B7 / PIO A вход = джойстик 2 (LPT-адаптер Sprinter 2016s) — **читателей не найдено** (джойстики BIOS идут через ACEX, `DCP.ASM:59-75`).
- Порт 1F (Kempston у ZX) совпадает с управлением PIO B: от `IN A,(1F)` спасает только подмена операнда в ACEX; `IN A,(C)` с `C = 1F` попадает в Z84C15 и на настоящей машине.
- CS трогают только загрузчики ACEX (BIOS и копия в `TITD.PAK`): от CSBR зависит, откуда берётся битстрим (ROM или fastram), и MAME по этому же признаку отличает «игровую» конфигурацию.

## 8. Что построено (Ф1, ветка `f1-minig`, 2026-11-20)

### 8.1 Выбор ЦПУ: T80pa

- **T80pa** (Sorgelig, BSD-подобная лицензия Wallner — совместима с GPL-3), копия из core-tsconf / core-profi (`src/rtl/cpu/t80/`); в tsconf её шина сверена такт в такт с z80-silicon (`karabas-go-notes/z80-silicon.md`). Две правки `karabas:` в `T80pa.vhd`: выход `WRITE_CYC` (флаг записи машинного цикла T80 — включение шины данных) и сброс `IntCycleD_n` по `RESET_n` (без него INIT = 00 давал IORQ в первом M1 после включения — на шине цикл INTA, у нас вместо опкода `F3` читалось `FF`).
- Временная диаграмма — как у Z80: `/MREQ`, `/RD` спадают на спаде T1, `/IORQ` + `/RD` / `/WR` — на фронте T2, автоматический TW в вводе-выводе и два — в INTA (`/IORQ` на спаде TW1), `/WAIT` берётся на спаде T2 / TW, опкод — на фронте T3 (DInst), данные чтения — на спаде T3. Для `docs/memtiming.md` это столбец «Z80 / T80pa»: чтение ROM — `c_f+15`, кеша — `c_f+7` (на 2 такта позже, чем предполагалось по `T80s`); M1 — без изменений. Данные записи T80pa появляются на выводах с фронта T2 (`D_OE` — с T1, в T1 на шине предыдущий байт); модель `tb_eq_acex` давала их с T1. ACEX берёт данные ЦПУ по подъёму стробов (`iowr_ev`, `RGACC` по подъёму `/MR`), DRAM / видео — через `MDO` в цикле DRAM; для слотов кеша (`docs/memtiming.md` п. 2: «данные с T1») это значит: байт записи брать по `/WR`, не раньше. Обращения к кешу в `tb_cpu_acex` не проверены (записей в кеш 0).
- Отклонено: **z80-silicon** (GPL-3, точна до кристалла, 983 LUT против ~1800, в iverilog быстрее) — путь между полутактами 21,98 нс (XST, `prefix_logic/cb_set` (фронт) → `alu_logic/alua` (спад)) при бюджете полутакта 21 МГц = 2 `CLK` = 23,8 нс до разводки — запаса нет; tsconf гоняет её на 14 МГц. Подменяется через те же порты T80pa (`z80s_t80pa.v` из tsconf), если понадобится точность флагов X/Y. tv80 не рассматривался (тайминги T80s-типа, только фронты). NMOS / CMOS: `OUT0 = 1` — `OUT (C),0` выводит `FF`, как CMOS Z84C15.
- Известные отличия T80pa от кристалла (по сверке tsconf): X/Y у SCF / CCF, блочных команд, `BIT n,(HL)`; DD/FD + INC/DEC BC/DE/SP; INT берётся на 1 T позже; HALT на полтакта позже.

### 8.2 Такты (Ф0.5: «T80 на clk42» и «T80 на CE_N» — одно и то же)

T80pa тактируется `CLK` = 84 МГц с разрешениями `CEN_p = CE_N & (CLKZ1 растёт)`, `CEN_n = CE_N & (CLKZ1 падает)`; для этого нужен `CLKZ1_NX` — значение `CLK_Z80` после ближайшего CE_N (`sp_dcp` `CLK_Z80_NX` = `clkz_d`, загружается в `clkz_q` по CE_N). **В `sp_acex` такого выхода пока нет** — тест берёт `dut.clk_z80_nx` иерархически; нужен выход `CLKZ1_NX` в `sp_acex`. Выходы T80pa — копии `*_NX`, выводы — регистр по CE (меняются через 1 `CLK` после фронта `CLKZ1`, как в модели `tb_eq_acex`). Отдельный домен `clk42` не нужен: его фронт совпадает с CE_N, а внутренние пути ЦПУ всё равно многотактовые (см. 8.5) — в `.ucf` нужно ограничение FROM-TO по группе регистров T80 (≥ 2 `CLK`).

### 8.3 Файлы

- `src/rtl/cpu/sp_z84c15.v` — верх: T80pa, регистр выводов, дешифрация внутренних портов по `A[7:0]` (10-13, 18-1F, EE, EF, F0, F1, F4); чтение внутреннего порта берёт внутренние данные, что бы ни было на `D_I` (`INT_RD` — признак для верха); INTA → `FF`; записи — обычный цикл шины (их видит DCP ACEX). `D_OE` — цикл записи T80 (с T1, данные верны с фронта T2). `CS0` / `CS1` — по `A` выводов, `CSBR` / `MCR` наружу.
- `sp_sio_ch.v` — канал SIO: поток байтов (`RX_D` + строб, `RX_RDY` = есть место; при `RDY = 0` источник держит байт), FIFO 3 байта, переполнение — замена последнего и флаг RR1.5 до команды 30; RR0 (Rx, Tx пуст, CTS / DCD входами), RR1, RR2 (= WR2), WR0 (указатель, команды 10 / 18 / 30), WR3 (Rx вкл., бит/символ: старшие неиспользуемые биты = 1 — по памяти о Zilog, на кристалле не проверено), WR5 наружу.
- `sp_ctc_ch.v` — канал CTC: счётчик (фронт по D4) / таймер (x16 / x256 от такта Z80, запуск по TRG по D3), константа, перезагрузка, ZC/TO; без прерываний. Только канал 0; 11-13 — запись принимается, чтение `FF`.
- `sp_pio_port.v` — порт PIO: режимы 0-3, маска направлений, слова прерываний принимаются и игнорируются; сброс — режим 1.
- SCRP / SCDP — в верхнем модуле, сброс как в MAME; F0 / F1 / F4 — чтение `FF`.

### 8.4 Тесты

- **`src/sim/cpu/run_cpu.sh`** (~12 с; T80pa — сетевой список `ghdl --synth`, `t80_v.sh`): `tb_z84c15` + `z84c15_test.asm` (sjasmplus): внешние порты, SCRP / SCDP и сброс, CS0 / CS1 при CSBR FF / FE / F0 и MCR 03 / 01, SIO A (FIFO 3 + удержание 4-го, переполнение, RR1, сброс ошибки, Rx выкл.), SIO B (7 бит, CTS = занят, RR2), PIO A / B (режим 3 с маской, режим 0, `OUT (C)` в 1F), WDT-порты, CTC0 счётчик 55 / 2D (период 45 × 96 `CLK` = 875 кГц / 45) и таймер x16 / 16 (1024 `CLK`), IM 1, IM 2 с вектором FF (шина в INTA = 00), HALT, 3,5 МГц, ожидания (2 на память 4000-7FFF, 1 на порт). ### 8.7 Как /INT и /NMI доходят до Z84C15 (схема 2016s, лист 2)

- ACEX выводит управляющее слово на шину `MA` в фазах 5-6 (`MA[14..12] = !TURBO, INT_X, NMI_X`, SP2_ACEX:886) и стробирует его `WR_AWG` (DCP `WR_AWGX`).
- На плате: **DD16 = КР1533ТМ9 (74ALS174, шесть D-триггеров)**, вход C (вывод 9) = `WR_AWG` — **по фронту** (на УГО — динамический вход), R (вывод 1) = `RESET/` — **асинхронный сброс в 0**. D0 = `MA12` → Q0 (2), D1 = `MA13` → Q1 (5), D2 = `MA14` → Q2 (7) = `TURBO`; D3-D5 — `XA0..XA2`.
- Q0 → **DD17.1**, Q1 → **DD17.2**: **К155ЛА8** (2И-НЕ с открытым коллектором, входы соединены — инвертор) → цепи **`NMI/`** (вывод 63 Z84C15) и **`INT/`** (вывод 19). Подтяжки к VCC — R33 (`NMI/`) и R45 (`INT/`) на листе 1; других источников на этих цепях на схеме нет.
- Итого: `INT/` = `!Q1`, `NMI/` = `!Q0`, т. е. **`INT_X` / `NMI_X` активны единицей на `MA`**, защёлкиваются **по подъёму `WR_AWG`** и держатся до следующего `WR_AWG`; при `/RESET` = 0 обе линии неактивны (Q = 0). На `WR_AWG` висит C39 на землю (затягивает фронт).
- Тесты (`tb_cpu_acex`, `tb_cpu_acexm`) так и моделировали (фронт, полярность, MA до фронта); добавлен сброс защёлки по `/RESET`. Подсчёт в `tb_cpu_acexm`: на каждом подъёме `WR_AWG` сравнивается `MA[14..12]` до и после фронта — см. `docs/memtiming.md` п. 7.
