# План ядра Sprinter (Sp2000) для Karabas Go / Mini / Mini G

Цель: компьютер PetersPlus Sprinter Sp2000 (Иван Мак, 2000–2003) на платах Karabas (XC6SLX25, ISE 14.7, XST): Z84C15 21 МГц, «большая» ПЛИС ACEX EP1K30 (дешифратор портов и памяти, видео, ускоритель, AY, клавиатура, мышь), «малая» EPM7064 (такты, синхронизация, сепаратор FDD, загрузка конфигурации ACEX), 4 МБ ОЗУ, 256 КБ видео-ОЗУ, 64 КБ fastram, ROM 256 КБ, WD1793, IDE, DS12887, ISA-8.

## Решения пользователя (2026-11-20)

- Подход: **перевод AHDL в Verilog**. AHDL в ядре не остаётся; оригинальный AHDL — только эталон (исходники и сравнение в симуляции).
- Переконфигурация (R2): **один битстрим с несколькими «личностями»** — стандартная конфигурация и конфигурация игры Thunder in the Deep; выбор по хешу битстрима, который BIOS / программа заливает в ACEX, как в MAME.
- BIOS: **пробуем все** (2.13, 2.17, 3.00, 3.03, 3.04, 3.05, 3.06).
- Репозиторий **публичный**.

## Как устроена переконфигурация в оригинале

- `SP2_MAX`: `/CONF_X` (nCONFIG ACEX) = открытый сток от `/RESET` — каждый сброс стирает ACEX. Пока ACEX пуст, ЦПУ работает из ROM и побитно (`WR_CNF`, `D0` → `10K_CLK`, `10K_D0`) заливает битстрим 59 215 байт (в ROM с 0x30100, либо программа кладёт свой в fastram). Первый `XACS` от ACEX переключает MAX в рабочий режим до следующего сброса.
- Порт `2E` — перезагрузка конфигурации через сброс. Состояние программы не сохраняется: программа сама рассчитана на перезапуск.
- MAME узнаёт одну альтернативную конфигурацию — игры Thunder in the Deep (хеш 0x3861cfa4, вывод «not fully discovered»).
- Внутри стандартной конфигурации многое тоже «перенастраивается», но это обычная логика: карта портов и страниц — ОЗУ 256×16 (`DCP.MIF`), таблица клавиатуры, регистры AY.

У нас: ЦПУ и логика в одной ПЛИС, поток конфигурации принимает ядро (счёт байт, хеш, «конфигурация готова»), личность выбирается по хешу; неизвестный хеш → стандартная конфигурация и сообщение в OSD.

## Платы

Все три — XC6SLX25, две SRAM IS61WV20488BLL-10 (2M×8, 10 нс, общий адрес `MA[20:0]`, шина 16 бит = 4 МБ), SDRAM MT48LC16M16A2 32 МБ. Раскладка одна для всех плат:

- SRAM: видео-ОЗУ 256 КБ (опция 512 КБ), fastram 64 КБ, ROM 256 КБ. Оригинал читает видео-ОЗУ 32 битами (4 × W24512); у нас два 16-битных обращения на 84 МГц.
- SDRAM: основное ОЗУ 4 МБ (оригинал — SIMM DRAM с тактами ожидания); больше — по желанию.
- Видео: 896 точек на 14 МГц, 312 / 320 строк, 50 Гц → удвоитель → HDMI / VGA 28 МГц.
- Go: физический дисковод (как nanomig / uknc).

## Периферия

| Узел оригинала | У нас |
|---|---|
| Z84C15 (Z80 + CTC + SIO + PIO + WDT + CS / wait-регистры) | T80 + CTC + SIO (мышь MS, COM) + PIO + CSBR — собрать / написать |
| WD1793 + сепаратор в MAX | модель ВГ93 по выводам (как в p4096) + перевод сепаратора; образы 720K / 1.44M (PC) и TRD; Go — физический FDD |
| IDE | `hdf_ata` (modules), образ на SD |
| DS12887 | MC146818 + `kg_l2_rtc` |
| AT-клавиатура, мышь | скан-коды PS/2 от прошивки МК → модуль KBD (своя таблица в ОЗУ); мышь — MS serial в SIO |
| AY (в ACEX), CBL 16 бит стерео → TDA1543 | перевод AY.TDF / CBL → `kg_pcm5102`, HDMI-звук |
| ISA-8 | нет |

## Фазы

Одна ветка и один PR на фазу.

### Ф0 — изучение (ветка `f0-survey`)

- 0.1 Опись AHDL (`docs/ahdl.md`): модули, порты, клоки (производные и пульсирующие), асинхронные `clrn` / `prn`, `LCELL`-задержки, `TRI`, память `lpm_*` и `.MIF`; правила перевода в синхронный Verilog на 84 МГц с разрешениями.

- 0.3 MAME против 2.18: карта портов, страниц, ускоритель, CBL, видео; список отличий 3.0x; конфигурация игры.
- 0.4 ROM и софт: образы BIOS 2.13–3.06 (CRC из MAME), откуда 3.05 / 3.06; DSS, Thunder in the Deep, демо / игры для проверки — локально, `~/Downloads/karabas-sd-sprinter`.
- 0.5 План тактов и памяти: расписание слотов SRAM (видео / ЦПУ / ускоритель), SDRAM, оценка LUT (T80 + перевод).
