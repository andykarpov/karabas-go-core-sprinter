# План ядра Sprinter (Sp2000) для Karabas Go / Mini / Mini G

Цель: компьютер PetersPlus Sprinter Sp2000 (Иван Мак, 2000–2003) на платах Karabas (XC6SLX25, ISE 14.7, XST): Z84C15 21 МГц, «большая» ПЛИС ACEX EP1K30 (дешифратор портов и памяти, видео, ускоритель, AY, клавиатура, мышь, CBL), «малая» EPM7064 (такты, синхронизация, сепаратор FDD, загрузка конфигурации ACEX), 4 МБ ОЗУ, 256 КБ видео-ОЗУ, 64 КБ fastram, ROM 256 КБ, WD1793, IDE, DS12887, ISA-8.

Открытые пункты после выпуска: `docs/BACKLOG.md`.

## Переконфигурация в оригинале и у нас

- `SP2_MAX`: `/CONF_X` (nCONFIG ACEX) = открытый сток от `/RESET` — каждый сброс стирает ACEX. Пока ACEX пуст, ЦПУ работает из ROM и побитно (`WR_CNF`, `D0` → `10K_CLK`, `10K_D0`) заливает битстрим 59 215 байт (из ROM с 0x30100 или из fastram). Первый `XACS` от ACEX переключает MAX в рабочий режим до следующего сброса. Порт `2E` — перезагрузка через сброс; программа сама рассчитана на перезапуск.
- Внутри конфигурации многое тоже «перенастраивается» обычной логикой: таблица портов (байт-дескриптор из DRAM, страница 0x40) → `MEM` 256×16, таблица клавиатуры, регистры AY.
- У нас: поток конфигурации принимает ядро (счёт байт, хеш, «конфигурация готова»), личность выбирается по хешу; неизвестный хеш → стандартная конфигурация и сообщение в OSD. Сброс перезагружает все ОЗУ, которые пишет ЦПУ или логика (в оригинале их обнуляет переконфигурация).

## Платы, такты и память (Ф0.5)

Все три платы — XC6SLX25, две SRAM IS61WV20488BLL-10 (2M×8, 10 нс, общий адрес `MA[20:0]`, шина 16 бит = 4 МБ), SDRAM MT48LC16M16A2 32 МБ. Раскладка одна для всех плат.

**Такты.** Оригинал: всё от 42 МГц, цикл памяти / видео = 6 тактов (фазы `CT` 0, 1, 2, 4, 5, 6) = 7 МГц, Z80 21 / 3,5 МГц, ~60 производных тактов и 11 мест по спаду 42 МГц (`docs/ahdl.md` п. 2). У нас:

- `clk84` = 2 × 42 МГц — один домен для перевода ACEX / MAX, SRAM и SDRAM; фазы 42 МГц (оба фронта оригинала) — разрешения на чётном / нечётном такте `clk84`. Производные такты оригинала → разрешения на фронте источника (выделитель фронта в `clk84`).
- T80 — на `clk42` (из той же PLL, синхронен с `clk84`), CE 21 / 3,5 МГц. Fmax T80 ~76 МГц (XST, core-agon) — на 84 не пройдёт без многотактовых ограничений, на 42 проходит.
  **Изменено 2026-11-20 (Ф1, `docs/z84c15.md` 8):** T80pa на `clk84` с разрешениями `CE_N & фронт CLKZ1` (нужен `CLKZ1_NX` из ACEX), выводы — регистр по CE; домен `clk42` не нужен. Пути T80 CEN → CEN — 4 такта `clk84`, CEN_n → CEN_p — 2: в `.ucf` многотактовое ограничение FROM-TO на регистры T80 (XST: худший путь 17,2 нс).
- Видео: 896 точек на 14 МГц, 312 / 320 строк, 50 Гц → удвоитель строк → HDMI / VGA 28 МГц (как profi).

**SRAM (84 МГц).** Поправка Ф1.2 (`docs/memtiming.md`): с регистрами в IOB обращение занимает 2 такта (~22 нс: выход 8 + SRAM 10 + вход 4) — **6 обращений по 16 бит на 7-МГц цикл**, свободно 1–2, а не 12 / 5–6, как оценено ниже. Помещается при выводе ранних сигналов из VIDEO2 / ACEX (`VA_NX`, `V_WR_NX`, `VA_MOD` + `MODE_RQ`, `VA_ATR`, `PIX_RQ`) и упреждающем чтении fastram по смене A; остаточный конфликт — первый графический цикл после ZX (+1 ожидание Z80). Исходная оценка:

| Слот | Что | Обращений по 16 бит |
|---|---|---|
| точки | 1 байт / цикл (графика), реже в ZX | 1 |
| атрибут / цвет | 1 байт / цикл | 1 |
| таблица режимов | 3 байта раз в 8 (4) циклов | 2 (раз в 4 цикла) |
| запись ЦПУ / ускорителя в видео-ОЗУ | ≤ 1 (2 при `DOUBLE_CAS`) байт / цикл | 1–2 |
| ЦПУ: ROM, fastram | ≤ 1 / цикл (3 такта Z80 на цикл) | 1 |
| свободно | | 5–6 |

- Палитра (256 × 8 слов в видео-ОЗУ, байты 0x3E0–0x3FF каждой строки) — **теневая копия в BRAM** (4 RAMB16), заполняется подглядыванием записей в эту область; из SRAM палитра не читается.
- Раскладка SRAM: видео-ОЗУ 512 КБ (256 КБ — штатно, вторая половина — опция 512 КБ), ROM 256 КБ (из `.kg` или с SD), fastram 64 КБ; остальное свободно (кеш дискет / HDD).

**SDRAM (84 МГц).** Основное ОЗУ 4 МБ (DRAM оригинала, страницы по 16 КБ). Оригинал делает одно обращение к DRAM за 7-МГц цикл: ЦПУ, ускоритель, байт-дескриптор порта (каждый `IN` / `OUT`) или отложенная регенерация. У нас тот же цикл: 12 тактов 84 МГц, случайное чтение / запись ACT + RD/WR + CL2 + PRE ≈ 7 тактов, регенерация — в цикле без запроса (как CBR оригинала, раз в 24 такта 42 МГц запрос; SDRAM нужно 8192 за 64 мс — с запасом). Такты ожидания ЦПУ остаются как в оригинале. Больше 4 МБ (до 16) — позже, по желанию.

**Объём (оценка).** Перевод ACEX + MAX ~1,1–1,4 тыс. LUT6 и ~1,1 тыс. триггеров, 5 RAMB8 (+4 RAMB16 палитры); T80 ~1,9 тыс.; Z84C15 (CTC, SIO, PIO, CS) ~1 тыс.; ВГ93 + сепаратор, `hdf_ata`, MC146818, SDRAM, удвоитель, HDMI, `kg_mcu2` / OSD ~4–5 тыс. Итого ~9–10 тыс. из 15 тыс. LUT6 — помещается на всех платах; SCROLL второй личностью ~1 тыс. LUT сверху.

### Ф4 — базовые узлы платы и дисковод Go (ветка `f4-board-io`)

Решения пользователя 2026-11-22: CD-ROM (ATAPI) не делаем ни в каком виде, второй канал IDE в этом ядре не подключаем. Базовый набор платы обязателен для всех ядер.

- 4.1 ✓ Пики звука на MCU (`audio_peaks` из modules, общий микс L / R): `audio_peaks` на `clk_bus` (такт `kg_mcu2`) по итоговому миксу `audio_l` / `audio_r` → `MATRIX_CMD` / `MATRIX_CMD_WR` (`ENABLE_AUX` уже был), как в core-nanomig; все три платы.
- 4.2 ✓ Лента: проверить `TAPE_IN` / `TAPE_OUT` (порт `FE` через ACEX), монитор ленты `kg_tape_monitor` в микс, пункт OSD «Tape monitor» Off / In / Out / Both (Menu+T), как в tsconf. Путь проверен в `sim/io/run_io.sh` (машина + io.asm в ROM, ~1 мин со сборкой Verilator): `IN (#FE)` бит 6 = `TAPE_IN` (0 и 1), `OUT (#FE)` бит 3 → `TAPE_OUT` (1 и 0). `kg_tape_monitor` (modules, как в tsconf) на `clk_bus`, его отсчёт складывается с L / R с насыщением; OSD — индекс 3 (`SW_N` = 4 на всех платах, VGA Sync Go остаётся 2). Подмодуль `modules` не обновляли: `kg_tape_monitor` / `audio_peaks` в нём уже есть.
- 4.3 ✓ MIDI: бит 2 регистра 14 AY (порт A, как у ZX 128 и tsconf) → `MIDI_TX`; запись регистра перехватывается вне ACEX (AY в ACEX — микропрограмма). `sp_acex` отдаёт стробы портов AY (коды DCP 90 / 91, т. е. `#FFFD` / `#BFFD` по таблице портов, а не своя дешифрация адреса): `AY_A_EV`, `AY_D_WR_N`, `AY_D_EV` (пометка `karabas:`); в `sp_machine` — тень R14: номер регистра `D[3:0]` в конце записи `#FFFD` (как `sp_ay`, старшие биты не проверяются), байт данных во время записи `#BFFD`, `MIDI_TX` = бит 2 (без учёта R7, как turbosound tsconf); 1 (покой) после сброса ЦПУ, пока ACEX не запущен и в SCROLL (там AY нет). Все три платы. Проверено в `sim/io/run_io.sh` (R14 = FB → 0, запись R7 не меняет, R14 = 04 → 1, запись R13 не меняет); `run_eq.sh acex` (SCEN 0) и `run_storage.sh` — 0 ошибок.
- 4.4 ✓ АЦП PCM1808: приёмник I2S, `ADC_CLK`, линейный вход в микс. В симуляции не проверялось (модуль тот же, что в p4096 / tsconf / baseconf), на плате — нет.
