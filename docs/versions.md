# Версии конфигурации ACEX: 2.18 → 3.03a и k30 (Ф1.0)

Источники: коммиты `upstream/tt-sp2000-acex` (3.00 `e93c37c8`, 3.03 `ea1f5e1b`, 3.03a `26b05fdf`) и k30 (`upstream/tt-sprinter-bios` @ 085ef3c `src/altera/acex/k30`), сравнение с 2.18 (`sprinter-hard/MaxPlus2`). Строки ниже — по `BASE_303.TDF`, `DCP.TDF`, `VIDEO2.TDF` 3.03a.

## 2.18 → 3.00 («программа может гасить изображение»)

- `SVIDEO.DIR_PORT[4] = RGMOD2` (было `GND` или `RGMOD1` при `SCREEN_OFF = "USE"`): бит 2 регистра видеорежима (порт `C5`) гасит изображение.

## 3.00 → 3.03 («программное управление клавиатурой, прерыванием и сбросом»)

| Где | 3.00 | 3.03 |
|---|---|---|
| `/RESET` | `!DFF(KEYS.kb_reset & SOFT_RESET)` | `!DFF((KEYS.kb_reset or !ALL_MODE5) & SOFT_RESET)` — Ctrl+Alt+Del запрещается битом 5 `ALL_MODE` |
| `KEYS.ena` | `!ALL_MODE0` | `ALL_MODE1` — чтение матрицы ZX по биту 1 |
| `NMI_X` | `GND` (или Alt+F12 при `NMI_ON`) | `!ALL_MODE4 & kb_alt & !kb_f12` — NMI по Alt+F12, запрет битом 4 |
| `CAS_A` | `LCELL(DECODE.CAS)` | `DECODE.CAS or DFF(!MC_WRITE & DECODE.CAS)` — CAS при записи на такт дольше |
| `/WE` | `DFFE(/WE_OUT or DECODE.RAS, CLK42, , /RESET)` | `!DFF(!/WE_OUT & !DECODE.CAS, !CLK42, !/WE_OUT & !DECODE.RAS)` — по спаду 42 МГц |
| `BLK_MR` | комбинационный | триггер на CLK42 (та же функция) |
| `ZX_PORT[6]` | `SP_SCR & !(A13 & !G_LINE7) & !G_LINE6` | `… & !ALL_MODE0` — бит 0 `ALL_MODE` отключает дублирование ZX-экрана в видео-ОЗУ |
| DCP `RAS.ena` / `CAS.ena` | одной формулой | разбиты на `LCELL` (та же функция) |
| VIDEO2 `V_CS0` | `GND` | `DFF(!VCM0 & VCM1, CLK42, V_CSX1)`, `V_CSX1 = LCELL(LCELL(!CLK42))`: сбрасывается, пока CLK42 = 1, начиная с того же фронта, что его ставит — по логике постоянный 0 (в микросхеме — иголка в две задержки LCELL в начале слота записи). Похоже на мёртвый опыт или ошибку восстановления; `V_CS1` = VCC. Вторая половина 512 КБ этим не включается — сверить по схеме |
| `DCP.MIF` | ячейка `EE` = `2000` | `2041` (3.03), снова `2000` в 3.03a (страница перехвата Reset после SCROLL) |

Это закрывает часть пунктов «3.0x?» из `docs/mame.md`: биты `ALL_MODE` 0, 1, 4, 5 (D2), дублирование ZX-экрана, гашение. Код 89 на чтение (D4), бит 1 данных кодов 16 / 17 (D12), `PN5` (D14) в 3.03a **не менялись** — у MAME это либо k30, либо ошибка эмулятора.

## k30 (BIOS 3.05 / 3.06): отдельная ветка от 2.18 — личность `PERS_K30` (сделано)

Источник — `upstream/tt-sprinter-bios` @ 085ef3c `src/altera/acex/k30` (верх `SP2_ACEX.TDF`), эталон `build_ref.sh K30`. Сравнение с 3.03a по модулям — по исходникам без комментариев (`--`, `% … %`) и пробелов, построчно; все различия ниже, остальное совпадает.

k30 сделан из авторского 2.18; изменений 3.00–3.03 в нём нет, есть свои.

**Верх (`SP2_ACEX.TDF` против `BASE_303.TDF`)**

| Где | 3.03a | k30 | Чьё |
|---|---|---|---|
| `/RESET` | `!DFF((KEYS.kb_reset or !ALL_MODE5) & SOFT_RESET)` | `!DFF(KEYS.kb_reset & SOFT_RESET)` — Ctrl+Alt+Del всегда | нет 3.03 |
| `KEYS.int_ena` | `ALL_MODE0` | `ALL_MODE0 & ALL_MODE3` (MAME: `(ALL_MODE & 9) == 9`) | своё |
| `KEYS.ena` | `ALL_MODE1` | `VCC` — матрица ZX всегда | своё (2.18: `!ALL_MODE0`) |
| `NMI_X` | `!ALL_MODE4 & kb_alt & !kb_f12` | `GND` (`NMI_ON = "OFF"`) | нет 3.03 |
| `CAS_A` | `DECODE.CAS or DFF(!MC_WRITE & DECODE.CAS)` | `DECODE.CAS` | нет 3.03 |
| `/WE` | `!DFF(!/WE_OUT & !DECODE.CAS, !CLK42, !/WE_OUT & !DECODE.RAS)` | `DFFE(/WE_OUT or DECODE.RAS, CLK42, , /RESET)` — по фронту, preset от `/RESET` | нет 3.03 |
| `BLK_MR` | триггер на CLK42 | комбинационный (`LCELL`) | нет 3.03 |
| `SVIDEO.DIR_PORT[4]` | `RGMOD2` | `GND` (`SCREEN_OFF = "NOT_USE"`): гашения битом 2 порта `C5` нет | нет 3.00 |
| `ZX_PORT[6]` | `… & !ALL_MODE0` | то же (k30 «NEW 25.08.2022») | одинаково |
| `XA` | `XA[2..0]` + вход `XA3` | `XA[3..0]` двунаправленный, `XA3 = TRI(GND, GND)` | только выводы |

**Подмодули**

| Модуль | Отличие |
|---|---|
| DCP | `PN[7..6].clrn = /RESET & CNF7` (3.03a и 2.18: `PN[7..5]`): `PN5` сбрасывается `CNF5` и больше не держится Pentagon-512. Остальное — `RAS.ena` / `CAS.ena` одной формулой (та же функция) |
| VIDEO2 | `WR_PIC.d = MODE0[5]` в слоте таблицы режимов (3.03a: `X_MODE5` — защёлкнутый по `LWR_COL`; k30 «NEW 26.08.2022, fix bug with first column» при переходе 320 → 640). `TSN_W3.d = X_MODE_BOND` = `GND` в обоих. `V_CS0 = GND` (в 3.03a триггер, по логике тоже 0). Формирователь записи (`V_WEMM…`, `F_WR`, цепочки `LCELL`) — те же `V_WR = V_WEN = V_WE or V_EN` без задержек. Нет `VLA_NEXT` / `VLA_MUX` / `CLK84` (перестановки и мёртвая логика) |
| ACCELER | `AA[]` / `AGR[]` +1 одной формулой (в 3.03a через узлы `AA_INC` / `AA_LOAD`) — та же функция |
| AY, KBD, MOUSE; все MIF | байт в байт |

**Перевод.** Вход `PERS_K30` у `sp_acex`, `sp_dcp`, `sp_video2` (в коде пометки `K30:`): мультиплексоры только перечисленных строк, при 0 — 3.03a бит в бит. Новые регистры: `we_q` (`/WE` k30, начальное 1, в `CFG_RST`). `BLK_MR` 3.03a — `blk_mr_q`, k30 — комбинационный `blk_mr_d`. Выбор — `sp_machine.CFG_PERS` = 1 по хешу при отпускании ACEX (`docs/machine.md` п. 3), вход меняется только во время `CFG_RST`.

**Сборки k30 в BIOS.** Хеш MAME у 3.05 / 3.06 EP1K30 — `5aa954b6`; другие сборки k30: `ae54ab61` (MAME 3.05), `49861031`, `fffc0208`. Переведена одна сборка (085ef3c); `f82f646` отличается только `PN5` (`PN[7..5]`). Что в других — не проверено.

**Проверка** (`src/sim/eq/run_eq.sh`, наш модуль с `PERS_K30` = 1 против сетевых списков k30):

| Тест | Эталон | Итог |
|---|---|---|
| `dcp_k30` (`tb_eq_dcp -DK30`) | `DCPK30` (DCP k30) | 0 расхождений, ~38 с |
| `video2_k30` (`tb_eq_video2 -DK30`) | `VIDK30` | 0, ~31 с |
| `acex_k30` (`tb_eq_acex -DK30`, верх `SP2_ACEX`: имена выводов в нижнем регистре, `XA[3:0]`) | `K30` | 0 во всех трёх сценариях, 6 мин 40 с подряд (`SCEN="0 1 2"`) |
| `acexm_k30` (то же на `sp_sram` / `sp_sdram` и моделях памяти) | `K30` | 0 во всех трёх, 3 мин 50 с: контроллер SDRAM работает и с `/WE` / `CAS_A` k30 |

Мутации — строка k30 возвращена к 3.03a через `force` (у iverilog правая часть `force` вычисляется один раз, если это не простая цепь: формы 3.03a — цепи стенда), прогон обязан упасть. `run_eq.sh acex_k30_mut`: `CAS_A`, `/WE`, `KEYS.int_ena`, `KEYS.ena`, `NMI_X`, `DIR_PORT[4]`, `/RESET` (Ctrl+Alt+Del при `ALL_MODE5` = 0), `WR_PIC` — пойманы (8 из 9, ~9 мин); `BLK_MR` (триггер вместо комбинационного) — **не пойман, открыто**: в сценарии 0 `BLK_MR` = 1 в 18 тактах записи в DRAM (`MC_WRITE` = 0, других запретов нет), но формы k30 и 3.03a там ни разу не различаются (страница не меняется в такте перед записью); застрявший в 0 `BLK_MR` (ранний неверный вариант мутации) выходы тоже не изменил — почему, не выяснено. Нужен тест записи в страницу `5x` сразу после смены страницы / `GLISSER`. `dcp_k30 +mut` (`PN5`) и `video2_k30 +mut` (`WR_PIC`) — пойманы.

Чтобы мутации было чем ловить, сценарий 2 `tb_eq_acex` дополнен (и для 3.03a): Ctrl+Alt+Del дважды, Alt+F12 при `ALL_MODE4` = 0, удержание `A` с чтениями `FDFE` / `00FE` при `ALL_MODE1` = 0 и 1, `ALL_MODE[5:0]` случайно. Заодно в 3.03a впервые проверены `NMI_X` (Alt+F12) и запрет Ctrl+Alt+Del битом 5 — 0 расхождений.

Не проверено: сборки k30 с другими хешами (`ae54ab61`, `49861031`, `fffc0208`), плата.
