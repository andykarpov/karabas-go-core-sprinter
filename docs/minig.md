# Sprinter на Karabas Mini G (Ф1.4)

Верх платы — `src/rtl/karabas_minig_top.v`: PLL, выводы, связь с МК (`kg_mcu2`, link v2), загрузка ROM из `.kg`, клавиатура и мышь от МК, видеовыход, звук. Машина — `sp_machine` (`docs/machine.md`) без изменений. Новое «клеевое» RTL без привязки к плате — `src/rtl/board/`.

## 1. Такты

Одна PLL от `CLK_50MHZ` (как core-p4096 / core-baseconf): VCO 50 × 37 / 2 = 925 МГц.

| Выход | Делитель | Частота | Что |
|---|---|---|---|
| `pll_clk<0>` = `clk_sys` | 11 | 84,09 МГц | `CLK` машины (2 × 42,045 МГц оригинала): ACEX, MAX, T80pa по разрешениям, контроллеры SRAM / SDRAM, запись в удвоитель строк, генераторы линий клавиатуры / мыши, мост загрузчика, приём I2S |
| `pll_clk<2>` = `clk_bus` | 33 | 28,03 МГц | ровно `clk_sys` / 3, фронты совпадают: `kg_mcu2`, OSD, чтение удвоителя, HDMI в режиме ядра, ЦАП PCM5102 |
| `pll_clk<1>` = `clk_8` | 116 | 7,97 МГц | `FT_CLK_OUT` (ODDR2; обязателен на Mini / Mini G) и `DCM_CLKGEN` HDMI |

- `SDR_CLK` = инверсный `clk_sys` — ODDR2 внутри `sp_sdram` (`docs/memtiming.md` 6.3), отдельного выхода PLL нет.
- Точка 14 МГц — не такт, а подъём `WR_COL` в домене `clk_sys` (раз в 6 тактов). Строка = 896 точек = 5376 `clk_sys` = ровно 1792 `clk_bus`.
- Частоты оригинала (42 МГц → у нас 42,045): Z80 21,02 / 3,5 МГц, строка 63,93 мкс, кадр 312 строк — 50,08 Гц, 320 — 48,83 Гц.
- Переходы 84 ↔ 28: регистр → регистр, обе частоты из одной PLL — ISE анализирует их с фазами (1 такт 84 МГц). Стробы `clk_bus` (`LD_WR`, `PS2_WR`, `MS_WR`, длина 3 `clk_sys`) ловятся выделителем фронта, начало строки в удвоитель — переключателем (toggle).

## 2. Выводы и ограничения (`src/karabas_minig.ucf`)

- Выводы — как у core-p4096 / core-archie (Mini G). `FLASH_CS_N` = 0 (это `~CS` SDRAM на ревизии G2). SDRAM: `CS_N` / `CKE` на плате не выведены, `sp_sdram` держит `CS_N` = 0 и даёт NOP командой 111.
- SRAM: адрес и `/OE` — регистры IOB; данные, их выход (T) и `/WE` — ODDR2, вход — IDDR2 (`Q0`; IOB не смешивает SDR и DDR, п. 8); `MD` через `IOBUF` побитно. `TS_SRAM_OUT` 8 нс, `TS_SRAM_IN` 4 нс (как core-archie: 8 + tAA 10 + 4 = 22 нс < 23,8).
- SDRAM: `TS_SDR_OUT` 6 нс, `TS_SDR_IN` 4 нс (как core-archie).
- T80pa: группа `machine/CPU/cpu/*` (`TG_T80`), `FROM TG_T80 TO TG_T80` = 23,78 нс (2 такта): каждый регистр T80pa меняется только на `CE_N`, где меняется `CLKZ1`, а таких `CE_N` не меньше двух тактов друг от друга (`docs/z84c15.md` 8.2, 8.5). Пути в группу и из неё — однотактовые.
- MCU_SCK, FT_CLK, HDMI — как core-p4096.
- XST: `register_balancing`, `move_first_stage`, `move_last_stage` выключены (у p4096 включены): регистры IOB и многотактовая группа T80 не должны переезжать.

## 3. Загрузка ROM

- `core.json` `"roms"`: `roms/kg/sp2k-3.06-hf2.rom` по адресу 0 (256 КБ; BIOS 3.06 Hotfix 2, «Релиз 19.01.2026», CRC `9aa7bb29`; до 26112106 — 3.04, затем 3.06 `187f4382`). Образ в git не лежит (`docs/roms.md`): `make minig` копирует его из `$(ROM)` (по умолчанию `~/Downloads/karabas-sd-sprinter/roms/unreal-ng-2026-11-21/sp2k-3.06-hf2.rom`, из [unreal-ng](https://github.com/alfishe/unreal-ng/tree/master/data/rom/sprinter)) в `src/roms/kg/` (в `.gitignore`); без файла — ошибка с подсказкой.
- МК грузит ROM через `kg_l2_load` (вид 0) байтами, не чаще одного на 250 нс. `sp_ld_bridge`: байт `b` → слово `0x040000 + b[17:1]` SRAM, байт слова по `b[0]` (0 = `D[7:0]`), FIFO 16, порт загрузчика `sp_sram` (свободные слоты; пока машина в сбросе, их почти все). `LD_READY` = 1, `CAPS` = 0.
- Сброс машины (`EPM_RES_N` = кнопка RESET оригинала: MAX `/RESET`, ACEX стёрт, BIOS заливает конфигурацию заново): с включения до конца первой загрузки ROM, на время загрузки ROM, пока МК `BUSY`, пока мост не пуст, по OSD Reset и кнопке платы 1. Затем MAX отпускает `/RESET` (по кадровому синхроимпульсу), ЦПУ исполняет загрузчик ACEX из ROM `0x30000` (~0,48 с), ACEX стартует, BIOS — со страницы 8.

## 4. Видео

`sp_vout` (`src/rtl/board/sp_vout.v`):

- Точка: на подъёме `WR_COL` берётся `PAL_Q` (тень палитры `sp_sram`; так же её сверяет `tb_mem.vh` с шиной эталона — 0 ошибок). Цвет: MAME хранит R, G, B по смещениям 0, 1, 2 элемента палитры; смещение 0 (`VXA[1:0]` = 00) — это байт 3 слова видео-ОЗУ (`V_WR[3]`), значит **R = `PAL_Q[31:24]`, G = `[23:16]`, B = `[15:8]`**, по 8 бит. Схемой не подтверждено (`docs/ahdl.md` п. 6, вопрос 8) — проверить на плате.
- `BLANK` ACEX не трогаем: в оригинале он даёт индекс 0 палитры (`DCOL.clrn`), это и идёт в ЦАП.
- Развёртка — по синхроимпульсам MAX: точка `x` — счёт подъёмов `WR_COL` от подъёма `SINC_H` (`x` 0..63 — сам импульс), строка `v` — счёт `SINC_H` от подъёма `SINC_V` (`v` 0..3 — импульс). Положение картинки относительно синхро задаёт программа (`HOLD`, порт CB), поэтому окно привязано к синхро, а не к счётчикам ACEX. 312 и 320 строк — оба (строки считаются, длина кадра — от MAX).
- Удвоитель: буфер 2 × 1024 × 24 (запись — `clk_sys`, чтение — `clk_bus`), каждая готовая строка читается дважды, точка за такт: 896 × 624 (640) на 28,03 МГц.
- Выход в OSD / HDMI: `DE` — точки `H0` … `H0`+719, строки `V0` … `V0`+287 (720 × 576), `H0` = 120, `V0` = 14 — **оценка** (PAL: активная часть ~10,4 мкс от начала синхро; MAME показывает 736 × 288 из 896 × 320), подбирать по снимку на плате. `HS` = точки 0..63, `VS` = строки `v` 0..3 (8 выходных строк), положительные (как их ждёт `kg_hdmi_ft`).
- Пока ACEX пуст (заливка конфигурации ~0,5 с после сброса) — чёрный кадр, синхро идут (MAX считает всегда).

## 5. Клавиатура и мышь

МК шлёт байты PS/2 набора 2 (`PS2_CODE`, `PS2_KIND` = 0; байты XT, `PS2_KIND` = 1, отбрасываются) и движения мыши (`MS_X` / `MS_Y` / `MS_B`).

- `sp_kbd_tx`: FIFO 16 байт → кадр AT 11 бит на `KBD_CC` / `KBD_DD` (вход мультиплексора `XA` → модуль KBD ACEX: матрица ZX, Ctrl+Alt+Del, F12 = турбо, INT). Бит 80 мкс (12,5 кГц), такт низкий с 1/5 до 7/10 бита, данные меняются в начале бита. Пауза между кадрами 1 мс: логика кадра ACEX (`KB_CT`) считает строки (64 мкс), пока такт высокий, и обрабатывает байт на счёте 3 … 0 — через 7 строк (448 мкс) после стоп-бита. В конце кадра тот же байт — в SIO A (`RXA_D` / `RXA_STB`; SIO берёт его только при `WR3` бит 0 = 1, как настоящий). Генератор SIO **не ждёт**: если программа не читает SIO (ZX-режим, зависший BIOS), FIFO на 3 байта переполняется, как у кристалла, а линии ACEX (Ctrl+Alt+Del, F12, матрица ZX) продолжают работать. Команд к клавиатуре (светодиоды) нет.
- `sp_ms_tx`: пакет Microsoft (3 байта: `1 L R Y7 Y6 X7 X6`, `0 X5..X0`, `0 Y5..Y0`, Y вниз — как USB) на `MOUSE_D` (модуль MOUSE ACEX), 1200 бод, старт, 7 бит, **два стоп-бита** (годится и для 7N1 BIOS, и для 7E1 DSS); каждый байт в конце кадра — в SIO B (тоже без ожидания). Движения копятся между пакетами (насыщение ±511), шаг пакета ±127, пакет — при ненулевой сумме или смене кнопок.

## 6. Звук и OSD

- `sp_i2s_rx`: поток I2S ACEX к TDA1543 (`DAC_BCK` 7 МГц, `DAC_WS` 218,75 кГц, 16 бит, MSB через такт после смены WS, WS = 0 — левый, дополнительный код) → два 16-битных отсчёта → `kg_pcm5102` (ЦАП платы) и звук HDMI (48 кГц, `kg_hdmi_ft`). Без смешивания и фильтра: AY + CBL так, как их сложил ACEX.
- OSD (`core.json`): только `Reset` (индекс 0, горячая клавиша **Menu+F12** — просто F12 у Sprinter — переключатель турбо, Ctrl+Alt+Del — его собственный мягкий сброс без переконфигурации). Выбор BIOS, диски — Ф2.
- Не сделано (шина в покое): ВГ93 + дисководы (`FDD_W` / `FDD_CH` = 1), IDE (CF-карта не выбрана), DS12887 (`kg_mcu2` без RTC), ISA, лента (вход `TAPE_IN` идёт в `XA`, выход `TAPE_OUT` — на вывод, не проверялись), АЦП, ESP.

## 7. Проверка в симуляции

- `src/sim/board/run_board.sh` (`tb_board.v`, iverilog, ~25 с): `sp_machine` + `sp_ld_bridge` + `sp_vout` + `sp_kbd_tx` + `sp_i2s_rx`, сброс как в верхе. Загрузчик МК (тайминг `kg_l2_load`, байт на 7 тактов 28 МГц) пишет страницу загрузчика ACEX (ROM `0x30000`, 512 байт; остальной ROM предзагружен, место загрузки сначала `FF`) — **0 ошибок**: все 512 байт в SRAM на момент отпускания сброса, первая выборка 0000 = `F3` (ROM `0x30000`), поток (256 бит), ACEX отпущен, первая выборка в рабочей карте — 0000 страницы 8; 896 подъёмов `WR_COL` и 896 записей в буфер на строку, на выходе 896 тактов, `HS` 64, `DE` 720 (окно в тесте сдвинуто, `V0` = 2); кадр клавиатуры `1C` — сдвиговый регистр KBD ACEX = `1 0 00011100 0` в момент байта в SIO A; звук — принудительное `AY_CHS` = `A5C3` / `4F81` выходит из `sp_i2s_rx` в обоих каналах. `run_board.sh verilator 256 6000` (~20 с прогона + сборка): **все 256 КБ через мост** с темпом МК (65,5 мс модели) — 0 неверных байт, старт и выпуск ACEX те же; клавиатура с **настоящим** таймингом (бит 80 мкс, пауза 1 мс): нажатие и отпускание A (`1C`, `F0 1C`) — каждый кадр в сдвиговом регистре KBD, `KB_OFF` ACEX ставится кадром `F0` (через 424 мкс после его конца) и снимается следующим, три байта в SIO A — **0 ошибок**; 94 строки по 896 точек, 2052 выходные строки с `DE` 720.
- `src/sim/board/tb_ms.v` (iverilog, секунды; масштаб: такт строки ACEX — каждые 16 тактов, бит — 13 строк): `sp_ms_tx` → `sp_mouse` ACEX — суммы X / Y и кнопки совпали (в т. ч. шаг больше 127 — два пакета), байты SIO B — по 3 на пакет.

## 9. Первая проверка на плате (что смотреть)

Не проверено на плате ничего. Порядок:

1. Положить `sprinter.kg` на SD-карту (ядро `Sprinter Sp2000`, Mini G; прошивку МК не трогать), выбрать в меню загрузки. МК грузит 256 КБ ROM (~65 мс + накладные), затем сброс отпускается.
2. **~0,5 с чёрный кадр с синхро** (ACEX пуст, BIOS заливает конфигурацию) — HDMI должен поймать 720 × 576 сразу (≈ 50 Гц, 28 МГц, 896 × 624). Нет сигнала — смотреть `kg_hdmi_ft` / окно; совсем ничего — ядро не стартовало (журнал МК: загрузка ROM, `BUSY`).
3. Затем **экран SETUP BIOS 3.04** (в симуляции до него не дошли: > 320 мс работы BIOS после старта; первая запись в видео-ОЗУ ~200 мс). Смотреть: картинка целиком в окне (если сдвинута / обрезана — `H0` / `V0` в `sp_vout`, снимок с захвата), **цвета** (R / B перепутаны → порядок байтов палитры, `docs/ahdl.md` вопрос 8), ровные ли строки (нет дрожания — значит, начало строки в удвоителе стабильно).
4. Клавиатура USB: стрелки / Enter в SETUP (путь SIO A), выход из SETUP; F12 — турбо (индикатор / скорость), Ctrl+Alt+Del — мягкий сброс (без чёрных 0,5 с), Menu+F12 (OSD Reset) — полный сброс с чёрными 0,5 с.
5. Звук: щелчки / звук AY в BIOS (если есть) через ЦАП и HDMI; при `DVI_ONLY` звука по HDMI нет.
6. Мышь: в SETUP не нужна; в DSS (Ф2, нужен IDE) — потом.
7. Если «зависает» после чёрного кадра: в OSD журнале МК проверить, что ROM загружен (вид 0, 262 144 байт); при неполной загрузке машина ждёт в сбросе (`rom_loaded`).

Не проверены и в симуляции: весь путь `kg_mcu2` → `PS2_WR` / `LD_WR` (поведение по описанию `kg_l2_load` / `kg_l2_hid`), HDMI / OSD (модули как в core-p4096), окно `DE` по реальному кадру (тест — одна часть кадра со сдвинутым окном), полный поток конфигурации через плату (в машине проверен Verilator-ом, `docs/machine.md` 5).
