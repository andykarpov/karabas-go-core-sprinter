# Свои конфигурации ACEX в программах Sprinter: обзор

Обзор на 2026-11-21: какие программы загружают в ACEX **свой** битстрим вместо стандартного, чем он отличается от стандартного, что есть в эмуляторах и стоит ли делать для него «личность» в ядре. RTL не трогали, эмуляторы не запускали. Скрипты: `python3 -I` сканер сигнатуры с хешем MAME (scratchpad сессии, вне git).

**Итог.** Своя конфигурация ACEX для Sp2000 в собранных коллекциях найдена одна: **SCROLL / «Game Config»** Ивана Мака (2002, хеш `3861cfa4`). Её используют Thunder in the Deep, демо `GAME_00` и `LDCONF … gc.bin`. DOOM и Mortal Kombat — программы Sprinter-97 (FLEX10K). На Sp2000 они новый битстрим не грузят: функция BIOS `#F3` включает режим внутри стандартной прошивки. Torn Metal в коллекциях нет. Опубликован он только как игра для ZX Spectrum 128 (TR-DOS).

## 1. Как программа меняет конфигурацию

- **Механизм (Sp2000).** Программа копирует в КЭШ (fastram, страницы 0–3 через порт `5C`) только поток: из файла с `0x100` (`HL` = `4100h`) в КЭШ с `1000`. В `FEF0` она пишет строку `ACEX_30K_LOADING`, в `FEE0` — `FF` (одна перезагрузка). `RELOAD.ASZ` умеет писать туда `M` («не использовать»); загрузчик ROM проверяет `I`, `M` в `FEE0–FEE1` и тогда перезагружает поток при каждом сбросе. Адрес возврата пишется в страницу `41` (`FFF0–FFF5`, флаг `ZX` в `FFFE`). Затем полный сброс: порт `2E` открывается через страницу DCP `40` (`LD (4400h),2Eh`), и дальше идёт цикл `OUT`. Загрузчик в ROM находит строку, ставит CSBR = `F0` и гонит поток из КЭШ, затирая `FEF0` (если не было `IM`). Источники: `DEMOS/GAME_00/RELOAD.ASZ` (исходник Ивана Мака); `tt-sprinter-bios/bios/loader/loader.asm`; [sp2000.pdf, гл. 1–2](http://winglion.ru/sprinter/sp2000.pdf); [doc.sprinter.ru/introduction/loading](https://doc.sprinter.ru/introduction/loading).
- **Возврат к стандарту.** Кнопка RESET всегда даёт конфигурацию из ROM, потому что флаг затёрт. Программы выходят так: `SET_RETURN` → сброс без флага → стандартная конфигурация из ROM → BIOS возвращает управление программе (страница `41`) → `RST 10h #41` в DSS. SCROLL ставит в DCP `EE` = `2041` (MAME: `m_ram_pages[0x2e] = 0x41`): так BIOS возвращается в загрузившую программу.
- **BIOS 3.05+ (Tolik-Trek).** Загрузчик понимает и сжатый поток: нули упакованы как `00 n` (`Altera0pak`, `tt-scroll-cnf/bin/Altera0pak.c`). Признак — несовпадение 6 байт заголовка `FF FF 62 7B 39 00`. Функция `#F3 RST_CONF.CUSTOM` с `A` = `Config_PG.*` и `B` = блок памяти с битстримом заливает его сама (`bios/exp/FUNC_SERVICE.asm`; `B` = 0 — поток из ROM). Константы `Config_PG` лежат в пустом `Shared_Includes`. `TITD_T_T.EXE` вызывает `#F3` с `A` = `FE`, `B` = блок `#C3`, затем с `A` = `FB`, `DE` = адрес возврата. На выходе — `#F3` с `A` = `FE`, `B` = 0, то есть поток из ROM. Скорее всего, `FE` = «залить сейчас», `FB` = «задать возврат».
- **Программы Sp97 на Sp2000.** Программа кладёт в свою страницу `FLEX_10K_LOADING` (`C080`) и байт ID (`C090`) и вызывает `#F3` с `A` = номер этой страницы (`IN A,(E2h)`). Исходник BIOS 3.05+ («crutch: only for old FLEX10K soft compatible», `A` < `80` или страница в SLOT3) читает ID и включает режим: CBL при ID = `FF`, `ALL_MODE`, карту портов. Битстрим при этом не грузится. Так ли это в BIOS 3.04 (наш ROM по умолчанию), не проверяли. Sp2000 сводит Sprinter-1 / -2 / ZX+AY, а также Game-1 / DooM / Video в прошивку с переключением через системный порт (sp2000.pdf, гл. 2.7).
- **Сигнатура потока ACEX 1K.** `FF FF 62 7B dd 00 FF FF …`: `dd` = `39` у EP1K30, `3C` у EP1K50 (у K50 в 3.06 поток сжатый: `… 3C 00 01 FF`), `25` у FLEX EPF10K10 (Sp97, 14 751 байт). Поиск по этой сигнатуре находит и константу заголовка внутри загрузчика: ROM `0x300d8` / `0x300db`, `LDCONF.EXE` `0x8fe`. Это не потоки, ниже они исключены.

Прочие находки сигнатуры — не конфигурации программ, назначение не выясняли: второй поток EP1K30 в ROM `0x10100` (`d094326f`) у сборок BIOS 2001–2002 (winglion `_bin/0001–0007`, `BIOS/2001*`); `SP2000/SP2000_T.BIN` (`00ff030c`, = `sp2_1k30.pof`); `.pof` отдельных модулей (`acceler.pof`, `video.pof` …) в winglion `SP2000/`.

Второй поиск — по строкам `ACEX_30K_LOADING` / `FLEX_10K_LOADING`: он находит программы, где поток сжат. Найдены только семейства TITD / `GAME_00` (с `TEST_005`, `TEST_010`) / `LDCONF`, Sp97 MORTAL / DOOM / `2DSTUDIO/OLD/WORK.TRD`, BIOS и тексты документации. ZXMAK2 `sp_disk1.vhd`: те же TITD, MORTAL, DOOM. Ограничения: ARJ проверен (через 7z), LZH и сжатые EXE — нет.

Где искали без находок (сигнатура, вложенные zip / 7z / rar / arj): `SPRINTER_v2.7z` (1004 файла), `SPRINTER.7z` (814; то же дерево, что `SPRINTER_archive.zip` — его не сканировали), spdx `system.zip` / `media.zip`, `karabas-sd-sprinter/{games,demos,os,utils,hdd}`, `mame306/IMG/sp_hdd_sys.img` (находит те же файлы TITD / LDCONF / GAME_00), ZXMAK2 `sp_disk1.vhd`, `upstream/sprinter-apps`, `sprinter-dos`, `sprinter-hard`, DOOM с app.sprinter.ru (`doom.zip`, ниже).

**Расхождение хеша k30.** В `docs/roms.md` для 3.05 / 3.06 EP1K30 записано `383a0f9f`, для EP1K50 — `8cd33f23` (коммит `e6c98a9`, способ расчёта не записан). Наш расчёт: `5aa954b6` и `e9dcc183`. Пробовали поток как есть и после распаковки, смещения `0x2ff00–0x30300`, фазу `n mod 4` и направление поворота: `383a0f9f` не получается ни в одном варианте. Тот же алгоритм даёт все остальные хеши таблицы. Проверить на стенде: `run_machine.sh` с ROM 3.06 и `CFG_BITS` 4096 печатает хеш приёмника. `roms.md` не правили.

**Слабость хеша MAME.** Он покрывает 512 байт, в основном `FF`. Разные сборки одной схемы дают разные хеши (k30: `5aa954b6`, `ae54ab61`, `49861031`, `fffc0208`), а разные схемы могут совпасть (2.16 = 2.17). Для ядра правило такое: личность включает только точное совпадение со списком особых потоков, всё прочее — стандартная. Хеш по всему потоку надёжнее: unreal-ng считает FNV-1a, у Game `C0FA3055`, плюс хеш MAME для совместимости.
