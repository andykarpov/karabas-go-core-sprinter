# Накопители Sprinter: IDE и ВГ93 на образах с SD (Ф2)

Жёсткие диски (IDE) и дисковод (ВГ93 = WD1793) работают на файлах-образах с SD через файловый монтировщик МК (`kg_mcu2` `ENABLE_IMG`, `kg_l2_img`). Код — `src/rtl/board/sp_storage.v` (контроллеры, мультиплексор слотов, данные периферии на `MD`), `src/rtl/fdd/sp_fdd.v` (ВГ93 + системный регистр `#FF`), `src/rtl/fdd/wd1793.v` (ВГ93). `sp_machine` отдаёт наружу стробы MAX и шину `MD` и принимает `PER_D` / `PER_OE` (`docs/machine.md`).

## 1. Что взято и откуда

| Узел | Источник | Изменения |
|---|---|---|
| IDE-устройство на образе | `modules/rtl/mcu/hdf_ata.v` (как в core-p4096 / core-profi / core-baseconf), `ENABLE_RDB(0)` | нет (модуль не трогали) |
| ВГ93 | `wd1793.v` MiSTer (sorgelig, GPL), sv2v; копия core-p4096 `src/rtl/fdd/wd1793.v` (= orionpro bfdf401, с Write Track из orion128), шапка с лицензией — как в core-specialist | под 1,44 МБ: адреса байт образа 21 бит вместо 20 (`img_size`, `buff_a`, `disk_size`, `hs`, `scan_addr`, `edsk_offset`, `input_addr`, `buff_addr`, `sd_lba`), `size_code` 5 = 18 секторов по 512; пометки `karabas:` |
| обвязка ВГ93 (системный регистр, приводы, мост `sd_*` ↔ `sdc_*`) | core-p4096 `p4096_fdd.v` | 2 привода (D0), геометрия по размеру образа, проверка плотности (п. 4), стробы MAX вместо дешифрации порта ЦПУ |
| мультиплексор слотов `sdc_*` (владелец по `SDC_SLOT`, младший слот первым) | верх core-p4096 | слоты 0–1 и 4–5 |

Вариант ВГ93 по выводам (`vg93_*` / `hrdy_fdc`, как в core-tsconf / profi / baseconf) не подходит: он работает только с физическим дисководом (поток MFM), образов не умеет. Сепаратор данных MAX (`FDAT` / `QDAT` / `WDAT`) не переведён: модель регистровая.

## 2. Путь порта

Цикл ввода-вывода: дескриптор порта из таблицы в DRAM (страница 0x40) → код в `MEM` DCP → управляющее слово на `MA` в фазах 5–6 → защёлка на плате (`WR_AWG`) → MAX: стробы `XHD_RD` / `XHD_WR` (IDE), `WG_RD_N` / `WG_WR_N` / `WR_PDOS` (ВГ93), `CMOS_*`; номер регистра IDE — `HD_A` = `MA[11:9]`, выбор CS — `XHD1_CS` / `XHD2_CS` из MAX (`docs/ahdl.md` 4.2, `docs/mame.md`).

- **Номер регистра ВГ93** — `MA[1:0]` = `A6..A5` порта. Защёлка платы (`DD11` / `DD16`) их не берёт (откуда ВГ93 берёт A0 / A1 на плате — по схеме не прослежено), у нас `sp_machine` защёлкивает `MA[14:0]` целиком, выход `WG_A`.
- **#FF (чтение)** — не строб MAX: код 15 (`701F`), тип 7, `MA2` = 1 — внешний мультиплексор КП11 по `RD_KMPS` ACEX (`INTRQ`, `DRQ`). `sp_machine` выводит `RD_KMPS`; `sp_storage` отвечает при `RD_KMPS` = 0, `HDD_C` = 0, `FDD_C0` = 1 и бите строба `FDD_C2` = 1 (`MA4`: у слова `701F` он есть, у слова покоя между циклами и у портов типа 7 без устройства — ISA `7000–7003` — нет).
- **Байтовые полосы.** IDE — слово на `MD[15:0]` (младший байт ЦПУ сразу, старший — в `HDDR` ACEX: `INI` с `B` = 00 читает слово, с `B` = FF — защёлку без строба IDE; запись наоборот — `OUTI` кладёт младший в защёлку, старший пишет слово). Регистры IDE — `MD[7:0]`. Порты типа 7 (ВГ93, `#FF`, CMOS) ACEX читает с `MD[15:8]`; `sp_storage` кладёт байт на обе половины.
- **Удержание.** Данные чтения стоят на `MD` (`PER_OE`) от начала строба до конца цикла `/IORQ`: ACEX берёт байт по подъёму `/IOMM` (`MDP`) и старший байт IDE по концу `/RD` (`HDDR`). Чтение канала / устройства / порта, за которым ничего нет, даёт **00** — не то, что держит «ёмкость» шины (иначе проверка привода BIOS `TEST_HDD_DRV` — запись регистра и чтение назад — нашла бы несуществующий диск).
- **Такты.** `sp_storage` на двух тактах: стробы, номер регистра и данные записи — регистры `clk_sys` (84 МГц), замороженные от начала строба до 12 тактов после конца; `hdf_ata`, `sp_fdd` и сторона `sdc_*` МК — на `clk_bus` (28 МГц = 84 / 3, одна PLL, фронты совпадают). Для `hdf_ata` шина IDE ещё раз берётся регистрами `clk_bus` (его логика видит только регистры своего такта), выходы контроллеров регистрируются на `clk_bus`, в `PER_D` — регистр `clk_sys`. Переходы `clk_sys` → `clk_bus` и обратно — регистр → регистр (бюджет 11,9 нс, PAR их анализирует как связанные такты) — первое, что смотреть в отчёте PAR.
- **`/WAIT` нет**: MAX не использует `XHR_RDY` (`docs/ahdl.md` 6.15), тайминг IDE держит таблица ожиданий ACEX; `hdf_ata` IORDY не нужен (сектор в буфере до `DRQ`).

Замеры (`tb_storage +timing`, тестовая программа; сняты до второго регистра `clk_bus` на шине `hdf_ata`, длины стробов от него не зависят):

| | Строб | Когда ACEX берёт байт |
|---|---|---|
| IDE (`XHD_RD` / `XHD_WR`) | 274 нс | — (данные IDE читаются верно, в т. ч. `HDDR`) |
| ВГ93 (`WG_RD_N` / `WG_WR_N`) | 417 нс | `mdp_ev` через ~310 нс после спада строба |
| `#FF` (`RD_KMPS`) | 643 нс | |

Данные контроллера появляются на `MD` через ~110 нс (ВГ93) / ~150 нс (IDE) после спада строба (регистры номера в `clk_sys` и `clk_bus`, регистр данных в `clk_bus`, `PER_D`) — запас 150–200 нс до `MDP`.

## 3. IDE

- **Каналы.** MAX выбирает канал кодами 2A / 2B (`#01BC` / `#21BC`, «Set HDD1» / «Set HDD2», `SHDD1` / `SHDD2`): HDD1 → `XHD1_CS`, HDD2 → `XHD2_CS`. После сброса MAX не выбран **ни один** (`NO_HDD`). BIOS 3.04 сам выбирает HDD2: в ROM `3E 21 D3 BC` (`LD A,#21 : OUT (#BC),A`) по адресам 0x2284, 0x20406, 0x208E6 (последний — `#01BC` или `#21BC` по условию); в симуляции — на 172,1 мс. MAME называет 2B (`m_ata[0]`) первичным. У нас: **первичный канал = HDD2 = `hdf_ata`** (master = слот 4, slave = слот 5); вторичный (HDD1) — без устройств, все регистры 00.
- **Устройство без образа** — `hdf_ata` даёт 00 во всех регистрах (нет устройства).
- **Геометрия** — `hdf_ata` без RDB: 16 головок, 63 сектора, цилиндры по размеру; CHS и LBA28. Образ ZXMAK2 `sp_disk1.vhd` (fixed VHD 2 ГиБ + 512 Б футер) монтируется как есть: футер — лишний последний сектор. Сброс IDE (`ata_reset`) — `XHD_RES` MAX (низкий до первого кадра) или `/RESET` ЦПУ: сброс посреди передачи не оставляет устройство в `DRQ` к следующему старту (как `machine_reset` в core-p4096).
- Команды — как у `hdf_ata`: IDENTIFY, READ / WRITE SECTORS / MULTIPLE, READ VERIFY, INITIALIZE DEVICE PARAMETERS, SET MULTIPLE, FORMAT TRACK, неисполнительные команды без действия.

## 4. ВГ93 и системный регистр

- Порты (DOS, таблица портов BIOS): команда / состояние `#0F` (и `#1F`), дорожка `#3F`, сектор `#5F`, данные `#7F` (коды 10–13), системный регистр `#FF` (запись — код 14 `WR_PDOS`, чтение — 15), 720 / 1440 — `#01BD` / `#21BD` (коды 16 / 17, флаг `FDD_1440` = `10K_D0` MAX).
- **`#1F` занят Z84C15**: внутренний PIO B (управление) на 1C–1F, внутреннее чтение побеждает (`sp_z84c15`). Поэтому FDRIVER2 BIOS берёт команду / состояние с `#0F`. TR-DOS с `IN (#1F)` получит `FF` от PIO — так же, видимо, и на плате (не проверено).
- Системный регистр `#FF`, запись: D0 — привод A / B (D1 не используется: два привода), D2 — `/MR` (0 = ВГ93 в сбросе), D3 — HLT (не используется), D4 — сторона (0 = сторона 1), D6 — плотность (не используется: её задаёт образ). Чтение: D7 `INTRQ`, D6 `DRQ`, остальные 1. Сброс — линия `/RESET` ЦПУ.
- **Образы, геометрия по размеру**: 1 474 560 — PC 1,44 МБ (80 × 2 × 18 × 512, `size_code` 5); 737 280 — PC 720 КБ (80 × 2 × 9 × 512, `size_code` 2); остальное — TRD (16 × 256, `size_code` 1). Порядок — дорожка × 2 + сторона, секторы с 1. Запись в образ есть (`RWMODE`), защита записи — `IMG_WP` МК.
- **Плотность.** MAX даёт ВГ93 1 МГц (720 КБ) или 2 МГц (1,44 МБ). Привод на чужой частоте не видит адресных меток, и BIOS определяет плотность именно так (`DISK_ID` FDRIVER2: Read Address с тайм-аутом ~140 мс, затем другая частота, до 4 попыток). Модель: для PC-образа чужой плотности `INTRQ` / `DRQ` команд типа II / III (чтение / запись сектора, Read Address, дорожка) до ЦПУ не доходят (команда «висит»); тип I (восстановление, поиск, шаг) и IV работают на любой частоте. TRD читается на любой частоте (какую ставит TR-DOS Sprinter — не проверяли).
- Сектор идёт к МК напрямую, без кэша (5–15 мс — как у настоящего дисковода).

## 5. OSD и форматы (`src/core.json`)

| Пункт | Слот | Расширения |
|---|---|---|
| Disk A (Menu+F5) | 0 | `.img .ima .trd` |
| Disk B (Menu+F6) | 1 | `.img .ima .trd` |
| HDD Master | 4 | `.vhd .img .hdf` |
| HDD Slave | 5 | `.vhd .img .hdf` |

Индексы переключателей не менялись (Reset — `"index": 0`, новые пункты — файлы и разделитель в конце списка).

Форматы: дискеты — сырые PC `.img` / `.ima` 720 КБ и 1,44 МБ (FAT12, DSS), `.trd`. **SCL не поддерживается** (`wd1793` его не знает; нужен конвертер в TRD — в прошивке МК или отдельный модуль), FDI / UDI тоже. HDD — сырой диск (MBR + FAT16) в `.img` / `.hdf` или fixed `.vhd`.

## 6. CMOS (точка подключения)

`sp_storage` уже кладёт на `MD` байт чтения CMOS: вход `CMOS_Q[7:0]` при `CMOS_DRD` = 0 (пока в верхе `8'h00` — CMOS читается как 00). Для `sp_cmos` (`docs/rtc.md`): стробы `m_cmos_dwr`, `m_cmos_as` (активный 1), `m_cmos_drd` (выходы `sp_machine` в верхе), адрес / байт записи — `m_md[15:8]`, байт чтения — в `CMOS_Q` (на домене `clk_sys`; `PER_D` берёт его каждый такт, пока строб низкий).

## 7. Тесты

`src/sim/storage/run_storage.sh [verilator|iverilog]` (`tb_storage.v`, `storage.asm`): `sp_machine` с BIOS 3.04 (его загрузчик льёт короткий поток, `CFG_BITS` 256), в странице ROM 8 — тестовая программа вместо BIOS; `sp_storage` и модель стороны `sdc_*` `kg_l2_img` (один запрос, младший слот первым, сектор берётся с запросом; образы — шаблон или файлы `+img0=` / `+img4=`). Программа сама заполняет таблицу портов (страница 0x40 в окне 3, пока `STARTING` = 0) и пишет результаты в порты `#01` / `#02`; стенд их проверяет.

Проверяется (0 ошибок, Verilator: сборка + 36 мс модели ≈ 8 с; `+trd` — 33 мс модели, 5 с):

- IDE: выбор HDD2 (`OUT (#21BC)`), состояние master 50, запись / чтение назад счётчика (`TEST_HDD_DRV`), READ SECTORS LBA 0 цепочкой `INI` с `BC` = `#0050` — 512 байт = образ (510 / 511 = 55 AA); WRITE SECTORS LBA 1 цепочкой `OUTI` (`BC` = `#0150`) — в образ легли верные 512 байт, READ SECTORS LBA 1 их вернул; slave без образа и вторичный канал — 00.
- ВГ93: привод A (1,44 МБ, `OUT (#21BD)`) — поиск дорожки 79, сторона 1, сектор 18 (LBA 2879, за 1 МБ образа: проверка 21-битной адресации); привод B (720 КБ, `OUT (#01BD)`) — дорожка 79, сторона 1, сектор 9 (LBA 1439); `+trd` — привод B TRD, 256 байт сектора 9 дорожки 79 стороны 1; привод A на частоте 720 КБ: Read Address без `INTRQ` / `DRQ` (тайм-аут), на 1,44 МБ — ID `C` 79, `N` 2.
- `+timing` — замеры п. 2, `+io=<маркер>` / `+iot=<мс>` — журнал циклов ввода-вывода, `+dbg=<нс>` — шина по тактам.

BIOS 3.04 как есть: `ARGS="+bios +cmos +pc +img4=…/sp_disk1.vhd +img0=…/dss_1_62_92.img" STOP_MS=600 ./run_storage.sh` (Verilator, 600 мс модели — 2 мин 20 с, ≈ 4,3 мс модели / с). `+cmos` — модель DS12887 в стенде с `src/roms/cmos_default.bin` (подмены C / D / UIP как в `sp_cmos`); без неё CMOS читается как 00 (так в верхе, пока `sp_cmos` не подключён). Ход: на 172,1 мс BIOS восстанавливает ВГ93 (команда 00, `#FF` = 3C) и выбирает HDD2; до ~330 мс рисует заставку (цикл `0BC2–0BFA`), дальше работает из ОЗУ (`C000`, `8000`, `D0xx`); **первое обращение к CMOS — 565,7 мс** (запись / чтение `#3F`, затем `#0E…#1F` с проверкой суммы; 171 чтение, 114 записей к 600 мс); **до 600 мс обращений к IDE нет** — с моделью CMOS и без неё одинаково (CMOS до 565 мс не читается). Обнаружение IDE — после чтения настроек CMOS (`#11` — настройки HDD, в `cmos_default.bin` = 00: что это значит для 3.04 — автоопределение или «нет диска» — не проверено). Следующий шаг — прогон 1–1,5 с модели (≈ 4–6 мин) только с согласия пользователя, или точка останова по PC.

Регрессия: `src/sim/machine/run_machine.sh iverilog 256 100` — 0 ошибок (9 с).

Ресурсы (XST, Mini G, весь проект): LUT 7891 → 10 259 (68 %), регистры 4755 → 5932, блоки ОЗУ 13; `sp_storage` отдельно — ~2050 LUT, 780 регистров, RAMB16 + RAMB8 (буферы секторов `hdf_ata` и `wd1793`). PAR не запускали.

## 8. Проверка на плате

1. SETUP BIOS 3.04 видит IDE master (образ `sp_disk1.vhd` в HDD Master): тип / ёмкость в списке дисков. Зависит от CMOS: пока `sp_cmos` не подключён, CMOS читается как 00 (сумма неверна — BIOS пишет значения по умолчанию, но записи пропадают).
2. DSS 1.62 грузится с `sp_disk1.vhd` («Starting…», командная строка / `fn`), каталоги читаются, запись файла сохраняется после перезапуска.
3. Дискета 1,44 МБ `dss_1_62_92.img` в Disk A грузится (BIOS сам находит 1,44 через `#21BD`); 720 КБ определяется как DD.
4. `.trd` в Disk A / B из режима ZX (TR-DOS) — каталог; при неудаче — проверить, какую частоту (720 / 1440) ставит TR-DOS и `#1F` против PIO Z84C15.
5. Slave (HDD Slave) и смена образа на лету; защита записи образа.

## 9. Открытые вопросы

- Где BIOS 3.04 ищет IDE (> 600 мс модели, после чтения CMOS на 565,7 мс) — прогон не досчитан; значение `#11` CMOS (00) для 3.04.
- Откуда ВГ93 платы берёт A0 / A1 (у нас — `MA[1:0]` управляющего слова).
- TR-DOS: `#1F` против PIO Z84C15; какую частоту ставит; SCL — конвертер.
- Вторичный канал (HDD1) пуст; второй `hdf_ata` — ещё порядка 1000 LUT (оценка, не синтезировали).
- Кэш образов дискет в SDRAM (как `orion_fdd_cache`) — для скорости, позже.
- Сепаратор данных MAX и физический дисковод (Go) — Ф3.
