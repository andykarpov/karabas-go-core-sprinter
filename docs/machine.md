# Машина Sprinter без платы: `sp_machine` (Ф1.3)

`src/rtl/top/sp_machine.v` — машина целиком, без привязки к плате: ЦПУ, ACEX, MAX, контроллеры памяти, защёлки и мультиплексор платы, путь загрузки конфигурации ACEX и сброс «как переконфигурация». PLL, выводы, связь с МК, HDMI, загрузчик ROM — в верхнем модуле платы (Ф1.4, `docs/minig.md`).

## 1. Состав

| Узел | Модуль | Примечание |
|---|---|---|
| Z84C15 | `sp_z84c15` (T80pa + SIO / CTC0 / PIO / SCRP) | такт `CLKZ1` + `CLKZ1_NX` (меняется только по `CE_N`, см. п. 2); `TRG0` = `AUD` (CT3) MAX, как на схеме (CLK/TRG0-2) |
| ACEX 3.03a / k30 / SCROLL | `sp_acex` | `CFG_RST` / `CFG_DONE` (п. 4), `PERS_K30`, `PERS_SCROLL` (п. 3) |
| MAX | `sp_max` | `/RESET` → `CONF_X_N` (в `sp_machine` через регистр, Ф1.4: путь для PAR), `CLKZZ`, `10K_CLK` / `10K_D0`; вход `RESET_N_I` ACEX = 1 (линию `/RESET` ведёт только ACEX, сброс MAX его стирает: `CFG_RST`) |
| видео-ОЗУ, ROM, fastram, тень палитры | `sp_sram` | порт загрузчика ROM (`LD_*`) — наружу, к верху платы |
| DRAM | `sp_sdram` | |
| защёлки на `MA` (DD11, DD16 и третья для `HDD_C0` / `FDD_C`) | в `sp_machine` | по подъёму `WR_AWG` берут `MA[14..2]` и `XA[2..0]`; сброс — линия `/RESET` ЦПУ. Выходы: `HDD_C`, `FDD_C` (к MAX), `HD_A`, INT (`MA13`), NMI (`MA12`), `!TURBO` (`MA14`), `TAPE_OUT` (`XA2`) |
| мультиплексор `XA` | в `sp_machine` | `SXA` = 0: `KBD_CC`, `KBD_DD`, `TAPE_IN`, `MOUSE_D` (XA3); 1: `FDD_W`, `FDD_CH`, `SINC_1`, `SINC_2` (от MAX); ведёт `XA`, пока `RDXA` = 0 |
| шины `D`, `MD`, `XA` | в `sp_machine` | без ведущего линия держит последнее значение (так рассчитан ACEX, см. шапку `sp_acex.v`) |

`CE` / `CE_N` делает сам `sp_machine` (после включения первым идёт `CE`).

Накопители (IDE, ВГ93 на образах) — снаружи, `sp_storage` в верхе платы (`docs/storage.md`): `sp_machine` отдаёт стробы MAX, `HD_A`, `WG_A` (`MA[1:0]` управляющего слова — защёлка берёт `MA[14:0]`), `RD_KMPS`, `IORQ_N`, `CPU_RES_N` и принимает данные периферии на `MD` (`PER_D`, `PER_OE`). Заглушки с пометкой TODO (порты): сепаратор ВГ93 (`FDD_W`, `FDD_CH`), DS12887 (`CMOS_*`), клавиатура и мышь (линии PS/2 и MS в мультиплексор, потоки SIO A / B), видеовыход (`WR_COL`, `PAL_Q`, `VA`, `SINC_H` / `SINC_V`, `T320`), звук — I2S ACEX (`DAC_*`).

## 2. Режим без конфигурации (ACEX пуст)

По схеме (`~/Downloads/Sprinter_2016s.pdf`, лист 1 и 3):

- `CS0` / `CS1` Z84C15 через R176 / R177 → `CS_ROM` / `CS_CASH`; ACEX, когда работает, их перебивает.
- `RA14` / `RA15` = `A14` / `A15` через R84 / R85; `RA16`, `RA17`, `ROM_W` — подтяжки к VCC (R87, R121). Значит, ROM видна с `0x30000 + A[15:0]` (страницы 0x0C–0x0F, загрузчик и битстрим), fastram — по `A[15:0]` (её второй выбор — `RA16` = 1).
- `WR_CNF` = `!(/WR | /MREQ)` (DD2.4): **каждая** запись ЦПУ в память — такт конфигурации; MAX: `10K_CLK` = `WR_CNF` (пока `CNF_OFF`), `10K_D0` = `D0` по его фронту.
- Такт ЦПУ: `CLKZZ` MAX (= `XCT1`, 14 МГц) через R43 на цепь `CLK_Z80`; работающий ACEX её перебивает.
- `/WAIT`, `/INT`, `/NMI`, `D0..D7`, `/RESET` — подтяжки; `WR_AWG` — R73 к VCC (защёлки не пишутся).
- `/RESET` ЦПУ ведёт только ACEX (вывод 19 `I/O/INIT_DONE`). MAX `/RESET` идёт лишь на `NCONF_X` (через VD11 на nCONFIG). Защёлка DD11 сбрасывается линией `/RESET` ЦПУ.

У нас, пока ACEX не отпущен (`sp_machine`):

- ЦПУ на `CLKZZ`. Фронты `XCT1` приходятся то на `CE`, то на `CE_N`; `sp_z84c15` ждёт такт, меняющийся по `CE_N` (выводы — регистр по `CE`). Поэтому `CLKZ1` = `CLKZZ`, перезахваченный по `CE_N`, `CLKZ1_NX` = сам `CLKZZ`. Фронт по `CE` уезжает на полтакта 84 МГц: высокий уровень 2 такта `CLK`, низкий 4 — частота та же (измерено: 14,001 МГц), полупериод не короче, чем у 21 МГц.
- Память — по `CS0` / `CS1` (адресные выходы `sp_z84c15`) и `/MREQ` без регенерации: `sp_sram` получает `RA` = {`CS1` ? `01` : `11`, `A15`, `A14`}, `SEL_ROM` = `CS0`, `SEL_CASH` = `CS1`, `CS_CASH` = !(`CS1` & `/MREQ`) — запись в fastram идёт через её буфер записи (он требует `RA[17:16]` = `01`).
- `sp_sram` и `sp_sdram` шагают по фазам `CT` ACEX; пока ACEX в сбросе, у них свой счётчик фаз (5 6 0 1 2 4 по `CE`), видеозапросы погашены. `sp_sdram` в это время сам делает регенерацию (`RAS_` высокий, свой счётчик) — DRAM не теряет содержимое (в оригинале её не регенерирует никто).
- `/WAIT`: в оригинале нет; у нас `CPU_WAIT_N` из `sp_sram` (байт ROM / fastram опоздал бы) — то же, что в рабочем режиме, где он идёт по И с `/WAIT` ACEX. Страховка.
- `/INT`, `/NMI` — из защёлки `MA` (сброшена), т. е. неактивны.

**Сброс ЦПУ — отличие от оригинала.** Оригинал при сбросе MAX ЦПУ не сбрасывает: ACEX стирается, его выводы отпускаются, ЦПУ продолжает с того адреса, где был, но уже в странице загрузчика; страница забита `FF` (`RST 38` → `JP 0` по адресам 0x38 и 0x66), и он сам приходит в 0. У нас MAX `/RESET` — ещё и `/RESET` ЦПУ (как в MAME: `schedule_soft_reset`). Это же снимает защёлку `MA`: иначе слово порта 2E (1011/000) осталось бы в DD11 и держало бы `SOFT_RESET` MAX (в оригинале DD11 сбрасывает только `/RESET` от ACEX — как оригинал выходит из 2E, по схеме не видно).

## 3. Поток конфигурации, хеш, «личность»

Загрузчик BIOS 3.04 (ROM `0x30000`, т. е. адрес 0 в режиме без конфигурации): `DI`; Z84C15 (SCRP / SCDP): регистр 0 (WCR) = 04, MCR = 3 (CS0 + CS1), CSBR = FE (0000–EFFF — CS0, F000–FFFF — CS1); SIO / PIO; если в fastram с `FEF0` подпись конфигурации — CSBR = F0 и поток из fastram с `1000`, иначе из ROM с `0100` (`0x30100`); флаг «IM» в `FEE0` — писать в `FD00` вместо `FE00`. Цикл на байт: `LD A,(HL)`, 8 × `LD (DE),A` + 7 × `RRCA` (бит 0 — `D0`), `INC E`, `INC HL`, `JR` = **113 тактов на байт**, бесконечно (ACEX сам перестаёт слушать). Записи идут в `FE00..FEFF` (CS1 = fastram).

Приёмник в `sp_machine`, пока MAX в режиме загрузки (`CNF_OFF`):

- на каждый подъём `10K_CLK` — бит `10K_D0` (младшим вперёд), счёт тактов и байт;
- **хеш MAME** (`sprinter.cpp`, `bootstrap_w`): сумма по первым 4096 записям в память после сброса, байт `n` (вся шина данных, не только `D0`) сдвинут на `8 × (n mod 4)`, по модулю 2³². Загрузчик пишет каждый байт битстрима 8 раз с поворотом, поэтому хеш зависит только от первых 512 байт битстрима. Проверено на файлах (`python3`, тот же алгоритм с `RRCA`): `SCROLL.ACX` (`upstream/tt-scroll-cnf`) = **`3861cfa4`** — константа MAME;
- конец потока — `CFG_BITS` + `CFG_INIT` тактов (параметры; 59 215 × 8 = 473 720 + 10 тактов инициализации ACEX 1K).

Загрузчик BIOS 3.05 / 3.06 понимает и сжатый поток (нули — `00 n`, признак — несовпадение заголовка `FF FF 62 7B 39 00`); хешируются записанные байты, т. е. поток после распаковки. Цикл длиннее: 11,4 мкс на байт (3.06 в `run_machine.sh`), полный поток ≈ 0,68 с.

**Таблица личностей** (`sp_machine`, хеш MAME; битстрим из ROM `0x30100`, `upstream/sprinter-bios/ALTERA`, `LDCONF`; `docs/configs.md` §2). Хеш покрывает только первые 512 байт потока (почти все `FF`): разные сборки одной схемы различаются, разные схемы могут совпасть (2.16 = 2.17). Поэтому в таблице каждая известная сборка, а личность включает только точное совпадение:

**Регистр личности.** `CFG_PERS` ставится по таблице, когда пришёл последний бит потока (`bits` = `CFG_BITS`: хеш полный, `CSBR` — ещё загрузчика), и держится до следующего потока. От стирания до отпускания (`CFG_INIT` тактов, перезагрузки ОЗУ — позже) `sp_acex` в `CFG_RST`, поэтому смена посреди работы невозможна. До 2026-11-21 личность ставилась в момент отпускания; теперь раньше, потому что DCP пишет `MEM[EE]` по `PERS_SCROLL` (п. 4), пока держится `CFG_RST`. `CFG_PERS` = 1 → `sp_acex.PERS_K30` = 1, 2 → `PERS_SCROLL` = 1 (те же входы у `sp_dcp`, `sp_video2`; `docs/versions.md`). `CFG_UNKNOWN` = хеша нет в таблице → сообщение в OSD, работает 3.03a.

**Условие `CSBR[3:0]` = 0 для SCROLL.** Загрузчик ROM (3.04 `0x30000`, 3.06 `tt-sprinter-bios/bios/loader/loader.asm`) ставит `CSBR` = `F0`, только если в `FEF0` fastram подпись `ACEX_30K_LOADING`, и тогда берёт поток из fastram с `1000`; поток из ROM идёт при `FE`. Thunder in the Deep кладёт поток в fastram сам (`TITD0`, `RELOAD.ASZ`) или через BIOS 3.05+ `#F3` с блоком памяти (`TITD_T_T`): `RST_CONF.CUSTOM` → `.INIT_ACEX` / `.PrepareHardReset` копирует страницы блока в КЭШ с `1000` (`.INIT_ACEX.PROGRAM.LOAD`, страница за страницей через окно 1) и пишет подпись (`ACEX.LOADER.String_Address`, `.INIT_ACEX.Reload_String`), затем `REINIT` (полный сброс); поток опять читает загрузчик ROM с `CSBR` = `F0`. Значит, условие выполняется во всех найденных путях. Стандартные потоки с хешем `3861cfa4` не встречаются (`docs/configs.md` §2), так что хватило бы и одного хеша; условие оставлено, как в MAME. Проверено: `tb_machine +scroll` с BIOS 3.04 и 3.06 (п. 5).

**`CFG_FNV`** — FNV-1a 32 по шине данных всех `CFG_BITS` записей потока (8 на байт, с поворотом), как unreal-ng: у SCROLL `c0fa3055` (проверено на файле). Только для журнала / OSD, выбор — по таблице. Логика: исключающее ИЛИ, затем умножение на `01000193` сдвигами и сложениями за два такта после записи (записи идут через ~100 тактов). С `CFG_BITS` 4096 (короткий прогон стенда) хеш другой: 3.04 — `fbec473a`, 3.06 — `35b7959e`; по всему потоку — `fc0928f2`, `f9f42e59`.

Отпускание: сосчитан весь поток, `sp_acex` закончил перезагрузку ОЗУ (`CFG_DONE`), SDRAM готова, и следующий фронт — `CE` (как при включении). ACEX стартует в состоянии включения: его `SOFT_RES` три периода `CT4` держит `/RESET`, и ЦПУ начинает с 0 уже в рабочей карте (BIOS: страница ROM 8, «EXP»). Первый `XACS` ACEX (у микросхемы — импульс при включении: `XACS.prn` = `XACS or …`, регистр без начальной 1) переводит MAX в рабочий режим; в переводе `xacs_q` стартует с 1, поэтому импульс делает `sp_machine`: `XACS` = 0 на `CE` + `CE_N` в момент отпускания.

## 4. Сброс = переконфигурация (`CFG_RST`)

Что в оригинале стирает ACEX (MAX `/RESET` → nCONFIG): включение (`PW_GOOD` по первому кадровому синхроимпульсу), кнопка `RESET` (J2 → `EPM_RES`), порт 2E (управляющее слово 1011/000 → `SOFT_RESET` MAX). **Не** стирают (только `/RESET` ЦПУ от самого ACEX): Ctrl+Alt+Del (`KB_RESET`), запись в страницу Ax при `SC4` (`SOFT_RES`), `ALL_MODE5` = 0. `docs/mame.md` считал переконфигурацией любой сброс — по схеме это не так; и сам MAME при записи в страницу Ax (`ram_w`) делает мягкий сброс без `m_conf_loading`, т. е. без переконфигурации. Оговорка: не все метки `RESET/` листа 2 (ISA, IDE) прослежены.

`sp_acex.CFG_RST` (синхронный, любой длины) и тот же вход во всех подмодулях:

- каждый регистр — в значение при включении (список совпадает с объявлениями `reg … = v`; блок `if (CFG_RST)` последним в каждом `always`, на каждом `CLK`, без `CE`);
- ОЗУ, которые пишет логика или ЦПУ, перезагружаются через свой порт записи: DCP `MEM` 256 × 16, KBD 256 × 8, AY 256 × 8 — из копии MIF (ПЗУ), буфер строки ACCELER 256 × 8 и FIFO CBL 256 × 16 — нулями. 256 тактов, конвейер на 2; `CFG_DONE` = 1 после 260 тактов `CFG_RST`. После них DCP, пока держится `CFG_RST`, каждый такт переписывает `MEM[EE]`: `PERS_SCROLL` ? `2041` : слово ПЗУ (личность SCROLL, `docs/versions.md`; один MIF вместо второй копии).
- Цена: три ПЗУ-копии MIF (8 Кбит; можно сложить в один RAMB16) и счётчики.

`sp_machine` держит `CFG_RST` от MAX `/RESET` до конца потока и `CFG_DONE` (≈ 0,48 с, перезагрузка ОЗУ — внутри).

Вход используется только в `if (CFG_RST)`: в старых стендах он не подключён (Z) и читается как «нет».

**Проверка** — `src/sim/eq/run_cfg_rst.sh` (`tb_cfg_rst.v`, ~30 с): два `sp_acex`. «fresh» стоит в состоянии включения (его такт начинается в момент отпускания), «dut» сначала портится: случайные значения во все 343 регистра (1130 бит) и все слова пяти ОЗУ (список генерирует `cfg_regs.py` из исходников), 2500 тактов свободного хода с PS/2, мышью, SINC_1, ещё раз случайные значения, затем `CFG_RST` 300 тактов. Отпускаются оба в одном `CE`; ЦПУ (`sp_z84c15`) выполняет `cpu_acex.asm` (сценарии 0, 1, 2), модели и шины ведёт «fresh». Сравнение в каждом такте: все выходы (`EQ_CMP`) и **всё состояние** (343 регистра), ОЗУ — в момент отпускания и в конце. Итог: 0 расхождений во всех трёх сценариях (275 / 250 / 142 мкс), журнал программы совпал. Мутации (обязаны провалиться): `+mut=1` — испорчен `DECODE.pn_q` после сброса, `+mut=2` — слово ОЗУ AY; обе пойманы.

Остальные тесты после правки: `run_eq.sh` (все, 7,5 мин на загруженной машине), `run_eq.sh acexm` (3 мин 20 с), `run_cpu_acex.sh` (3 мин 33 с), `src/sim/cpu/run_cpu.sh` (21 с) — 0 ошибок.

## 5. Симуляция машины и скорость

`src/sim/machine/run_machine.sh [iverilog|verilator] [CFG_BITS] [RUN_US]` (`tb_machine.v`): BIOS 3.04 (`~/Downloads/karabas-sd-sprinter/roms/mame-named/sp2k-3.04.rom` = MAME `sp2k-3.04` = zxgit `sp2k-3.04.253.bin`, `docs/roms.md` 1.1; в репозитории только битстримы, полного образа нет) в модели SRAM, память — модели без задержек (тайминг `sp_sram` / `sp_sdram` проверяет `tb_eq_acexm`), один стенд для iverilog и Verilator. `XHD_RES_ON_HSYNC` = 1 (сброс включения — строка, а не кадр).

Сценарии (`ARGS`), стенд сам проверяет (`tb_machine: N errors`): старт с 0000 страницы ROM 8 в рабочей карте, хеш и личность (при `CFG_BITS` ≥ 4096), выход MAX из режима загрузки после отпускания (`CLKZZ_OE` = 0), переполнение буфера записи fastram. Все — 0 ошибок (Verilator, `CFG_BITS` 4096; `+reset` ещё и iverilog с 256):

- без аргументов — хеш `78eddfc6`, личность 0;
- `ROM=…/sp2k-3.06.rom`, `ARGS="+hash=5aa954b6 +pers=1"` — BIOS 3.06: хеш `5aa954b6`, личность 1 (k30), `PERS_K30` = 1, `CFG_FNV` `35b7959e` (4096 записей), BIOS с 0000 страницы 8; отпускание на 5,97 мс (поток 3.06 медленнее, 11,4 мкс на байт); Verilator 23 с;
- `+reset` — кнопка через 1 мс после отпускания: ACEX стёрт, второй поток, второй старт совпал с первым (хеш, первая выборка, первые 8 `OUT`);
- `+p2e` — слово порта 2E (1011/000) в защёлке `MA`: то же;
- `+scroll` — `SCROLL.ACX` в fastram с `1000` и подпись загрузчика `ACEX_30K_LOADING` в `FEF0` (строкой, не из ROM: у 3.06 она по другому адресу): загрузчик берёт поток из fastram (CSBR = F0), хеш **`3861cfa4`, личность 2**, `PERS_SCROLL` = 1, `MEM[EE]` DCP = `2041` (у остальных прогонов стенд проверяет `2000`); так же с BIOS 3.06 (`ROM=…/sp2k-3.06.rom`, отпускание на 6,02 мс, `CSBR` = `F0`); с `+reset` второй поток — из ROM (загрузчик затёр подпись): хеш `78eddfc6`, личность 0, `MEM[EE]` снова `2000`. Все 0 ошибок (2026-11-21: Verilator; `+scroll` с 3.04 ещё и iverilog, 2 мин 4 с).

Ход (iverilog и Verilator совпадают построчно):

- 61,7 мкс — MAX отпускает `/RESET`, первая выборка ЦПУ с 0000 (ROM `0x30000`);
- 90,8 мкс — первый такт конфигурации (настройка Z84C15, SIO, PIO, проверка подписи в fastram);
- 8,04 мкс на байт (113 тактов на 14 МГц) → полный поток 59 215 байт = **0,476 с** модельного времени;
- после отпускания ~1,8 мкс сброса от ACEX, затем первая выборка в рабочей карте: адрес 0000, страница ROM 8 (BIOS), дальше `OUT` в SIO / PIO / SCRP (`EE` / `EF`: CSBR / MCR), порт `FE`.

## 6. Открытые вопросы

- Выход из порта 2E в оригинале (DD11 держит 1011/000, а `/RESET` ЦПУ при пустом ACEX никто не ведёт) — по схеме не видно; у нас сброс ЦПУ от MAX (п. 2).
- `/RESET` ЦПУ при включении в оригинале: подтяжка R40 и ничего больше; ЦПУ стартует как получится и попадает в 0 через `FF` / `JP 0`. У нас — чистый сброс.
- Личности k30 и SCROLL собраны (`docs/versions.md`), на плате не проверялись (SCROLL — ни Thunder in the Deep, ни `GAME_00`).
- Хеш MAME не различает 2.16 и 2.17 (одинаковые первые 512 байт). Для OSD можно добавить CRC всего потока.
- `sp_sdram` в режиме без конфигурации регенерирует сам — DRAM переживает переконфигурацию (в оригинале — нет; программы на это рассчитывать не должны).
- В стендах, где `sp_acex` / подмодули включены без `CFG_RST` (в т. ч. новый `tb_cpu_acexm`), вход висит в Z; работает (используется только в `if`), но лучше подключить 0.
- XST после правок не запускался: вывод BRAM для ОЗУ с мультиплексором порта записи и ПЗУ-копий MIF не проверен.
- Источник фаз `CT` для `sp_sram` / `sp_sdram` переключается (свой счётчик ↔ ACEX) без выравнивания по 7-МГц циклу: `sp_sram` безопасен (слоты всегда по `CE_N`), `sp_sdram` в момент сброса может увидеть урезанный цикл; модели без задержек этого не ловят.
