# Ф0.3 — MAME `sprinter.cpp` против AHDL 2.18

Источники: `upstream/mame/sprinter.cpp` (2059 строк), `z84c015.cpp/.h` (база `tmpz84c015` в `upstream/mame` не лежит, на неё ссылок по строкам нет); AHDL `upstream/sprinter-hard/Quartus2/ACEX/*.TDF`, `DCP.MIF`, `MAX/SP2_MAX.TDF`. Ссылки вида `cpp:584` — строки `sprinter.cpp`; `DCP:351` — `DCP.TDF`; `ACEX:1076` — `SP2_ACEX.TDF`; `VID:390` — `VIDEO2.TDF`; `ACC:` — `ACCELER.TDF`; `KBD:`, `MAX:` — соответственно.

Сравниваем только активные ветки AHDL: `UPDATE = 1` (`ACEX:556-639`, `DCP:581-587`), `MODE = "SPRINTER"`, `MOUSE = "NO"`, `NMI_ON = "OFF"`, `SCREEN_OFF = "NOT_USE"`. Ветки `ELSE GENERATE` (`ACEX:641-712`, `DCP:588-596`) мертвы.

Внимание: адреса в `DCP.MIF` **десятичные** (`16` = код `0x10`, `136` = `0x88`).

## 0. Главное

1. **Таблица порт → код одинакова во всех BIOS 2.13 … 3.04** (распакована из ROM, раздел 1.1). Значит, 3.0x не добавили новых портов в адресном пространстве Z80; отличия 3.0x — внутри логики ACEX (что делает код), а не в карте.
2. MAME моделирует одну «суммарную» конфигурацию для всех BIOS (битстрим, который BIOS заливает, MAME не исполняет). Отличия MAME от 2.18 — смесь функций 3.0x, упрощений эмулятора и ошибок MAME. В таблице отличий (раздел 2) у каждого пункта класс.
3. Конфигурация игры в MAME — это та же стандартная машина плюс другой `screen_update_game` (раздел 1.12); MAME сам пишет, что она «not fully discovered» (`cpp:45`).

## 1. Что реализует MAME

### 1.1 Два уровня декодирования портов

**Уровень 1 — таблица портов в ОЗУ (16 КБ, страница 0x40).** `m_dcp_location = ram + (0x40 << 14)` (`cpp:1531`). Индекс (`cpp:584` чтение, `cpp:706` запись):

```
idx = CNF[4:3]<<12 | PN5<<11 | DOS<<10 | RD<<9 | A15..A14<<7 | A6..A5<<5 | A13<<4 | A7<<3 | A2..A0
```

`DOS` здесь = `m_dos` (0 — TR-DOS включён, 1 — выключен), `RD` = 1 для IN. Адресные биты A3, A4, A8…A12 **не декодируются** (поэтому, например, `#5C` = `#54`, `#FB` = `#7B` по коду). AHDL — то же самое, только как адрес DRAM: столбец `(CNF4,PN5,DOS,/WR,A15,A14,A6,A5,A13,A7,A2)` + `MCA = A1..A0`, строка `(CNF4,CNF3,0x40)` (`DCP:351-352`, `DCP:382-384`); код читается с шины `MD` в `DCPP` (`DCP:624-627`). **Совпадает.**

Таблицу пишет BIOS: страница 0x40 видна в окне 3 до первого IN (`m_starting`, `cpp:367`; AHDL `PGS = DD = 0` → `MIF[0] = 0x1040 «DCP PAGE»`, `DCP:718-722`). В ROM таблица лежит упакованной с `0x21400` (ROM-страница 8, смещение `#1400`), распаковщик в ROM по `0x20CA2`:

```
LD HL,#1400 / LD DE,#C000 : байт-маска, старший бит первым: 1 = литерал, 0 = 0x00; до DE = 0
затем LDIR #C000→#F000 (1 КБ) и #F000→#F400 (3 КБ)  => при CNF[4:3]=3 таблица = первый 1 КБ ×4
```

Распаковка ROM 2.13, 2.17, 3.00, 3.03, 3.04 (`~/Downloads/karabas-sd-sprinter/roms/mame-named`) даёт **байт-в-байт одинаковые** 16 КБ. ROM 3.05 / 3.06 не проверены (нет нужных образов; `sp2k-3.06-hf2` из unreal-ng устроен иначе).

Таблица при `CNF[4:3] = 0`, `PN5 = 0` (адрес — шаблон по декодируемым битам, A3/A4/A8-A12 любые; «DOS» = TR-DOS включён):

**Уровень 2 — что делает код.** MAME: `switch` в `dcp_r` (`cpp:587-681`) и `dcp_w` (`cpp:710-914`). Для кодов `C0…FF` та же ОЗУ — регистры страниц (`m_ram_pages`, раздел 1.2).

### 1.2 Память

Окна по 16 КБ. Регистры страниц — `m_ram_pages[0x40]` (коды `C0…FF`), значения по умолчанию (`cpp:1533-1539`):

```
C0-CF: 00 ×16                       (копии системных портов)
D0-DF: 10 … 1F
E0-EF: 41 41 41 41 41 41 41 41 00 05 02 41 FF 00 00 41
F0-FF: 00 … 0F
```

**Совпадает** с младшими байтами `DCP.MIF 192…255`. Старший байт MIF (биты страницы 11..8 = 0, тип 2) процессор не пишет (`DCP:726-731`) — страниц 256 × 16 КБ = 4 МБ (у MAME `m_ram` 64 МБ, но индекс 8 бит).

`update_memory` (`cpp:320-382`) — дословный перевод AHDL:

- **Окно 0.** `pre_rom = rom_sys | cash_on`, `pre_cash = !cash_on` (`ACEX:582-583`). ROM: страница `(ROM_RG & 0x0F) ^ (!sys_pg << 3)` (`ACEX:613`). Fastram («cash», 64 КБ): страница `ROM_RG & 3` (`ACEX:614`), по `IN #FB`. Иначе ОЗУ по регистру `PG0` (`cpp:338-347` = `DCP:685-696`, `CASH_ON = 0`, `NMI_ENA = 1`); запись разрешена только при `SC0 & ram_sys` (`DCP:598`, `ACEX:631`).
- **Окна 1, 2** — регистры `E9`, `EA` (`DCP:708-709`).
- **Окно 3** — регистр `PG3 = (!PN7, 1, (SC4&!CNF7)|(CNF7&PN6), PN2..0)` → коды `D0-D7`, `F0-FF` (`cpp:366` = `DCP:682`). До первого IN — страница 0x40.
- **ISA** в окне 3: `SC4` и страница `D0…DF` (MAME `(p & 0xF9) == 0xD0`), бит 2 — IO/mem, бит 1 — слот (`cpp:369-379,1246-1276`). ISA-память MAME не делает (`FF`).
- **Видеостраницы** `0x50…0x5F` (`cpp:1175-1177,1193-1205`): адрес `port_y * 1024 + A[9:0]`, запись в видео-ОЗУ и (если бит 2 = 0) в тень DRAM страницы `0x50+`; бит 3 — прозрачность для `FF`; чтение — из тени DRAM. AHDL: `GRAF`, `GA = (1,G_LINE)`, `BLK_MR`, `GLISSER` (`DCP:344-348,607-613`, `ACEX:966-970`). **Совпадает.**
- **ZX-экран**: запись в окна 1 / 3 (страницы `1101X1`) дублируется в видео-ОЗУ по адресу `(A7..0)<<10 | ZXS4..1<<6 | (ZXS0^SP_SA^A13)<<5 | A12..8` (`cpp:1208-1219`; AHDL `VID:383`, `ACEX:1008-1009`, `DCP:337-342`).
- **DOS** (TR-DOS теневой ROM): M1 в `#3Dxx` при `PN4` → DOS вкл, M1 выше `#4000` → выкл (`cpp:1383-1400`; AHDL `ACEX:836-838`). **Совпадает.**
- **Мягкий сброс записью**: окно 3, `SC == 0x10`, страница `0xA0` (`cpp:1190-1191`; AHDL `ACEX:562-563`: `SC4` и страница `0xAx`).

### 1.3 Видео

Растр 896 × 320 (или 312) на 14 МГц (`X_SP/3`), видимая область 736 × 288 (48+640+48, 16+256+16) (`cpp:180-190,1981`). Счётчики AHDL: `CTH 0…55` по 48 тактов 42 МГц = 16 точек, `CTV 0…319` (`VID:307-320`); 312 строк делает MAX (`NT320`, `MAX:241`), подстраивая `CTV` через `COPY_SINC_V`.

**Описатели (mode descriptors)** лежат в видео-ОЗУ: знакоместо 16×8 точек, байты `+0…+3` по адресу `(1 + a*2 + 0x80*RGMOD0)*1024 + 0x300 + b*4`, `a` = 0…55 (столбец), `b` = 0…39 (строка из 8 линий) (`as_mode`, `cpp:547-553`; AHDL `VLA` при `VCM=3`: `(RGMOD0, CTH, CT5, 1,1, CTV[8..3], 0,0)` `VID:437`). `RGMOD0` — выбор одного из двух наборов (страница экрана). Байт0 = `VDM3`, байт1 = `VDM2`, байт2 = `VDM1` (`VID:536-538`); байт3 в 2.18 не читается.

- **Графика** (`mode0` бит4 = 0), `draw_tile` `cpp:430-451`: пиксели с `y = mode1[7:3]*8 + линия`, `x = mode0[3:0]*64 + mode1[2:0]*8`; `mode0` бит5 = 1 — 256 цветов (1 байт = точка ×2, 320 точек), 0 — 16 цветов (полубайт, 640 точек, сначала старший); `mode2` бит2 — «lowres» (×2 по обеим осям, `mode2[1:0]` выбирают четверть); палитра `mode0[7:6]`. AHDL `VID:469-476,600-604` — **совпадает**.
- **Текст / ZX** (`mode0` бит4 = 1), `draw_symbol` `cpp:453-497`: символ — байт по `(mode1<<10)|(mode0[3:0]<<6)|(PN3<<5)|(mode0[7:6]<<3)|линия`, атрибут — по `(mode2<<10)|(mode0[3:0]<<6)|(PN3<<5)|0x18|mode0[7:6]`; `mode0` бит5 = 1 — точки ×2 (ZX 256 → 512), 0 — два 8-точечных символа на знакоместо (второй — из описателя `+1024`, т. е. `CT5 = 0`) → текст 80×32. Цвет: палитры 4…7 (`0x400 + attr + 0x100*бит + 0x200*flash`), мигание = бит 4 номера кадра. AHDL `VID:481-494,609-612` (`CTF4`, `SCR128 = PN3`).
- **Бордюр / гашение**: `mode0[7:4] = F` → бордюр (палитра 4, индекс `border*9`), если ещё `mode0[3:2] = 11` — чёрное (`BLANK`) (`cpp:475-479`; `VID:390-391,586-587`).
- **Палитры**: последние 32 байта каждой строки 1 КБ (`0x3E0…0x3FF`): 8 палитр × 256 строк, 4 байта на цвет (R, G, B, —) (`vram_w`, `cpp:1238-1243`; AHDL читает цвет из видео-ОЗУ при `VCM=0`, `VID:410`).
- **INT от описателей**: `mode0 & 0xFD == 0xFD` — запрос; прерывание в последней линии строки, на первом знакоместе после серии `FD` (`update_int` `cpp:1278-1313`; AHDL `INTTX`, `INTT` `VID:392-394`, `INT_X` `ACEX:744`). Сброс через 32 такта 3.5 МГц (`cpp:1736`) / AHDL — по INTA или через ~2 периода `CTH2`.
- **`HOLD` (`CB`)**: MAME сдвигает картинку на `((7 - D[3:0])*2, 7 - D[7:4])` (`cpp:851`). AHDL сдвигает синхронизацию: `SINC_HOLD[3:0]` тактуется `CT4` (шаг 24 такта 42 МГц = 8 точек), `SINC_HOLD[8:4]` — по строке, предзагрузка `(HOLD[7:4],0)` (`ACEX:795-821`); сброс `HOLD = 0x77` только при включении (`/RES`, `ACEX:827-830`). Масштаб шага MAME и AHDL расходится — проверить в симуляции.

### 1.4 Ускоритель

Включён `ALL_MODE0` (`acc_ena`, `cpp:197`; `ACC.ACC_ENA` `ACEX:914`). Команда — непрефиксная `LD r,r` с одинаковыми регистрами (условие `cpp:922-923` = `ACC:262-268`), режим `m_acc_dir` (`cpp:925-935` = `ACC:248-257`):

| Команда | `acc_dir` | Действие |
|---|---|---|
| `LD B,B`, `HALT` | 00 | выкл |
| `LD C,C` | 25 | заполнение константой (запись данных ЦПУ N раз, адрес+1) |
| `LD D,D` | 09 | следующий доступ к памяти задаёт длину N (0 = 256) |
| `LD E,E` | 15 | заполнение по вертикали (`port_y++`) |
| `LD H,H` | 41 | двойной байт: запись и по `адрес^1` |
| `LD L,L` | 27 | копирование строки: чтение → буфер 256, запись ← буфер |
| `LD A,A` | 17 | копирование по вертикали |

Логические функции: `AND/XOR/OR/CP (HL)` (`A6/AE/B6/BE`) задают операцию над буфером при чтении (`cpp:938-951`, `update_accel_buffer` `cpp:1127-1137`; AHDL `FN_ACC`, `XMD` `ACC:320-337`).

Модель MAME: `check_accel` (`cpp:1007-1052`) по первому доступу к памяти (не M1) ставит `ACCEL_GO`; блочная операция — WAIT, таймер `acc_tick` (`cpp:956-997`) делает все N байт сразу (по 6 тактов 42 МГц на байт), затем `wait_off` снимает WAIT через это время; при чтении ЦПУ получает последний байт (`defer_access`). Работает только на страницах ОЗУ (`BANK_RAM_MASK`, `cpp:1098-1112`). Буфер — `m_accel_buffer[256]`, индекс — счётчик `acc_cnt` (вниз от `rgacc`) или `xcnt` (альтернативный режим `C7`: `xcnt:xagr += aagr` на каждом байте, `cpp:1114-1125`). При записи в страницу `0xFD` данные буфера идут в FIFO CBL (`cpp:1069-1087`). AHDL: `ACC_CNT`, `CONTINUE` держит цикл памяти, `RAM` 256×16 (`ACC:62,184-246,339-359`), `CBL_WR` по странице `FD` (`ACEX:1121-1123`).

Ещё: правка операнда `IN/OUT (n)` = `#1F` (`cpp:1009-1015`, см. отличие D21).

### 1.5 CBL (Covox Blaster)

`m_cbl_xx` (код 89): бит7 — режим CBL (FIFO), бит6 — стерео, бит5 — 16 бит, бит4 — прерывание, биты 3..0 — частота (`cpp:198-201`). Делители `{13,9,0,0,0,0,0,0,27,19,13,9,6,4,3,1}`, такт `(div+1)` периодов `42 МГц/192` = 218.75 кГц: 15.6 / 21.9 / 7.8 / 10.9 / … / 109 кГц (`cpp:801-805`) — **совпадает** с `CBL_TAB` (`ACEX:1082-1101`). FIFO 256 × 16: `cbl_tick` (`cpp:1748-1765`) берёт 1 (моно) или 2 (стерео) слова; в 16-битном режиме байты пишутся парой (младший, затем старший `^0x80`, `cpp:1078-1086`; AHDL `CBD`, `MDO15 xor MODE16` `ACEX:1138-1147`). Прерывание каждые 128 отсчётов, тогда `wa = cnt ^ 0x80` (`cpp:1760-1764`; AHDL `CBL_INT` по спаду `CNT6`, `CBL_WA` `ACEX:1073,1131-1134`). Без режима CBL код 88 — простой Covox на обе ЦАП (`cpp:790-791`; `CBL_R = D<<8` `ACEX:1164`). В `#FE` при режиме CBL: бит7 = половина FIFO (`cnt ^ wa`), бит5 = нижний бордюр (`cpp:1696-1701`; AHDL `CBL_IND`, `CTV8` `ACEX:388,1117`).

### 1.6 Ожидания

`do_mem_wait(cpu_taken)` (`cpp:1720-1731`): только в турбо (21 МГц), выравнивание на 6 тактов ЦПУ + `6 - cpu_taken` (ОЗУ 3, порты 4, ISA 3). ROM и fastram — без ожиданий (обход `ram_r`). На 3.5 МГц ожиданий нет вовсе. Это грубая модель, а не железо (см. D23).

AHDL: цикл DRAM 6 тактов 42 МГц (`CT 0…5`), `/MR_WAIT` в турбо или при активном ускорителе (`DCP:486`); порты — счётчик `WT_CT` по таблице `W_TAB[TURBO, тип порта]` 1…10 тактов 21 МГц (`DCP:544-567`), без ожидания для `111XX1XX` вне турбо в DOS (`DCP:541`); ROM / ISA — 4 такта (`WAIT_ROM`, `ACEX:587-596`); вне турбо — эмуляция «торможения» Spectrum для окна 1 и `PN2`-страниц окна 3, если `ALL_MODE2 = 0` (`WAIT_ORIG`, `ACEX:558-559`).

Турбо: `TB_SW` (код C6, `D1=1`) и ручной переключатель F12 (`m_turbo_hard`, `cpp:1767-1771`; AHDL `TEST_SWITCH` `ACEX:521-523`, `TURBO` `DCP:264`).

### 1.7 Клавиатура, мышь, джойстики, Z84C15

- **Z84C15** (`z84c015.cpp`): `tmpz84c015` (Z80 + CTC + SIO + PIO + WDT) + регистры `SCRP/SCDP` на `EE/EF` (WCR, MWBR, CSBR, MCR). Выборка `CS0` / `CS1` по `CSBR` и `MCR` переводит адрес в `0x1xxxx` (обычная карта Sprinter) / `0x2xxxx`, иначе `0x0xxxx` (`bootstrap_r/w`) — `translate_memory_address`. Ожидания WCR/MWBR не моделируются; `WCR = 0` сразу (в железе `FF` до 16-го M1), `CSBR = FF` вместо «`|= 0x0F`» (`z84c015.cpp:96-100`).
- **Клавиатура AT → SIO A**: данные → `RXDA`, такт → `RXCA`/`TXCA` (`cpp:1987-1991`). BIOS и DSS опрашивают `#19/#18` (KEY.ASM: WR4 = `07` — x1, чётность, 1 стоп; WR3 = `C1`), т. е. скан-коды читаются Z84C15, не ACEX. Прерывание клавиатуры: `on_kbd_data` считает 11 фронтов такта при `(ALL_MODE & 9) == 9` (`cpp:1706-1718`).
- **ZX-матрица (`#FE`, код 40)**: MAME строит её из своих клавиш хоста (`IO_LINE0-7`, `cpp:1775-1891`); AHDL переводит скан-коды AT в матрицу таблицей `KBD_INI2.MIF` (`KBD:167-177`), включается при `ALL_MODE0 = 0`.
- **Мышь**: MS-mouse на SIO B (`RXB`, такт `ZC0` CTC, `cpp:2000-2007`; DSS INTMOUSE: CTC0 `55/45` от 875 кГц → ~1200 бод x16). Kempston-мышь (код 58) в MAME — отдельные абсолютные координаты хоста (`mouse_input1-3`); в AHDL — декодер MS-протокола того же провода `MOUSE_D` (`MOUSE.TDF`), т. е. одна мышь.
- **CTC**: входы `CLK/TRG0-2` = 875 кГц (`X_SP/48`), `ZC2 → TRG3` (`cpp:1993-2008`).
- **Джойстики**: код 15 — `joy_ctrl_r(1)`, PIO A — `joy_ctrl_r(2)`; 6-кнопочный Sega-мультиплекс по `DTRB` / `PB7` (`cpp:1330-1374`), сброс счётчиков на кадровом INT.
- **Прерывания**: `input_merger` (кадр, клавиатура, CBL) → `INT`, вектор `FF` (`cpp:1955-1964`).

### 1.8 IDE, FDD, CMOS, ISA, AY

- IDE: два `ata_interface` (`m_ata_selected`), 16 бит через защёлку и `A8` (раздел 1.1). BIOS/DSS читают сектор цепочкой `INI` с `BC = #0050` — B = 0 → слово, далее B = FF → защёлка (HDRIVER6.ASM:265-275). **Совпадает** с AHDL.
- FDD: `beta_disk_device` (ВГ93 + системный регистр `#FF`, состояние INTRQ/DRQ). 720 / 1440 — коды 16/17 (`OUT (#BD)` с `A=#01/#21`, т. е. по A13; FDRIVER2.ASM:733-741). В AHDL ВГ93 снаружи, MAX даёт такт ВГ93 1 / 2 МГц, сепаратор данных `FDAT/QDAT`, прекомпенсацию `WDAT`, «турбо» такта при простое (`TURBING`) (`MAX:272-370`).
- CMOS: DS12885 (должен быть DS12887A, `cpp:1966`).
- ISA: два слота `isa8`, по умолчанию `zxbus_adapter`; только IO, память — `FF`; частота шины не определена (`FIXME`, `cpp:1973-1979`).
- AY: `ay8910` на 1.75 МГц, A → L, B → L+R, C → R (`cpp:2013-2017`). AHDL — свой AY в ACEX с таблицей громкости `AY.MIF` и бипером (`AY3.BEEPER = BORDER4`), смешивается с CBL в один 16-битный поток на TDA1543 (`ACEX:1047-1064,1203`).

### 1.9 Загрузка конфигурации и сбросы

- `machine_start`: `m_conf_loading = 1`, `m_conf = 0` (`cpp:1545-1546`).
- `machine_reset` (`cpp:1549-1601`) при `m_conf_loading`: счётчик и хеш в 0, окно 0 = ROM-страница `0x0C` (ROM `0x30000`, загрузчик и битстрим), окно 3 без ISA. Иначе — обычные `update_memory`, 320 строк.
- `bootstrap_r/w` (`cpp:1139-1166`) — адреса вне `CS0` (и `CS1`): при `m_conf_loading` чтение/запись идут в fastram; каждая запись: `hash += data << (8 * (count % 4))` (весь байт, не только D0), после **0x1000** записей: `m_conf_loading = 0`, `m_conf = (CSBR & 0x0F) == 0` («CS0 выключен ⇒ загрузчик читает конфигурацию из fastram») `&& hash == 0x3861cfa4`, `m_ram_pages[0x2E]` (регистр `EE`) `= m_conf ? 0x41 : 0x00`, мягкий сброс.
- Код 2E — `m_conf = 0`, `m_conf_loading = 1`, сброс (повторная загрузка).
- Железо (MAX): `CNF_OFF = 1` после `/RESET` — режим загрузки, `10K_CLK = WR_CNF`, `10K_D0 = D0` — по одному биту на запись ЦПУ (59 215 байт = 473 720 записей); первый `XACS` от ACEX → рабочий режим (`MAX:265-266,322-324`). `/CONF_X = /RESET` (открытый сток, `MAX:318`) — **любой** сброс (кнопка, Ctrl+Alt+Del `KB_RESET` `KBD:112-114`, запись в страницу `Ax`, порт 2E) стирает ACEX, и BIOS заливает конфигурацию заново.

### 1.10 Сброс состояния (MAME `machine_reset`)

`m_dos = 1`, `rom_sys = ram_sys = sys_pg = arom16 = 0`, `cnf = pn = sc = rom_rg = 0`, `cash_on = 0`, ускоритель выкл, `cbl_xx = 0`, `ata_selected = 0`, `turbo_hard = 1`. **Не** сбрасываются: `m_all_mode`, `m_port_y`, `m_rgmod`, `m_hold` (только в `machine_start` = 0), `m_turbo` (не инициализируется вовсе).

### 1.11 Конфигурация игры: `screen_update_game` (`cpp:500-545`)

Выбирается `screen_update` при `m_conf != 0` (`cpp:399-402`); всё остальное (порты, память, ускоритель, INT) — как в стандартной.

Построчно (каждая линия `vpos` отдельно):

1. `b` = строка знакомест с учётом `HOLD`; `a` = столбец левого края `cliprect`; начальная прокрутка `scroll = lookback_scroll(a, b)`.
2. Для каждой точки `hpos`: `a16 = (hpos + scroll.x*2 - 48 - hold.x) mod 896` (горизонтальная прокрутка шагом 2 точки), `b8 = (vpos + scroll.y - 16 - hold.y) mod H` (вертикальная прокрутка 0…15 линий).
3. В начале знакоместа берётся описатель `as_mode(a16>>4, b8>>3)` (тот же, что в стандартной конфигурации): палитра `mode0[7:6]`, `x = mode0[1:0]<<8 | mode1` (10 бит, байт в строке 1 КБ), `y = mode2` (8 бит, строка видео-ОЗУ).
4. Точка: если `mode0[7:5] = 111` — бордюр (`mode0[3:2] = 11` → цвет 0, иначе `border*9`, палитра 4); иначе `pal + vram[(y + (b8 & 7))*1024 + x + ((a16 & 15) >> 1)]` — **всегда 256 цветов**, точка ×2.
5. `mode0` бит2 = 1 — у знакоместа есть байт3: `scroll = (mode3[3:0], mode3[7:4])`; новая прокрутка применяется после конца этого знакоместа (`a16 & 15 == 15`) или сразу на границе, если описатель с битом 2 уже взят (`cpp:517-521`).

`lookback_scroll` (`cpp:555-568`) должен найти последний описатель с битом 2 левее/выше, но написан с ошибкой: `h` и `v` — копии начальных `a`, `b`, они не меняются; циклы уменьшают `a`, `b`, а условие `(h != a) && (v != b)` смотрит всё время на один и тот же описатель `(a0, b0)`. Итог: возвращает прокрутку самого начального знакоместа, если у него бит 2 и `b0 > 0` (при `b0 = 0` — `{0,0}`), то есть на деле «поиска назад» нет. Также `pal`, `x`, `y` не инициализированы до первого описателя (`cpp:510-511`), а `cliprect` по строкам у MAME может начинаться не с 0 — результат зависит от разбиения на частичные обновления.

## 3. TODO и приёмы MAME, не являющиеся поведением железа

- `TODO` (`cpp:42-45`): память ISA; отвязка от родителя Spectrum; отрисовка конфигурации игры «not fully discovered».
- `X_SP` — «TODO X1 after spectrumless» (`cpp:178`); частота ISA — `FIXME` (`cpp:1975-1979`); DS12885 вместо DS12887A.
- `m_dcp_location` — таблица портов читается прямо из ОЗУ при каждом IN/OUT (в железе — тоже цикл DRAM; совпадает по смыслу).
- Ускоритель: вся блочная операция выполняется мгновенно в `acc_tick`, ЦПУ держится WAIT по таймеру; `defer_access`, `adjust_icount` — механика MAME. Логическая функция «липкая» (D19).
- `do_mem_wait` — эвристика выравнивания; нет ожиданий на 3.5 МГц и для ROM (D23).
- `m_starting`: запись в порты игнорируется до первого IN (`cpp:688`) — в AHDL то же через `DCPP.clrn` (`DCP:622-626`), но MAME дополнительно сбрасывает флаг в `dcp_r` безусловно.
- Загрузка конфигурации: битовый поток не моделируется; «конец загрузки» = 0x1000 записей в fastram; хеш — сумма байтов со сдвигом (не CRC битстрима). Тест `CSBR & 0x0F == 0` — косвенный признак «конфигурация из fastram».
- `m_ram_pages[0x2E] = 0x41` для игры (`cpp:1162`) — подстановка вместо MIF игрового битстрима.
- `lookback_scroll` не ищет назад (раздел 1.11); неинициализированные `pal/x/y`.
- Z84C15: нет ожиданий WCR/MWBR, `WCR = 0` сразу, `CSBR = FF` (`z84c015.cpp:96-100`).
- Kempston-мышь и MS-мышь — две независимые мыши хоста; ZX-матрица — клавиши хоста; Sega-джойстики.
- AY / Covox / CBL — раздельные устройства MAME, без общего сумматора и TDA1543.
- Сброс из `ram_w` (страница `A0`) и `schedule_soft_reset` не перезагружают конфигурацию.
- `update_int` ищет `FD` с поправками «2 строки сверху, 3 знакоместа слева, 3 teared blank?» (`cpp:1289-1292`) — подобранные смещения.
- `m_hold` сдвигает картинку, а не синхронизацию (масштаб, D33).

## 4. Что трогают BIOS SETUP и DSS

Порты (по исходникам `upstream/sprinter-bios/SETUP`, `upstream/sprinter-dos`), код — по таблице раздела 1.1:

| Порт | Код | Кто | Зачем |
|---|---|---|---|
| `#82 #A2 #C2 #E2` | E8 E9 EA F0 | SETUP (66× `OUT (PAGE3)`), DSS (`HARDWARE.INC`, `DOS_X.ASM:23-26`) | окна 0…3, чтение и запись |
| `#89` | C4 | SETUP `Y_PORT` (FDRIVER2, DSETUP), DSS INTMOUSE (`IN A,(Y_PORT)` — читает **последнее записанное**, MAME и AHDL одинаково) | строка видео-ОЗУ |
| `#C9` | C5 | DSS `VPAGE` (INTMOUSE) | `RGMOD`, страница экрана |
| `#FE` | C2 / 40 | SETUP, DSS | бордюр, клавиатура ZX |
| `#3C`, `#7C` | C6 (+ прямой декод `/SYS`) | SETUP (`OUT (#7C)`, `OUT (#3C)`), DSS (`OUT (#7C)`) | системный ROM, CNF |
| `#18/#19` | — (Z84C15 SIO A) | SETUP KEY.ASM, DSS KEYINTER | скан-коды AT, опрос |
| `#1A/#1B` | — (SIO B) | DSS INTMOUSE, SETUP FDRIVER2 (Sprinter 97: 1.44 через WR5 SIO B) | мышь MS |
| `#10` | — (CTC0) | DSS INTMOUSE | скорость мыши |
| `#0F #3F #5F #7F #FF` | 10…14 / 15 | SETUP FDRIVER2 | ВГ93 (только при DOS) |
| `#01BD` / `#21BD` | 16 / 17 | SETUP FDRIVER2:733-741 | 720 / 1440 |
| `#0050…#0055`, `#4052/#4053`, `#4152/#4153`, `#0150`, `#0254/#0255` | 20…29 | SETUP HDRIVER6 / EXTENDED / AUTOIDE, DSS (через BIOS) | IDE, `INI` по 16 бит |
| `#1FFD` | C0 | только закомментировано (DSETUP `;R01`) | — |

Не трогают (по исходникам): ускоритель (`LD r,r` в SETUP / DSS не найдено), CBL `#004E`/`#204E` (коды 89 / C3), `#FC` (C7), `HOLD`, ISA, порт 2E, Kempston-мышь. DSS работает через BIOS (`RST #08`), сам BIOS-ядро в исходниках нет — его порты видны только по таблице (раздел 1.1) и коду ROM.

Вывод: для запуска SETUP и DSS нужны страницы / окна, `#89/#C9`, ZX-клавиатура и бордюр, CNF / ROM-переключение, Z84C15 (SIO A с x1-тактом от клавиатуры AT, SIO B + CTC для мыши), ВГ93, IDE 16 бит. От списка отличий раздела 2 им важны D1/D2 (сброс и смысл `ALL_MODE`; кто пишет код C3 — порт `#204E` — в исходниках SETUP / DSS не видно, значит BIOS-ядро в ROM; проверить дизассемблером), D14 (`PN5` выбирает подтаблицу портов), D25 (турбо при сбросе), D23 (тайминги IDE / FDD при опросе). Ускоритель, CBL и видеорежимы нужны программам (демо, игры), а не BIOS / DSS.
