# Опись AHDL оригинала и правила перевода (Ф0.1)

Источник: `upstream/sprinter-hard`, ветка `quartus2`, версия «2.18» (10.03.2002). Ссылки `файл:строка` даны по `Quartus2/ACEX/*.TDF` и `Quartus2/MAX/SP2_MAX.TDF`.

Живой код: параметры по умолчанию `UPDATE = 1`, `MODE = "SPRINTER"`, `NMI_ON = "OFF"`, `SCREEN_OFF = "NOT_USE"` (SP2_ACEX:4-10), `MOUSE = "NO"` (VIDEO2:9), `NUM = "NO"`, `G_MODE = 1` (SP2_MAX:6-8). Ветки `ELSE GENERATE` для `UPDATE = 0` (SP2_ACEX:641-712, DCP:588-596) мёртвые. **SP2_ACEX:432-520 — один комментарий `% … %`**: весь блок `IF MODE == "SPECTRUM"` (тестовый экран, `KTA` / `KTD` / `TEST_1`) закомментирован. Строки 521-538 — живой безусловный код, `END GENERATE` на :540 тоже в комментарии (:539-541).

Описи ниже — только по живому коду, если не сказано иное.

Числа LE и регистров — `SP2_ACEX.map.rpt:241, 252-272`; память — `SP2_ACEX.map.rpt:332-341`, всего 14 080 бит (`SP2_ACEX.fit.summary`): DCP 4096 + CBL 3840 (бит 0 выброшен, `CBD[0]` lost fanout) + AY 2048 + KBD 2048 + ACCELER 2048 (старший байт дублирует младший, `ACCELER:350`). У MAX отчётов в репозитории нет.

Итоги, важные для плана:

- Тактов кроме `CLK42` много: около 60 разных тактовых цепей в ACEX (Quartus насчитал 54 узла ripple / gated, `SP2_ACEX.tan.rpt:2050-2104`, и ещё 4 вывода Z80 как отдельные домены: `/m1`, `/mr`, `/wr`, `/io`) и 13 в MAX. Отрицательный фронт `CLK42` используется в 11 местах. Комбинационных петель: 1 в ACEX (`STARTING`) и 5 в MAX.
- Quartus-сборка из этой ветки по таймингу не проходит: Fmax 37,04 МГц при нужных 42 (`SP2_ACEX.tan.summary`, путь `ISA_PORT[6]` → регистр на `!CLK42`).
- **Файлы `.MIF` в `Quartus2/ACEX` испорчены при переводе адресов в десятичные** (п. 6.1): клавиатура в такой сборке сдвинута на два скан-кода. Эталон — копии `MaxPlus2/ACEX/*.MIF`.
- Дешифратор портов **двухуровневый**: каждый цикл ввода-вывода сначала читает байт-дескриптор из DRAM (страница 0x40, 16 КБ, таблицу пишет BIOS), затем дескриптор индексирует `MEM` 256×16 (п. 4.1).
- В видео-ОЗУ лежат не только пиксели: там же **палитры** и **таблица режимов** (по слову на 4 / 8 точек × 8 строк; задаёт адреса, режим, бордюр и положение INT). Каждые 23,8 нс (такт 42 МГц) — одно 32-битное обращение, 6 слотов на 7-МГц цикл (п. 3).

> Опись сделана по 2.18. В 3.03a `DIR_PORT4` = `RGMOD2` (гашение, ИЛИ в `BLANK`), а не постоянный 0 — см. `docs/versions.md`.

## 1. Модули

### 1.1 SP2_ACEX (верх)

Порты (SP2_ACEX:24-76):

- Такт: `TG42` (вход 42 МГц), `CLKZ1` (выход, такт Z84C15 = `DECODE.CLK_Z80`).
- Z80: `/WAIT`, `/RESET` (BIDIR, открытый сток через `TRI`), `/M1`, `/RF`, `/IO`, `/WR`, `/RD`, `/MR`, `/HALT` (не используется), `A[15..0]`, `D[7..0]` (BIDIR).
- ROM / кеш / ISA: `CS_ROM`, `CS_CASH`, `RA[17..14]` (страница ROM 16 КБ / кеша / слота ISA).
- Видео-ОЗУ (4 × W24512, 32 бита): `V_CS[1..0]` (константы: `V_CS0 = GND`, `V_CS1 = VCC`, VIDEO2:449, 458), `VA[15..0]`, `V_WR[3..0]` (побайтные /WE), `VD3..VD0[7..0]` (BIDIR). `WR_COL` — строб внешнего защёлки ЦАП RGB (= `SVIDEO.WR_PIX`).
- ЦАП звука TDA1543: `DAC_DATA`, `DAC_WS`, `DAC_BCK`.
- DRAM (SIMM): `MD[15..0]` (BIDIR, она же шина данных IDE / ВГ93 / CMOS / ISA), `MA[14..0]`, `RAS_[1..0]`, `CAS_[3..0]`, `/WE`.
- Связь с MAX и платой: `XACS` (первый `XACS` переводит MAX в рабочий режим; он же «ROM_WE»), `XA[3..0]` (BIDIR, мультиплексная шина), `SXA` (выбор половины внешнего мультиплексора), `RDXA`, `WR_AWG` (строб управляющего слова на `MA`), `RD_KMPS`, `WR_DWG`.

Подмодули (SP2_ACEX:79-89): `MS : MOUSE`, `KEYS : KBD`, `SVIDEO : VIDEO2`, `DECODE : DCP WITH (UPDATE)`, `ACC : ACCELER`, `AY3 : AY`, `CBL : lpm_ram_dp` 256×16.

Что внутри верха:

- Регистры портов (все тактуются `/IOWR`, разрешение — `DCPP` = дескриптор порта от DCP): `BORDER` C2/CA (:313-315; биты 2..0 бордюр, 3 `TAPE_OUT`, 4 бипер AY), `ALL_MODE` C3 (:1038-1041; бит 0 — клавиатура «все клавиши» + INT по клавишам + разрешение ускорителя, бит 2 — отключить «оригинальные» ожидания), `RGMOD` C5/CD (:954-958; бит 0 → `DIR_PORT3`, страница таблицы режимов), `HOLD` CB (:823-830; сдвиг картинки относительно синхро MAX), `CBL_XX` 89 (:1075-1077), `ROM_RG` 8F или 5C при `/SYS = 0` (:635-639), `ISA_PORT` 1111xxxx (:552-554). По адресу, а не по дескриптору: `/SYS`, `SYS_PG` — порты 3C / 7C (:545-550, 566-569), `CASH_ON` — `IN A,(FB)` / `(7B)` (:577).
- Выбор ROM / кеша / ISA (:558-639): `PRE_ROM`, `PRE_CASH`, `PRE_ISA` → `CS_ROM`, `CS_CASH`, `RA[]`, `BLK_MEM` (запрет DRAM) и ожидание ROM `WT_R` (4 такта 42 МГц, :587-596). См. п. 4.4.
- Шины данных (:358-426): `MDP` (данные периферии с `MD`), `HDDR` (буфер старшего байта IDE), выбор `PDD` по `DECODE.TYPE[2..1]`, `D_OUT` (когда ACEX ведёт `D`).
- Мягкий сброс `SOFT_RES` (:300-306, 562-563), `/RESET` наружу (:296).
- Мультиплексор `XA` (:759-793): выдача `KBD_CX`, `KBD_DX`, `TAPE_OUT` (`WR_TM9`), приём `KBD_CC`, `KBD_DD`, `TAPE_IN`, `MOUSE_D` (`SXA = 0`) и `FDD_CH`, `FDD_W`, `SINC_1`, `SINC_2` (`SXA = 1`).
- Подстройка развёртки под синхро MAX: `SINC_HOLD`, `COPY_SINC_H` / `COPY_SINC_V` (:795-821).
- Строки DRAM (:851-878): `RAS_`, `CAS_` (выбор байта по `MCA` и `DOUBLE_CAS`), `/WE`; `MA[14..12] = (!TURBO, INT_X, NMI_X)` (:886) — **INT, NMI и TURBO уходят к Z84C15 через внешнюю защёлку на шине `MA`**, стробом `WR_AWG`.
- `INT_X` (:744-745): кадровое прерывание `SVIDEO.INTT`, прерывания клавиатуры и CBL.
- Звук (:1047-1203): AY + CBL → `AY_CHS` → сдвиговый `AUDIO_R` → I2S. CBL — FIFO 256×16 (п. 4.6).
- Мышь: `KEMPS` (:1210-1214), порты Kempston-мыши по `A10`, `A8`.

Параметры: `UPDATE`, `MODE`, `NMI_ON`, `SCREEN_OFF` (выше).

### 1.2 DCP

Порты (DCP:12-97), по группам:

- Такт и сброс: `CLK42`, `/RESET` → `/RES` (сброс по включению, :260), `CT[2..0]` (от VIDEO2).
- Цикл памяти: `CONTINUE` (от ускорителя) → `RAS`, `CAS`, `MC_END`, `MC_BEGIN`, `MC_TYPE`, `MC_WRITE`; `MA[11..0]`, `MCA[1..0]`; `REFRESH` (= `CT4`), `BLK_MEM`, `DOUBLE_CAS`.
- Z80: `/IO`, `/RD`, `/WR`, `/MR`, `/RF`, `/M1`, `A[15..0]` (= `ACC.AO`, адрес после ускорителя), `DI[7..0]` (= `D`), `MD[7..0]` (= `ACC.DO`, байт из DRAM) → `DO[7..0]`, `/WAIT`, `/IOM`, `/IOMM`.
- Такт Z80: `TURBO_HAND` (F12) → `CLK_Z80`, `TURBO`.
- Карта: `PAGE[11..0]`, `TYPE[3..0]` (= `MEM.q`), `RA[17..14]` (не используется при `UPDATE = 1`), `CS_ROM`, `CS_RAM`, `V_RAM`, `PORT`, `RAM`, `BLK_R`, `DOS` (вход), `PN4Q`, `DCPP[7..0]`.
- Периферия: `WR_DWG`, `WR_TM9`, `WR_AWG`, `RD_KP11`, `KP11_MIX`, `HDD_DATA`, `HDD_FLIP`.
- Видео / ускоритель: `G_LINE[9..0]` → `GA[9..0]`, `GRAF`, `SP_SCR`, `SP_SA`, `SCR128`, `ACC_ON`, `TEST_R`.

Параметр `UPDATE` (1: выбор ROM / кеша перенесён в верх).

Память `MEM : LPM_RAM_DP` 256×16, `DCP.MIF` (DCP:111, 726-748): адрес чтения = адрес записи = `PGS[7..0]`; пишется только младший байт (`ADR8_MEM = GND`, :726-731), **из процессора**: `OUT` в порт с дескриптором ≥ C0 (`MEM_WR`, :724). Выход — `PAGE` / `TYPE` / `DO` (п. 4).

Регистры: `PN` (7FFD), `SC` (1FFD Scorpion), `SYS`, `CNF`, `AROM16`, `TB_SW` (:649-672), `DCPP`, `DD` (:624-639), счётчик ожидания `WT_CT` (:544-567), `HDD_A` (:386-404).

Выходы: в верх (`PAGE`, `TYPE`, `DCPP`, `/IOM`, `/IOMM`, `HDD_*`, `MC_*`, `RAS` / `CAS`, `MA`, `TURBO`), в ускоритель (`MC_*`, `CAS`, `RAS`), в VIDEO2 через верх (`GA` → `VAI[19..10]`, `SP_SCR` / `SP_SA` → `ZX_PORT`, `SCR128` = `PN3`).

### 1.3 VIDEO2

Порты (VIDEO2:14-77):

- `CLK42`; выходы счётчиков `CT[5..0]`, `CTH[5..0]`, `CTV[8..0]`, `CTF[6..0]` (в верх, оттуда в DCP, ACCELER, AY, KBD), `BLANK`, `INTT`.
- Подстройка: `COPY_SINC_H`, `COPY_SINC_V` (`START_UP` не используется).
- Запись из ЦПУ: `WR` (строб), `VAI[19..0]` (адрес: `GA` от DCP + `ACC.AO[9..0]`), `MDI[15..0]` (данные = `ACC.MDO`), `DOUBLE_CAS`; `D[7..0]` не используется.
- Видео-ОЗУ: `VAO[15..0]` → `VA`, `VDO0..3` → `VD` при записи, `VDM0..3` ← `VD`, `V_WR[3..0]`, `V_WEN[3..0]` (разрешение выдачи `VD`), `V_CS[1..0]`, `WR_PIX` → `WR_COL`.
- `ZX_PORT[7..0]` (страницы экрана ZX, разрешение «теневой» записи, ZX A15), `DIR_PORT[7..0]` (0 `SCR128`, 3 страница таблицы режимов, 4 гашение — не подключено, 7..5 бордюр).
- `MOUSE_X/Y[9..0]` — для курсора, при `MOUSE = "NO"` мёртвые.

Параметры: `MODE` (только `"SPRINTER"`), `MOUSE`, `HOR_PLACE` / `VER_PLACE` (не используются).

Внутри: генератор `CT` / `CTH` / `CTV` / `CTF` (:260-323), конвейер выборки `VCM` → `VLA` (:399-442), регистры режима `MODE0..2` (:530-539), сдвиговый `D_PIC0`, `DCOL`, `BRVA` / `RBRVA` (адрес палитры, :570-620), формирователь записи `MXWE`, `V_WE`, `V_EN`, `V_WR` (:376, 622-667). Память `MS_DAT` 256×16 (`MOUSE.MIF`, курсор мыши) — только при `MOUSE = "YES"`, у нас не нужна.

### 1.4 ACCELER

Порты (ACCELER:6-59): `CLK42`, `/RESET`, `CT[2..0]`, `CLK_Z80`; `RAS` (не исп.), `CAS`, `MC_END`, `MC_BEGIN` (не исп.), `MC_TYPE`, `MC_WRITE` (не исп.) → `CONTINUE`; `AI[15..0]`, `DI[7..0]` ← Z80 → `AO[15..0]` (адрес в DCP и VIDEO2), `DO[7..0]` (байт DRAM к ЦПУ и в DCP); `/IO`, `/RD`, `/WR`, `/MR`, `/RF`, `/M1`, `/IOM`, `DCP[7..0]` (= `DCPP`); `MDI[15..0]` ← `MD`, `MDO[15..0]` → `MD` и VIDEO2; `G_LINE[7..0]`, `GLISSER`, `ACC_ON`, `ACC_ENA` (= `ALL_MODE0`), `DOUBLE_CAS`, `HDDR`, `HDD_FLIP`, `ACC_DIR[7..0]`.

Память `RAM : LPM_RAM_DP` 256×16 без MIF (:62, 349-359), фактически 256×8 (`data = (XMD, XMD)`): буфер строки для копирования и операнд AND / OR / XOR; пишет сам ускоритель (`RAM_WR`, :347), адрес `ACC_CNT` или `XCNT` (`ALT_ACC`, :339-342).

Состав: декодер опкодов на шине `DI` во время M1 (`PRF_CMD`, `ED_CMD`, `CB_CMD`, `ID_CMD`, `RETI`, `RETN`, `STATE_EI`, `IN_OUT_CMD`, `FN_ACC`, `ACC_MODE`, :130-180, 248-271, 320-322); счётчик `ACC_CNT` и его загрузка `RGACC` (:189-218); строка графики `AGR` → `G_LINE` (:195-206); второй адресатор `AAGR` / `XCNT` / `XAGR` (порт C7, :220-233); адрес `AA` → `AO` (:361-371); данные `MD`, `MDO`, `XMD`, `DO` (:275-337). Подробно — п. 4.5.

### 1.5 AY

Порты (AY:7-29): `/RESET`, `CLK42`, `AY_T[8..0]` (= `CTH[2..0], CT[5..0]`, внешний счётчик), `AY_D_WR`, `AY_A_WR` (стробы записи данных / адреса, от верха по `DCPP` = 91 / 90), `D[7..0]`, `BEEPER` (= `BORDER4`) → `DO[7..0]` (чтение регистра), `AY_CH_L[9..0]`, `AY_CH_R[9..0]` (ABC-стерео, B в оба канала), `AY_CH_VAL`; `AY_CH_A/B/C` в верху не подключены.

Устройство: не классический AY, а **микропрограммный автомат** над одной однопортовой `lpm_ram_dq` 256×8 (`AY.MIF`, :194-195). Адреса 0x00-0x0F — регистры AY (пишет ЦПУ в фазе `AY_CCC[1..0] = 01`), 0x10-0x1D — рабочие счётчики, 0x1E / 0x1F — константы 00 / FF, 0x80-0xB9 — микропрограмма (64 шага × 3 фазы; фаза 11 не встречается, потому что `CT[1..0]` не бывает 11, п. 3.1), 0x30-0x3F — таблица, недостижимая (адрес микрокоманды 5 бит, :182). Полный проход — за 4 `CTH` = 192 такта 42 МГц = 218,75 кГц, как делитель тона у AY на 1,75 МГц. Шум — 17-битный `AY_SH` (:264-267), громкость — таблица `AY_CH_CS` (:321-338), сумма каналов — `LPM_ADD_SUB` в `AY_CH_LX` / `AY_CH_RX` (:350-358). `AY_CH_DIR` (регистр 0x10, :134-137) пишется, но нигде не читается.

### 1.6 KBD

Порты (KBD:6-32): `CLK42`, `CLK_K` (= `DFF(CTH5)`, 15,6 кГц), `KBD_CC`, `KBD_DD` (линии AT-клавиатуры, через `XA`), `/RF`, `/IO`, `/IOM` и `/M1` (не исп.), `A[15..8]`, `ENA` (= `!ALL_MODE0`), `INT_ENA` (= `ALL_MODE0`) → `KBO[7..0]` (столбцы ZX), `KB_RESET` (Ctrl+Alt+Del), `KB_F12`, `KB_CTRL`, `KB_ALT`, `KB_SH`, `INT`.

Память `lpm_ram_dq` 256×8, `KBD_INI2.MIF`, выход без регистра (:167-169) — сразу и таблица «скан-код → (ряд, столбец)» (адреса = скан-коды), и **состояние матрицы ZX** (адреса `101_rrr_11` = A3, A7 … BF, :127). Пишет только сам модуль (`WR_KBD`, :165), в циклах регенерации Z80 (`K_CLK = DFF(/RF)`). ЦПУ таблицу не пишет. Чтение порта — 8 тактов `KB_MA` по рядам, логическое И по `A[15..8]` (:132-177).

### 1.7 MOUSE

Порты (MOUSE:7-15): `MOUSE_D`, `CLK` (= `DFF(CTH5)`, 15,6 кГц = 13 × 1200 бод) → `OUT_X[9..0]`, `OUT_Y[9..0]`, `OUT_K[1..0]`, `INT` (не исп.). Приёмник протокола Microsoft (3 байта, 7 бит), накопление координат.

### 1.8 SP2_MAX (EPM7064)

Порты (SP2_MAX:18-91): такт `TG42_IN` → `TG42_OUT`, `TG42_BUF` (инверсия), `CLKZZ` (14 МГц к Z84C15 в режиме загрузки, `TRI` по `CNF_OFF`), `CLK14`; `AUD` (такт таймеров = `CT3`), `BEEP` (= GND); CMOS DS12887 `CMOS_DRD`, `CMOS_AS`, `CMOS_DWR`; ВГ93 `WR_PDOS`, `WD`, `WSTB`, `SR`, `SL`, `RSTB`, `TR43`, `CLK_WG`, `FDAT`, `QDAT`, `RDAT`, `/WG_WR`, `/WG_RD`, `STE`, `DENS_X` (= VCC), `WDAT`; связь с ACEX `XA[2..0]` (вход, не используется), `XACS`, `SINC_1`, `SINC_2` (опорные синхро для ACEX), `HDD_C[3..0]` (= `MA[8..5]`), `FDD_C[2..0]` (= `MA[4..2]`); IDE `HD_DIR`, `HD_CS`, `XHD_RES`, `XHD_WR`, `XHD_RD`, `XHD1_CS[2..1]`, `XHD2_CS[2..1]`, `XHR_RDY` (не исп.); загрузка ACEX `/CONF_X` (nCONFIG), `10K_CLK`, `WR_CNF`, `10K_D0`, `D0`; монитор `SINC_V`, `SINC_H`, `SINC` (смесь), `VGA_IN`, `SINC_IN` (не исп.); `EPM_RES`, `PW_GOOD`, `GND65`, `GND33`.

Что делает:

- 14 МГц из 42 (`XCT`, :252-258) и строчная / кадровая развёртка монитора: `CT[3..0]` от 14 МГц, `CTH` 0..55 (64 мкс), `SINC_H` = `CTH` 52..55 (4,57 мкс); `CTV` 320 или 312 строк (`T320`), `SINC_V` 4 строки (:171-245). **Синхроимпульсы на монитор даёт MAX**, ACEX подгоняет свои счётчики под `SINC_1` / `SINC_2` с поправкой `HOLD`.
- Загрузка конфигурации ACEX (:265-266, 318-324): `CNF_OFF` = асинхронный RS-триггер (установка `/RESET`, сброс `XACS`); в режиме загрузки `10K_CLK = WR_CNF`, `10K_D0 = D0`.
- ВГ93: такт `CLK_WG` 1 МГц (720 КБ) или 2 МГц (1,44 МБ, и на время шагов головки — `TURBING`), цифровой сепаратор данных `WGR` / `RDAT_X` / `FDAT` / `QDAT` (:270-309), предкомпенсация записи `REG_P` / `LR_T` (:332-355).
- Декодер управляющего слова с шины `MA` (защёлка вне ПЛИС, строб `WR_AWG`; :391-467): стробы ВГ93, CMOS, IDE, переключатели 720 / 1440, HDD1 / HDD2, 312 / 320, мягкий сброс (= перезагрузка ACEX). `10K_D0` в рабочем режиме служит флагом `FDD_1440` (:324, 398).

Параметры: `G_MODE`, `NUM`, `NUMBER1..7` (при `NUM = "YES"` в кадре сдвигались бы строки — мёртвое).

### 1.9 Сравнение с копиями MaxPlus2

`MaxPlus2/MAX` — побайтно то же. В `MaxPlus2/ACEX` (кроме пробелов и кодировки CP866 комментариев AY):

- TDF: в Quartus2 закомментированы неиспользуемые узлы (`DMD`, `T_SIGNAL`, `RED/GREEN/BLUE`, `MDR`, `ISA_CASH`, `ROM_WRITE_MODE` в SP2_ACEX; `AY_CLK1`, `AY_ADRX` в AY), добавлены пометки `-- not used ?`; `AY:294` исправлен `AY_GF` → `AY_GF[]`; **DCP:138 `STARTING : NODE` → `SOFT` + `DEFAULTS STARTING = VCC` (:221-223)** — комбинационная петля оформлена иначе. Логика та же.
- ACF: только настройки компилятора.
- MIF: адреса переведены HEX → DEC **с ошибками** — п. 6.1.

`Other/UNUSED` — старые варианты (`DCP2`, `DC_PORT2`, `CONSOLE`, `DATA_MUX` …), в сборку не входят.

## 2. Опасные для XST места

### 2.2 Асинхронные `clrn` / `prn`, не являющиеся простым сбросом

Простой сброс (`/RESET`, `/RES`, `DECODE./RES`) не перечисляю. Остальное:

*Загрузка счётчика по асинхронному входу*

- VIDEO2:260-278 — `CT5`, `CTH` = 50 (0x32), `CTV` = 290 (0x122) по `COPY_SINC_H` / `COPY_SINC_V` (подстройка под MAX).
- SP2_ACEX:562 — `SOFT_RES[].prn` (запуск сброса 3 → 0).
- DCP:548 — `WT_CT[].prn = MC_END`.
- KBD:71 — `KB_CT[].prn = DFF(KBD_CC)` (пока CLK клавиатуры в нуле, таймаут кадра = 7).
- MOUSE:35 — `CT[].clrn = MOUSE_IMP` (подстройка фазы бита по фронту `MOUSE_D`).
- SP2_ACEX:1115 — `CBL_CNT[].clrn = CBL_MODE`; :1131-1134 — `CBL_WA` очищается / ставится по `CBL_MODE`, `CBL_INT_ENA`, `CBL_INT`, `CBL_CNT7`.

*Самосбрасывающиеся импульсы (длина = задержка петли)*

- VIDEO2:625-627 — `V_WE_R = DFF(GND, !CLK42, , !V_WE)` → `V_WE.prn`: импульс записи видео-ОЗУ в полтакта.
- VIDEO2:448 — `V_CST0` (мёртвое).
- DCP:300 — `WR_AWGX` (`prn = DFF(WR_AWGX)`).
- ACCELER:271 — `ACC_MODE3.clrn = !DFF(ACC_MODE3, CLK_Z80)`: импульс на один такт Z80.
- SP2_ACEX:621 — `XACS.prn = XACS or (!/MR & ROM_RG4)`.
- SP2_ACEX:744 — `INT_X.prn`: снятие по INTA (`/IO`, `/M1`) или через 2 периода `CTH2` (~18 мкс).
- DCP:529 — `HDD_FLIP.clrn` через триггер на `!DOUBLE_CAS` с `prn = HDD_FLIP`.
- SP2_ACEX:1126 — `CBL_WAE`, `prn = CBL_INT`.

*«Anti gluk»: защёлка на спаде строба, отпускание при его снятии*

- DCP:491 `MEM_RW`, :492 `IO_RWM` (`prn = LCELL(Q or !/strobe)`).
- SP2_ACEX:598-600 `CS_ISA`, `CS_ROMT`, `CS_CASHT` — то же.
- DCP:494 — `IO_RW.prn = /M1`; :535 — `/IOM.prn = !/IO & /M1`; :444, 449 — `MC_BEGIN.prn`, `MC_END.clrn = !(/MR & /IO)`; :439 — `prn = !/IO` в синхронизаторе `IO_RW`; SP2_ACEX:310-311 — `/IOWR`, `/IORD` `prn = !/IO`; ACCELER:179 — `IN_OUT_CMD.clrn = /IO`; ACCELER:184 — `ACC_GO.prn = !/MR & /M1`; ACCELER:243 — `ACC_END.prn = /M1`; DCP:724 — `MEM_WR.clrn = !/IO`.

*Маскирование данных асинхронным сбросом*

- AY:120-126 — `BD[7..4]` очищаются по номеру регистра (`AY_ADR`): неиспользуемые биты регистров тона / шума.
- ACCELER:181-182 — `DO[4..3].clrn = !CORRECT_1F`: подмена операнда `1F` → `07` у `IN A,(n)` / `OUT (n),A` (п. 4.5).
- VIDEO2:593 — `DCOL.clrn = !BLANK`; :614-615 — `RBRVA` по `!BORD`; :596-597 — `BRVA` по курсору мыши (константы).
- AY:252-253 — `AY_DQX` очищается / ставится (шум, бипер в канал); AY:198-199 — `AY_CX`, `AY_CXX.prn` из регистров; AY:155, 273-274 — `AY_F_RES` (`clrn = AY_F_R1`), `AY_VA` / `AY_VX` / `AY_VAR` (`clrn = AY_F_RES`).
- DCP:669 — `SC.clrn = /RESET & !CNF6` (Scorpion выключен); :671-672 — `PN[5..0].clrn = /RESET & !CNF5`, `PN[7..5].clrn = /RESET & CNF7` (п. 6.4: `PN5` назначен дважды).
- DCP:626, 634 — `DCPP`, `DD.clrn = MC_END & DCP_RES`; DCP:513, 521 — `/IOMY`, `/IOMZ.prn = PORTS_X`; DCP:463 — `RFT.prn = RFC`; DCP:539 — `prn = NO_IO_WAIT`.
- SP2_ACEX:569 — `SYS_PG.prn = !ROM_RG4`; :588 — `clrn = !WAIT_ROMX`; :792-793 — `SINC_1/2.clrn = /RES`; :827-830 — `HOLD` ставится в 0x77 по `/RES`; :1073 — `CBL_INT.prn`; :1121 — `clrn = CBL_INT_ENA & ACC_DIR1`; :1142 — `CBD.clrn = CBL_MODE16`.
- VIDEO2:371 — `MXWE`: `clrn = E_WR` (комбинационный!), `prn = V_WE`.
- VIDEO2:649-652 — `V_EN.clrn = F_WR` (только при старте).
- KBD:65 — `INT.prn = INT_ENA`; :109, 114 — `KB_F12`, `KB_RESET.prn` от `KB_CT == 1`; :134 — `KB_MA.clrn = !DFF(/IO)`; :149 — `KDD[7..6].prn = !KB_CT2`; :172 — `KBD.prn` от триггера с `clrn = !/IO & ENA`.
- SP2_MAX:154 — `/RESET.clrn = SOFT_RESET` (комбинационный дешифратор входов `HDD_C` / `FDD_C`!); :265 — `CNF_OFF`; :324 — `10K_D0` `clrn = S720`, `prn = S144 & /RESET`; :426-432 — `prn = FDD_C2`; :454-455 — `prn = HDD_C0`.

Не перевожу как «простой сброс» и `/RES` (DCP:260, `DFFE(VCC, CLK42, , , CT0)`): это импульс по включению. Quartus его выбросил как «stuck at VCC» (`SP2_ACEX.map.rpt`, Registers Removed), то есть в Quartus-сборке его нет, в MAX+PLUS II — вероятно, был.

### 2.3 LCELL / EXP: задержки, фильтры, формирователи

- Формирователи импульсов на цепочках LCELL: VIDEO2:638-647 (`V_WEMMM` → `V_WEMMN` → `V_WEMMO` → `V_WEMM`; `V_WR` = И двух задержек = /WE видео-ОЗУ, `V_WEN` = И трёх = окно выдачи `VD`, на одну задержку длиннее /WE — удержание данных); VIDEO2:452-455 `V_CSX` (мёртвое); удвоители `CLK84` DCP:266, VIDEO2:669 (мёртвые).
- Задержка такта: VIDEO2:539 `LWR_MODE = LCELL(LCELL(WR_MODE))` — данные `VD` ловятся чуть позже фронта `WR_MODE`.
- Задержка адреса до CAS: SP2_ACEX:859-868 `CAS_A = LCELL(DECODE.CAS)`, `CASX_` — LCELL поверх. `MA` меняется тем же фронтом, что и `CAS` (п. 3.3), — установку адреса дают задержки LCELL.
- «anti gluk»: DCP:490-492 (комментарий), SP2_ACEX:598-600 — см. п. 2.2.
- `T_RDXA = LCELL(RDXA)` (SP2_ACEX:762) — буфер такта; `WR_TM9 = LCELL(CT2)` (:765) — разрешение `TRI`.
- Остальные `LCELL(...)` в выражениях (`LCELL(MEM.q[7..4] == B"0101")` и т. п.) — разбиение логики на ячейки, функционально провод.
- MAX: `EXP` — инверсия в расширителе произведений. `EXP_X`, `EXP_Y` (:158-159) не используются (`G_MODE = 1`). Остальные — части петель (п. 2.5) и логики.

### 2.4 TRI / OPNDRN

Все на выводах, внутри ядра станут мультиплексорами:

- SP2_ACEX:296 `/RESET = TRI(GND, …)`, :903 `/WAIT = TRI(/WAIT_ALL, LCELL(!/WAIT_ALL))` — открытый сток (тянет только в 0).
- SP2_ACEX:417-426 — `D`, `VD0..3`, `MD[15..0]`; :780-783 — `XA[3..0]` (выдача при `WR_TM9`, `XA3` никогда).
- SP2_MAX:187-188 `SINC_1/2 = TRI(…, VCC)` (просто выход), :257 `CLKZZ = TRI(XCT1, CNF_OFF)`, :318 `/CONF_X = OPNDRN(/RESET)`.

### 2.5 Комбинационные петли и защёлки

- DCP:715 `STARTING = LCELL(/RESET & (STARTING or !(/IO or /RD)))` — защёлка: 0 при сбросе, 1 после первого `IN`. Quartus: «Found combinational loop of 1 nodes `dcp:DECODE|$00055`» (`SP2_ACEX.tan.rpt:2048`).
- SP2_MAX:272 `TURBING` — RS-защёлка: ставится `STE` или режимом 1,44, снимается `WSTB` / `RSTB`.
- SP2_MAX:307 `RDAT_X` — ловушка импульса `RDAT` до `CT_WG1`.
- SP2_MAX:406-407 `T320` / `NT320` — RS на двух `EXP`.
- SP2_MAX:417-419 `THDD` / `NTHDD` / `NO_HDD` — защёлка из трёх `EXP`.
- SP2_MAX:265 `CNF_OFF` — RS-триггер на асинхронных входах DFF (петли нет, но поведение то же).

## 3. Временная сетка

### 3.1 Счётчики

- `CT[2..0]` (VIDEO2:284-294): 0 → 1 → 2 → 4 → 5 → 6 → 0, шесть состояний = 7 МГц (142,9 нс), значений 3 и 7 нет. Дальше называю их «фазы» 0, 1, 2, 4, 5, 6.
- `CT[5..3]` (:297-298): +1 при выходе из фазы 6 (разрешение `DFF(CT0 & CT2)` от фазы 5). `CT[5..0]` — 8 × 6 = 48 тактов = 8 точек 7 МГц.
- `CTH` 0..55 (:307, 310-314): +1 раз в 48 тактов → 2688 тактов = 64 мкс, 448 точек 7 МГц на строку.
- `CTV` 0..319 (:308, 316-320): +1 в конце строки при `CTH == 48`. Длину 312 задаёт MAX (`T320`), ACEX подстраивается сбросом `CTV` в 290 по `COPY_SINC_V`.
- `CTF` (:322-323): +1 по `CTV8` — счётчик кадров.
- MAX (SP2_MAX:171-245): своя пара `CTH` (0..55 от 875 кГц) / `CTV`. ACEX сравнивает фазу (`SINC_HOLD`, `HOLD` — порт CB), так что положение картинки относительно синхро задаётся программно.

Из `CT[1..0]`: `CLK21 = DFF(!CT0 xor CT2)` (DCP:281) — 1 в фазах 1, 4, 6 (21 МГц); `CLK_Z80` (DCP:277) — 21 МГц в турбо, иначе `TFF` на фазе 2 → 3,5 МГц; один 7-МГц цикл = 3 такта Z80 в турбо.

### 3.2 Видео-ОЗУ: шесть слотов на цикл 7 МГц

`VCM` (VIDEO2:399-406) — регистр от фазы `CT`; `VLA` (:408-442) — регистр от `VCM`; `VA = VLA[17..2]` (слово 32 бита), `VLA[1..0]` — байт. На выводах адрес держится один такт 42 МГц (23,8 нс), то есть **каждый такт — новое 32-битное обращение**.

| Фаза `CT` в такте n | `VCM` в n+1 | Адрес на `VA` в n+2 | Обращение | Захват данных | Что используется |
|---|---|---|---|---|---|
| 4 | 2 | `VXA` (адрес записи ЦПУ) | **запись** ЦПУ / ускорителя, если `MXWE` (:430-434) | — | 1 байт (или 2 при `DOUBLE_CAS`, `V_EN`, :649-652) |
| 5 | 0 | `BRVA[7..0], 11111, RBRVA[10..8], 00` | чтение **палитры**, `WR_COL` = 0 (`TSN_W3`, :410-421) | вне ACEX: защёлка ЦАП по `WR_COL` (выведено, не подтверждено схемой) | всё слово идёт мимо ACEX |
| 6 | 5 | `SVA` = адрес точек (`RSVA` ветка «pic») | чтение **точек**, `WR_PIC` (:422-424) | `D_PICx_` по спаду в n+3, байт по `DFF(VLA[1..0])` (:523-528) | 1 байт → `D_PIC0`, только при `LD_PIC` (:501, 575-580): раз в 8 (или 4) циклов |
| 0 | 1 | `SVA` = адрес атрибутов (ветка «atr»); в графике тот же адрес, что у точек | чтение **атрибута / цвета**, `WR_COL` (:422-425) | то же | 1 байт → `DCOL` каждый цикл (:582-591) |
| 1 | 4 | палитра, как в фазе 5 | чтение **палитры**, `WR_COL` = 0 | вне ACEX | вторая точка цикла (14 МГц) |
| 2 | 3 | `DIR_PORT3, CTH[5..0], CT5, 11, CTV[8..3], 00` | чтение **таблицы режимов** (:435-441) | `MODE0..2` по `LWR_MODE` прямо с `VD3..VD1` (:533-538) | 3 байта, только при `WR_MODE`: раз в 48 тактов (`CT[5..3] == 7`) или дважды (ещё `CT[4..3] == 3`, если `!MODE0[5]`) (:438) |

Итого на 8 точек ZX (48 тактов): 48 обращений по 32 бита (16 палитра, 8 точки, 8 атрибуты, 8 таблица режимов, 8 записи). **Используется из этого**: точки 1-8 байт, атрибуты / цвет 8 байт, таблица режимов 3-6 байт, палитра 16 слов (выход наружу), записи — сколько было (не больше одной на 6 тактов).

Ещё о видео:

- 256 цветов: `BRVA = DCOL` (:600-604), одна точка на 6 тактов (7 МГц), обе палитры цикла — одна точка. 16 цветов (`MODE0[4] | MODE0[5] = 0`): по `CT2` старшая / младшая тетрада — две точки (14 МГц). ZX: `DCOL` = атрибут, `RBRVA = (1, FLASH & !BLANK, D_PIC0[7])` (:609-612) — **цвета ZX тоже через палитру**: банк палитры выбирают мигание и бит точки.
- Палитра в видео-ОЗУ: индекс → `VLA[17..10]`, банк → `VLA[4..2]`, область `VLA[9..5] = 11111` (байты 0x3E0-0x3FF каждой 1024-байтной строки). 256 × 8 слов.
- Таблица режимов: `VLA[17]` — страница (`RGMOD0`), `[16..11]` = `CTH`, `[10]` = `CT5`, `[9..8] = 11`, `[7..2]` = `CTV[8..3]`. `MODE0`: [3..0] → `SVA[9..6]`, [4] ZX / графика, [5] ширина, [7..6] смещение ZX, `[7..4] = 15` — бордюр (цвет из `BORDER`); `BORD & MODE0[3] & MODE0[2]` → `BLANK`, плюс `MODE0[0]` → `INTTX` → **кадровое INT там, где его поставила таблица режимов** (:390-394). `MODE1` → `SVA[17..13]` и строки, `MODE2` → адрес атрибутов и удвоение строк (`M_CTV`, `M_CT`, :469-470).
- Запись: `SVIDEO.wr` (SP2_ACEX:987) = запись DRAM (`MC_WRITE = 0`, `CAS = 0`, не `GLISSER`) → `E_WR` (спад, если адрес графический `VAI19` или экран ZX `ZX_SCREEN`, VIDEO2:366) → `VXA` / `VXD` защёлкнуты, `MXWE` ждёт слота фазы 4. Данные — копия того, что пишется в DRAM (`MDI = ACC.MDO`). Скорость записи совпадает со скоростью DRAM (≤ 1 на 6 тактов).
- **Чтения видео-ОЗУ процессором нет**: `VD` идут только в VIDEO2. ЦПУ читает копию из DRAM; страницы 0x54-0x57, 0x5C-0x5F пишутся только в видео-ОЗУ (`BLK_MR`, SP2_ACEX:967-968), страницы 0x58-0x5B с `GLISSER` не пишут байт FF (прозрачность).
- Адрес ZX-записи (VIDEO2:383): `VXA = (0, 0, A[7..0], ZXS[4..1], ZXS0 ^ ZXA15 ^ A13, A[12..8])`, байт = `A[9..8]`. Графика (:380): `VXA = VAI = (GRAF, GA[8..0], AO[9..0])`, при `GRAF = 1` `GA = (1, G_LINE[8..0])` (DCP:344-348): строка 1024 байта, Y — из `AGR` (порт C4 / ускоритель), а `A[13..10]` не участвуют.

### 3.3 Цикл DRAM на той же оси

(DCP:439-480; `MC_TYPE`, `RAS`, `CAS` активны нулём.)

| Фаза | 6 | 0 | 1 | 2 | 4 | 5 |
|---|---|---|---|---|---|---|
| Решение | `MC_BEGIN`, `MC_TYPE`, `MC_WRITE`, `RFC`, `MCA` | | | | | `MC_END` |
| `MA` | ← строка | строка | строка → столбец | столбец | столбец → управляющее слово | слово |
| `MA_CT` | 0 | 1 | 1 | 2 | 2 | 0 |
| ЦПУ (`MC_TYPE = 0`): `RAS` | | | 0 | 0 | 0 | |
| ЦПУ: `CAS` | | | | 0 | 0 | 0 |
| Регенерация CBR (`MC_TYPE = 1`, `RFC = 0`): `CAS` | | | 0 | 0 | 0 | |
| CBR: `RAS` | | | | 0 | 0 | 0 |

- В каждом 7-МГц цикле — одно обращение к DRAM: ЦПУ, ускоритель, чтение таблицы портов (п. 4.1) или регенерация CBR. Регенерация отложенная: запрос раз в 24 такта (`RFT` по `CT4`), выполняется в цикле без запроса ЦПУ (`RFC`, :466-469). Во время работы ускорителя её нет.
- `MA` (DCP:284-380): строка — в фазах 0-1, столбец — 2-4, в фазах 5-6 на `MA` **управляющее слово для периферии** (`WR_TM9` → `WR_AWG`, :300-305) — та же шина ведёт защёлку на плате и входы `HDD_C` / `FDD_C` у MAX.
- `MC_END` ставится в фазе 5, если `CONTINUE` (ускоритель не продолжает), сбрасывается вместе с `MC_BEGIN` асинхронно, когда сняты `/MR` и `/IO`.
- Данные к ЦПУ: `DO` по спаду в фазе 6 (ACCELER:312), после подъёма `CAS`; запись: `MDO` держится, пока `CAS = 0` (ACCELER:290-292).

### 3.4 Ожидания (`/WAIT`)

`/WAIT_ALL = DECODE./WAIT & WAIT_ROM & WAIT_ORIG` (SP2_ACEX:899), открытый сток.

- `/MR_WAIT` (DCP:486): `MC_END or MEM_RW or (!TURBO & !ACC_ON)` — в турбо (или с включённым ускорителем) ЦПУ ждёт конца цикла DRAM. Запрос попадает на ближайшую фазу 6, доступ — фазы 0-5: 6-12 тактов 42 МГц от спада `/MR` (143-286 нс) при такте Z80 47,6 нс. В режиме 3,5 МГц ожиданий памяти нет.
- `/IO_WAIT` (DCP:539-554): `WT_CT` загружается из `W_TAB` по `(TURBO, TYPE[2..0])` (:556-567) и считает вниз на `CLK21` (такты 21 МГц): без турбо 2, 2, 1, 1, 1, 2, 7, 10; в турбо 2, 2, 4, 4, 7, 7, 7, 10 для `TYPE` 0..7. Плюс сам цикл DRAM для дескриптора. `NO_IO_WAIT` (:541) снимает ожидание для портов `A[7..0] = 111xx1xx` в режиме 3,5 МГц и TR-DOS выключенном (`DOS = 1`).
- `WAIT_ROM` (SP2_ACEX:587-596): обращение к ROM или ISA → `WT_R` 4 → 0, около 5 тактов 42 МГц.
- `WAIT_ORIG` (:558-559): «оригинальные» ожидания для совместимости — без турбо, если `ALL_MODE2 = 0`, обращение к окну 1 или к окну 3 со страницей с `PN2` ждёт, пока `CT5 = 0` (половина каждых 48 тактов).

### 3.5 Что это значит для нашей памяти

16-битная SRAM на 84 МГц — 12 обращений по 16 бит на 7-МГц цикл; оригинал делает 6 по 32 бита, ровно столько же. Но используемых данных меньше: точки 1 байт, атрибут 1 байт, запись 1-2 байта, таблица режимов 3 байта раз в 8 (4) циклов. Предложение для Ф0.5: палитру держать в BRAM (2048 × 24…32 бит, 3-4 RAMB16, заполняется подглядыванием записей в область `VXA[9..5] = 11111`), из SRAM читать только точки, атрибут и таблицу режимов. Тогда видео занимает 3-5 из 12 слотов, остальное — ROM и fastram. Каждое обращение ЦПУ к порту — ещё и чтение SDRAM (дескриптор): либо держать страницу 0x40 копией в BRAM (16 КБ = 8 RAMB16), либо закладывать это чтение в расписание SDRAM.

## 4. Карта ввода-вывода и памяти

### 4.1 Дешифратор портов: два уровня

1. **Таблица дескрипторов в DRAM.** Цикл ввода-вывода запускает обычный цикл DRAM (`MC_RQ` по `IO_RW`, DCP:439) с адресом из `X_ADR` (DCP:350-355). Строка: `(0, CNF4, PN5, DOS, /WR, A15, A14, A6, A5, A13, A7, A2)`, столбец: `(0, 0, CNF4, CNF3, 0x40)`, байт — `MCA = A[1..0]`. Если сопоставить с раскладкой обычного адреса памяти (строка `0, A13, A11, A10, A9..A2`, столбец `0, 0, A13, A12, страница[7..0]`), это **страница 0x40, смещение** `{CNF4, CNF3, PN5, DOS, /WR (1 — чтение), A15, A14, A6, A5, A13, A7, A2, A1, A0}` — 16 КБ, 4 карты портов по `CNF[4..3]`, отдельно чтение / запись, TR-DOS и `PN5`. Та же формула в MAME (`sprinter.cpp:584, 706`, `m_dcp_location = RAM + (0x40 << 14)`, :1531). Таблицу заполняет BIOS: после сброса, пока `STARTING = 0`, окно 3 показывает `MEM[0] = 0x1040`, то есть страницу 0x40 (DCP:718-722, DCP.MIF:14).
2. **`MEM` 256×16.** Прочитанный байт `MD` → `DCPP` (DCP:624-627) и `DD` (:632-639; если `MD[7..4] = F`, вместо него `11_PG3` — запись текущей страницы окна 3) → `PGS` (:717-722) → `MEM.q` → `TYPE` = `q[15..12]`, `PAGE` = `q[11..0]`. Сам `DCPP` сравнивается в верху с константами (регистры портов, п. 1.1).

Пока `STARTING = 0` (до первого `IN` после сброса), `DCPP` и `DD` держатся в нуле (`DCP_RES`, :622) и `MEM` не пишется (:724).

### 4.2 Слово `MEM`

| `TYPE` (`q[15..12]`) | Чтение (`PDD`, SP2_ACEX:386-400) | Где в `DCP.MIF` |
|---|---|---|
| 1 | FF (`TYPE[2..1] = 00`) | все 00-7F по умолчанию |
| 2 | `q[7..0]` (`DECODE.DO`) — читаемые «копии» | 88, 89, 8D-8F, 92-9F, B0-BF, C0-FF |
| 3 | данные AY (`AY3.DO`) | 52, 8C, 90, 91 |
| 4 | клавиатура / магнитофон (`KEY/KEMS`; в режиме CBL бит 7 = `CBL_IND`, бит 5 = `CTV8`) | 40 |
| 5 | Kempston-мышь (`KEMPS`) | 58 |
| 6 | IDE: `MDP` = `MD[7..0]` или `HDDR` | 20-29 |
| 7 | системные (ВГ93, CMOS, 720 / 1440, HDD1 / 2, 312 / 320, мягкий сброс, ISA): `MD[15..8]`; `RD_KMPS` | 10-17, 1C-1E, 2A-33 |
| C | клавиатура (как неполная дешифрация FE) | 80-FF по умолчанию |

ACEX не ведёт `D` при `DCPP[7..4] = 0` или 3 (SP2_ACEX:408): там данные даёт внешнее устройство или их нет. `TYPE[2..0]` ещё и выбирает число тактов ожидания (п. 3.4).

`PAGE[11..0]`:

- Для страниц памяти (`MEM` C0-FF): `q[7..0]` — номер страницы DRAM (256 × 16 КБ = 4 МБ). `q[7..4] = 0101` — графическая страница (`GRAF`, DCP:607-613; `VIDEO_PG`, SP2_ACEX:966); `q2`, `q3` — только видео-ОЗУ / прозрачность (:967-970); `q[7..4] = A` в окне 3 при `SC4` — запуск мягкого сброса при записи (:562); `q[7..0] = FD` — запись ускорителем в FIFO CBL (:1122).
- Для системных портов (типы 6, 7) — **управляющее слово на `MA`** в фазах 5-6 (DCP:369-378): `MA[11..9] = HDD_A` (номер регистра IDE из адреса, :386-404), `[8..6] = q[8..6]`, `[5..4] = q[5..4]` со стробами `/IOMZ`, `/IOMY`, `[3] = /WR`, `[2] = q2`, `[1..0] = A[6..5]`. Расклад битов — комментарий `DCP.MIF:16-31`: 0-1 `WG_A5/6`, 2 мультиплексор КП11 (0 ВГ93 / CMOS, 1 Kempston / ТМ9), 3 чтение / запись, 4 `CS_WG93` или `WR_TM9`, 5 строб HDD / CMOS, 6-7 группа (00 FDD / экран, 01 HDD / сброс, 10 HDD1 / 2, 11 CMOS), 8 `CS1` / `CS3` или данные / адрес CMOS, 9-11 `HDD_A`. MAX видит это как `FDD_C = MA[4..2]`, `HDD_C = MA[8..5]` (SP2_MAX:374-389).
- `q[11..8] = 0` при `q[7..5] = 101` — регистр данных IDE (`HDD_DATA`, `HDD_FLIP` — 16-битный обмен через `HDDR`, DCP:523-529).

Запись `MEM` (DCP:724): `OUT` в порт с дескриптором ≥ C0 пишет `D` в младший байт `MEM[PGS]`; старший (тип) переписывается сам собой. Отсюда: порты страниц — дескрипторы E9 / EA (окна 1, 2), E0-EF (варианты окна 0), D0-DF / F0-FF (перевод страниц 7FFD в страницы DRAM); порты C0-CF («SYS PORTS COPYES») читаются как последнее записанное значение.

### 4.3 Окна памяти и регистры страниц

`PGS` для памяти (`/IO = 1`): `11_MPGS[5..0]` (DCP:706-712, 718-719):

| `A[15..14]` | `MPGS` | Запись `MEM` | По MIF |
|---|---|---|---|
| 0 | `PG0` = `10_abcd` | E0-EF | E0-E7, EB, EF = 2041; E8, ED, EE = 2000; E9 = 2005; EA = 2002; EC = 20FF |
| 1 | `101001` | E9 | страница 5 |
| 2 | `101010` | EA | страница 2 |
| 3 | `PG3` = `(!PN7, 1, x, PN[2..0])` | D0-DF или F0-FF | F0-FF = страницы 00-0F, D0-DF = 10-1F |

- `PG3[3]` (DCP:682) = `SC4 & !CNF7` (Scorpion 1FFD бит 4) или `PN6 & CNF7` (Pentagon-512), `PG3[5] = !PN7`.
- `PG0` (DCP:685-696): `a = SC0 | !SYS | CASH_ON`, `b = AROM16 & !(SC0 & SYS) | CASH_ON`, `c / d = SPR_[1..0] & SC_LCELL | !SYS`; `SPR_ = !SC1 & (DOS, PN4 | !DOS)` — «расширение / DOS / BASIC128 / BASIC48». `NMI_ENA = VCC`, `CASH_ON = GND` при `UPDATE = 1` (:585-587).
- Регистры DCP (:643-672), запись по `/IOWR` DCP: `SC` (дескриптор C0 / C8, порт 1FFD), `PN` (C1 / C9, 7FFD), по C6 / CE: `CNF` (если `DI2`), `AROM16` (если `!DI1`, = `DI0`), `TB_SW` (если `DI1`, = `DI0`, турбо), `SYS = !A6`.
- `DOS` (SP2_ACEX:836-838): включается выборкой опкода из 3Dxx при `PN4 = 1`, выключается выборкой выше 3FFF — Beta 128. Активный уровень 0.
- `SCR128 = PN3` (экран 5 / 7), `V_RAM = PN2` (для `WAIT_ORIG`).

### 4.4 ROM, кеш, ISA (`UPDATE = 1`)

SP2_ACEX:545-639:

- `/SYS` (порты 3C / 7C, `A6`) — системное ПЗУ в окне 0; `SYS_PG` (`D0`, если `!D1`) — ПЗУ 0 / 1; `ROM_RG` (дескриптор 8F, или порт 5C при `/SYS = 0`): `[3..0]` страница ПЗУ, `[4]` — запись во флеш (`XACS`).
- `CASH_ON` — `IN A,(FB)` / `IN A,(7B)`, бит `A7`: в окне 0 вместо ПЗУ кеш (fastram, `CS_CASH`, `RA = 01_ROM_RG[1..0]`).
- ISA: `ISA_PORT` (дескрипторы Fx) = `1101xxxx` и `BLK_R` (`SC4`) → окно 3 на слот ISA; `ISA_A20` — порт 1B.
- `CS_ROM`, `CS_CASH`, `CS_ISA` защёлкиваются на спаде `/MR` (:598-600); `BLK_MEM` запрещает DRAM, `RD_RAM` разрешает ACEX вести `D`.
- `RA[17..14]` (:611-617): ПЗУ `(ROM_RG3 ^ !SYS_PG, ROM_RG[2..0])`, кеш `01_ROM_RG[1..0]`, ISA `(!PRE_ISA, 0, ISA_PORT[2..1])`.

### 4.5 Ускоритель (ACCELER)

- Включение: опкод `LD r,r` с одинаковыми регистрами в M1 без префикса (ACCELER:261-269): `ACC_MODE = (1, r)`.

| Опкод | `r` | `ACC_DIR` | Режим (:248-257) |
|---|---|---|---|
| 40 `LD B,B` | 0 | 00000000 | выключить |
| 49 `LD C,C` | 1 | 00100101 | заливка константой |
| 52 `LD D,D` | 2 | 00001001 | загрузить счётчик |
| 5B `LD E,E` | 3 | 00010101 | заливка по вертикали |
| 64 `LD H,H` | 4 | 01000001 | двухбайтные операции |
| 6D `LD L,L` | 5 | 00100111 | копирование строки |
| 76 `HALT` | 6 | 00000000 | (ничего) |
| 7F `LD A,A` | 7 | 00010111 | копирование по вертикали |

  Биты `ACC_DIR`: 0 включён (`ACC_ON`), 1 работа через буфер `RAM`, 2 считать `ACC_CNT`, 3 загрузить `RGACC` из следующего обращения, 4 вертикаль (+1 к `AGR` = `G_LINE`), 5 горизонталь (+1 к `AA`), 6 два байта (`DOUBLE_CAS`).
- Запуск: следующее после `LD r,r` обращение к памяти (не M1, не регенерация) — `START_ACC = 0` (:237; имя инвертировано: 0 = «старт»). Адрес `AA` ← `AI`, дальше `AA + 1` / `AGR + 1` каждый цикл DRAM; `CONTINUE = ACC_END` держит `MC_END` в нуле, ЦПУ стоит в `/WAIT`, пока `ACC_CNT` не дойдёт до 1 (:241-246). Темп — одно обращение на 7-МГц цикл.
- Буфер `RAM` 256×8: при копировании чтение пишет строку в буфер (`RAM_WR`, :347), запись берёт из буфера; `FN_ACC` (опкоды `BE` / `B6` / `AE` / `A6` = `CP / OR / XOR / AND (HL)`, :320-337) — операция над буфером при чтении.
- `GLISSER` (:282-287): байт FF не пишется в страницы прозрачности (п. 3.2).
- `AGR` (`G_LINE`) — порт C4 / CC; `AAGR` / `XCNT` / `XAGR` — порт C7 / CF (`ALT_ACC`, второй адресатор буфера).
- Защита от прерываний `ACC_BLK` (:164-166): INTA ставит блокировку, `RETI` снимает. См. п. 6.5.
- **Подмена операнда порта 1F** (:176-182): после опкода `IN A,(n)` / `OUT (n),A` (D3 / DB без префикса) байт `n = 1F`, прочитанный из DRAM, отдаётся процессору как `07` (сброс битов 4, 3). MAME делает `1F → 0F` и только для ОЗУ (`sprinter.cpp:1009-1014`) — расхождение, п. 6.
- `STATE_EI`, `RETN`, `CB_CMD`, `ID_CMD`, `ACC_DIR` наружу (`ACC_DIR1` — CBL): декодируются, но частью не используются.

### 4.6 CBL (SP2_ACEX:1066-1166)

- `CBL_XX` (дескриптор 89): бит 7 — режим FIFO, 6 — стерео, 5 — 16 бит, 4 — прерывание, [3..0] — частота (`CBL_TAB`: 218,75 кГц / (N + 1): 7,8125 … 109,375 кГц; 0, 1 — 16 / 22 кГц).
- FIFO — `CBL` 256×16. Запись: порт с дескриптором 88 (`CBL_WR`) или ускоритель в страницу FD при `CBL_INT_ENA & ACC_DIR1` (:1121-1123). Адрес записи: с прерыванием — указатель `CBL_WA`, без — `!A[15..8] ^ CBL_WA` (`OUT (C),A`, индекс в `B`). 16 бит — два обращения (`CBL_WAE`, младший байт в `CBD`), старший бит инвертируется (знак). Данные — с `ACC.MDO`, то есть с шины `D` через ускоритель.
- Чтение: `CBL_CNT` +1 (моно) / +2 (стерео) на шаге частоты; `CBL_IND` = полнота (`CBL_CNT7 ^ CBL_WA7`); прерывание `CBL_INT` на спаде `CBL_CNT6` (каждые полбуфера), снимается INTA.
- Без режима FIFO `CBL_R = (D, 00)` при записи в порт 88 — 8-битный Covox.
- Выход: `AY_CHS = AY + CBL_R[15..5]` → `AUDIO_R` → I2S: `DAC_BCK = CT2` (7 МГц), `DAC_WS = CTH1` (218,75 кГц), 16 бит на канал (:1047-1064, 1187-1203).

### 4.7 Режимы совместимости

- `CNF[4..3]` — одна из четырёх карт портов в таблице DRAM.
- `CNF5` — сброс `PN[5..0]`; `CNF6` — Scorpion выключен (`SC = 0`); `CNF7` — Pentagon-512 (`PN[7..6]` в номере страницы). Точная логика `PN5` — п. 6.4.
- `ALL_MODE0` — клавиатура «все клавиши» (`KEYS.ena = 0`) с INT по клавише, разрешение ускорителя; `ALL_MODE2` — без «оригинальных» ожиданий.
- `TB_SW & TURBO_HAND` — турбо (F12 переключает `TURBO_HAND`, SP2_ACEX:521-523).
- `NO_IO_WAIT`, `WAIT_ORIG` — п. 3.4.

## 5. Правила перевода

### 5.1 Модули и имена

- Один модуль Verilog на подпроект AHDL: `sp2_acex`, `dcp`, `video2`, `acceler`, `ay`, `kbd`, `mouse`, `sp2_max`; над ними наш верх. Имена сигналов — как в AHDL: `/X` → `X_n`, `/` внутри имени (`KEY/KEMS`) → `_`, `$`-узлов нет. Комментарий `// AHDL DCP.TDF:491` у неочевидных мест; наши правки — `// karabas:`.
- Мёртвое (помечено в п. 2) не переводим, но упоминаем в комментарии со ссылкой на строку.
- `INCLUDE`-ные `lpm_counter` / `lpm_add_sub` — обычная арифметика.

### 5.2 Один такт 84 МГц с разрешениями

Рекомендую **`clk84` (2 × 42 МГц) для всего ядра**: `ce42` — каждый второй такт (передний фронт `CLK42`), `ce42n` — промежуточный (задний фронт). Почему не 42 МГц с разрешениями:

- 11 мест с триггерами на `!CLK42` (п. 2.1), среди них захват данных видео-ОЗУ, `PGS`, `MC_RQ`, `CLK_Z80`. На 84 МГц у них своя фаза, поведение по тактам сохраняется; на 42 МГц их пришлось бы сдвигать на полтакта.
- Полутактовые импульсы (`V_WE`, `V_WE_R`) и окна LCELL (`V_WR` / `V_WEN`, `CAS_A`) ложатся на фазы 84 МГц.
- SRAM 16 бит должна дать два обращения на такт 42 МГц (п. 3.5).
- Z80 21 / 3,5 МГц, видео 14 / 28 МГц — целые доли 84 (84 / 3 = 28 для удвоителя). 84 МГц получается из 50 МГц платы через DCM (× 42 / 25).

Цена: тайминг на 84 МГц в Spartan-6. Широкие комбинационные пути оригинала (`MEM.q` → дешифраторы → `PDD`, у Quartus 27 нс) обычно имеют два такта 84 МГц (`ce42`), их можно ограничить multicycle-путями в UCF или поставить регистр в свободную фазу.

### 5.3 Как переводить каждый класс

1. **Такт от бита счётчика** (`CT2`, `CT4`, `CT5`, `CTH1/2/5`, `CTV8`, `KB_CT2`, `KB_MA2`, `RXA0/1`, `AY_CCC7`, `CBL_CNT6` …): разрешение по фронту, вычисленное из того же счётчика (декодер «следующее значение даст фронт»), чтобы не добавить такт задержки. Где задержка в такт 42 МГц не видна снаружи — достаточно детектора `x & ~x_q`.
2. **Строб Z80 как такт** (`/MR`, `/M1`, `/IO`, `/WR`, `!(/M1 or /MR)`, комбинационный `/IOWR` DCP): у нас T80 внутри и синхронен (`ce` 21 / 3,5 МГц от `clk84`), его стробы — обычные регистровые сигналы. Фронт — детектор на `clk84`; отдельно для каждого места решить, какой фронт и в какой фазе такта Z80 он приходит (данные `D` / `A` должны быть ещё действительны — для `/IOWR` по подъёму это так).
3. **Регистровый строб как такт** (`/IOWR` верха, `/IOM`, `/IOMM`, `LWR_COL`, `WR_PIC`, `LWR_MODE`, `AY_A_WR`, `T_RDXA`, `WR_C7`, `!CBL_WR`, `V_WE`, `10K_CLK` …): разрешение = детектор нужного фронта.
4. **Задний фронт `CLK42`**: тот же регистр с `ce42n`.
5. **TFF на производном такте** (`TEST_SWITCH`, `CLK14`, `CT_WG`): `if (ce_edge) q <= q ^ t`.
6. **Деление «XOR с собственным выходом»** (MAX `XCT`, `CT_WG`, `STWG`): не переводить буквально; написать счётчики с тем же периодом и скважностью (14 МГц = 84 / 6, `CLK_WG` = 1 / 2 МГц), проверить моделью (`xct`: `XCT1` 0,0,0,1,1,1 по полупериодам 42 МГц; `STWG2` меняется каждые 7 полупериодов `CT_WG`).
7. **Асинхронная загрузка** (`CTH` / `CTV` по `COPY_SINC`, `SOFT_RES.prn`, `WT_CT.prn`, `KB_CT.prn`, `MOUSE CT.clrn`, `CBL_WA` …): синхронная загрузка с высшим приоритетом. Асинхронный вход действует в том же такте, поэтому если значение читается в этом же такте, выход берём как `load ? value : q` (комбинационно) — иначе сдвиг на такт.
8. **Самосбрасывающийся импульс** (`V_WE`, `WR_AWGX`, `ACC_MODE3`, `INT_X`, `XACS`, `HDD_FLIP` …): импульс заданной длины в тактах `clk84`; длину брать из логики петли (полтакта 42 = 1 такт 84, «до следующего фронта `CLK_Z80`» = до следующего `ce` Z80).
9. **«Anti gluk»** (`MEM_RW`, `IO_RWM`, `CS_ISA`, `CS_ROMT`, `CS_CASHT`): регистр, захватывающий значение по спаду строба (детектор), и комбинационное «неактивно, пока строб снят» на выходе, как у `prn`.
10. **Маскирование асинхронным сбросом** (`BD[7..4]`, `DO[4..3]`, `DCOL`, `RBRVA`, `SC` / `PN` по `CNF`, `DCPP` / `DD` по `MC_END` …): синхронный сброс в регистре плюс `q & ~mask` на выходе, если маска меняется в такте чтения.
11. **LCELL-задержки и формирователи**: LCELL — провод. Где задержка формировала окно (`V_WR` / `V_WEN`, `CAS_A`, `LWR_MODE`, `/WAIT`), нужное окно делается фазами `clk84` или вообще не нужно: внешних DRAM / видео-ОЗУ с их временами у нас нет, контроллеры SRAM / SDRAM свои.
12. **Комбинационные петли** (`STARTING`, `TURBING`, `RDAT_X`, `T320`, `THDD` / `NTHDD` / `NO_HDD`, `CNF_OFF`): явный RS-регистр с тем же приоритетом установки / сброса; асинхронность — по правилу 7.
13. **TRI / OPNDRN**: `D`, `MD`, `VD`, `XA` — мультиплексоры «кто ведёт»; `/WAIT`, `/RESET` — И активных-нулём источников. Шина `MA` как управляющая шина периферии остаётся внутренним сигналом (её читают модели ВГ93 / IDE / CMOS вместо MAX и защёлки ТМ9).
14. **Многократное присваивание** (AHDL объединяет по ИЛИ; DCP:671-672 `PN5`): записать явно.
15. **Внешние линии клавиатуры / мыши / магнитофона** (`KBD_CC`, `KBD_DD`, `MOUSE_D`, `TAPE_IN` через `XA`): синхронизатор и фронт; при подаче скан-кодов от МК модуль KBD можно кормить сразу байтами, минуя `KB_D` (решить в Ф1).

### 5.4 Память и MIF

- Все `lpm_ram_dp` / `lpm_ram_dq` — блочная память XST (`RAMB8BWER`, 256×16 и 256×8 помещаются в одну). Поведение портов как у EAB: адрес по `inclock` (и выход по `outclock` у AY — проверить латентность в сравнении), KBD — выход без регистра (распределённая память или BRAM с предвыборкой адреса).
- Начальное содержимое: `$readmemh` из `.hex`, которые делает `tools/mif2hex.py` из **`MaxPlus2/ACEX/*.MIF`** (не Quartus2, п. 6.1). Разбор MIF: `[a..b] : v;` — диапазон, `a : v1 v2 …;` — подряд идущие адреса, комментарии `%…%` и `--`.
- **Сброс = перезагрузка ACEX.** В оригинале каждый `/RESET` стирает ACEX (MAX:318), и всё — регистры и память с MIF — возвращается в начальное состояние. У нас память, которую пишут ЦПУ или логика (`MEM` DCP — младший байт; регистры AY 0x00-0x1D; матрица в KBD; буфер ACCELER; FIFO CBL), надо перезаливать при каждом сбросе: автомат 256 тактов, читающий копию начального содержимого (вторая BRAM или ПЗУ на LUT), около 3 мкс. Регистры — в начальные значения AHDL (0, кроме `prn`).
- Логика, рассчитанная на «0 после загрузки»: `/RES` (DCP:260), `F_WR` (VIDEO2:654), `START_UP` (SP2_ACEX:821), `STARTING` (DCP:715), начальная фаза `CT`. У нас — явный импульс сброса после перезагрузки.

### 5.5 Объём

ACEX: 1562 LE, из них 958 регистров и 1198 комбинационных функций (384 четырёхвходовых, `SP2_ACEX.map.rpt:234-237`); MAX — до 64 макроячеек. LUT4 → LUT6 обычно 0,6-0,8, плюс детекторы фронтов и мультиплексоры вместо асинхронных входов (~100-150 LUT, ~100 триггеров), минус мёртвое (курсор, тестовые узлы, удвоители). Оценка: **~1100-1400 LUT6 и ~1100 триггеров** на ACEX + MAX, 5 `RAMB8` (+ копии для перезаливки), без палитры в BRAM. Это 8-10 % LUT XC6SLX25 (15 032); основное место займут T80, Z84C15-периферия, ВГ93, IDE и контроллеры памяти.

## 6. Открытые вопросы и подозрительные места

1. **MIF в `Quartus2/ACEX` испорчены при переводе HEX → DEC** (`MaxPlus2/ACEX` — исходные):
   - `KBD_INI2.MIF`: метки 12, 13 повторены (`Quartus2/ACEX/KBD_INI2.MIF:25-28`) — все скан-коды начиная с 0x0E сдвинуты на два адреса вниз (103 отличия). В MaxPlus2 таблица совпадает с набором 2 AT по своим комментариям (0x05 F1, 0x06 F2, 0x0D Tab, 0x11 Alt, 0x12 L Shift, 0x14 Ctrl, 0x15 Q, 0x16 1, 0x1A Z, 0x1B S, 0x1C A, 0x1D W). В Quartus-сборке клавиатура сломана.
   - `AY.MIF`: в MaxPlus2 строка `0 : 32 значения подряд`, в Quartus2 — по 2 значения на «адрес» 0..15, строки перекрываются: регистры 07-0E и рабочие 10-1D начинаются с других значений (21 отличие; например, `R7 = 00`, громкости = FF).
   - `DCP.MIF`: значение 203F (окно страниц 0x3F) перенесено с адреса 159 (9F) на 160 (A0).
   Нужно: эталон Ф0.2 (`docs/refsim.md`) собирать с MIF из MaxPlus2, наши `.hex` — тоже из них.
2. **Тайминг Quartus-сборки**: Fmax 37,04 МГц < 42 (`SP2_ACEX.tan.summary`). Эталонный сетевой список функциональный, на поведение не влияет, но байты `SP2K_217.BIN` (MAX+PLUS II) могут вести себя иначе в гонках LCELL.
3. **Порт 1F**: AHDL `1F → 07` (ACCELER:182, сброс битов 4 и 3), MAME `1F → 0F` (только бит 4). В TR-DOS `IN A,(1F)` — статус ВГ93; как карта портов DOS это учитывает — проверить в Ф0.3 (версия 3.0x могла поменять).
4. **`PN5` назначен дважды** (DCP:671-672): `PN[5..0].clrn = /RESET & !CNF5` и `PN[7..5].clrn = /RESET & CNF7`. По правилу AHDL (ИЛИ) `PN5` сбрасывается только при `/RESET = 0` или при `CNF5 = 1 & CNF7 = 0`. Задумано ли так («reset PN5» / «set Pentagon-512»)?
5. **`ACC_BLK` почти всегда 1** (ACCELER:164-166): `prn = /RESET & ACC_MODE3`, а `ACC_MODE3` — импульс в один такт Z80 после `LD r,r` (:271). Блокировка ускорителя на время прерывания (INTA → 0, `RETI` → 1) тогда не работает. Проверить в эталоне и в MAME.
6. **KBD:126** — скобка: `DFF((/IO & (RXA[] == 0),CLK42,,))` — у `DFF` один аргумент-группа. Как это понял компилятор (регистр или нет) — посмотреть в сетевом списке.
7. **Фаза `TG42` у ACEX**: MAX выдаёт `TG42_OUT = LCELL(TG42_BUF) = !TG42_IN` (SP2_MAX:162-167). Что приходит на вывод `TG42` ACEX — прямой 42 МГц или инверсия — по схеме (`~/Downloads/Sprinter_2016s.pdf`); важно для фазы `CLKZ1` относительно 14 МГц MAX.
8. **Куда идут данные палитры**: из ACEX слово палитры не читается, видимо его ловит внешняя защёлка ЦАП по `WR_COL`. Какие байты `VD0..3` — R, G, B — и есть ли четвёртый, смотреть по схеме.
9. **`MODE0[5] = 0` в ZX-режиме**: `D_PIC0` перезагружается каждые 4 цикла (`LD_PIC` по `CT[4..2] == 0`, VIDEO2:501), а сдвигается раз в цикл — показываются 4 бита байта? MAME (`sprinter.cpp:489`) при этом сдвигает на 14 МГц. Сверить в Ф0.3.
10. **`ROM_WRITE_MODE`** (SP2_ACEX:705, мёртвая ветка `UPDATE = 0`): `!(A14 or A14)` — опечатка вместо `A15`. На живой код не влияет.
11. **Мягкий сброс через страницу Ax** (SP2_ACEX:562): запись в окно 3 при `SC4` и странице 0xA0-0xAF сбрасывает Z80 (~70 тактов), без перезагрузки ACEX. В MIF страниц Ax нет; кто так делает — искать в BIOS / DSS. Отдельно мягкий сброс через MAX (дескриптор 2E, `HDD_C = 1011`) — перезагрузка ACEX, MAME `sprinter.cpp:779-782`.
12. **`WAIT_ORIG`** — ожидание на окне 3 по `PN2` (страницы 4-7), а не по нечётным страницам, как у Spectrum 128. Задумано ли — сверить с MAME.
13. **INT от клавиатуры** (SP2_ACEX:744): такт `INT_X` = `INTT & KEYS.int` — при `ALL_MODE0 = 1` фронт даёт и конец кадра клавиатуры. Точное поведение (длина, снятие) — в эталоне.
14. Пометки авторов: «now not complete!» (SP2_MAX:311, сепаратор / звук `BEEP = GND`), «now NOT PRECOMP!» (:328 — при этом `REG_P` ниже есть), «now not protect!» (:320, `10K_CLK`), `HD_DIR` «????????????» (:434), `DCP.MIF:73` «???» (дескриптор 2F), DCP.TDF:330-333 и DCP.MIF:25-28 расходятся в описании битов 6-7 управляющего слова, `-- not used ?` в Quartus2-копиях.
15. Вход `XHR_RDY` (готовность IDE) в MAX не используется, `/WAIT` от IDE нет — тайминг IDE держится только на `W_TAB`.
